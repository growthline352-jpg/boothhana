2026-10-09 · 로컬 미리보기 · 데스크톱 및 390×844 모바일 검토

기능은 연결됐지만, 사용자의 결정 단계는 아직 연결되지 않았다

행사 탐색 → 상세 → 코스 생성 → 장소 추가 → 다른 탐색 경로 → 보관함 → 공유를 직접 조작했다. 기존 사용자의 127.0.0.1 저장 데이터와 분리된 localhost에서 테스트했다. 이는 전문가 관점의 흐름 검토이며 실제 사용자 테스트나 전환율 분석 결과가 아니다. 검토 중 제품 소스는 수정하지 않았다.

핵심 문제는 후보 수집, 일정 편집, 완성 코스 확인이 하나의 자동 저장 편집 흐름에 섞여 있다는 점이다. 먼저 UX-01~04를 해결하고 모바일 노출 순서를 정리하는 것이 우선이다.

가볍게 발견 → 찜하거나 코스에 담기 → 담은 장소 함께 보기 → 날짜·순서·시간 조정 → 코스 미리보기 → 공유·당일 사용

UX-01 · 높음

탐색 경로에 따라 추가 대상이 달라짐

직접 확인 일정 편집 → 행사 더 찾기에서는 기존 일정에 추가된다. 같은 편집 화면에서 상단 발견으로 이동하면 카드 CTA가 '이 행사로 코스 짜기'로 바뀌고, 누르면 새 일정이 생성된다. 테스트 일정 수가 2개에서 3개로 증가했다.

사용자에게 생기는 부담 같은 하루를 만들던 사용자가 탐색에 들어간 경로를 기억해야 한다.

개선 방향 카드 행동을 '코스에 담기'로 통일하고, 현재 담을 코스와 장소 수를 지속적으로 표시한다. 대상 변경은 기존 코스/새 코스 선택에서 명시적으로 처리한다.

UX-02 · 높음

장소마다 탐색과 편집을 왕복함

직접 확인 행사 더 찾기 → 작은 취향 수집소 일정에 추가를 누르면 즉시 일정 편집 화면 상단으로 이동한다. 다음 후보를 담으려면 행사 더 찾기로 다시 이동해야 한다.

사용자에게 생기는 부담 여러 장소를 비교하고 모으는 흐름이 매번 끊긴다. 자동 저장이 후보 결정과 확정의 구분을 대신하고 있다.

개선 방향 담기 후 목록과 스크롤을 유지하고, 하단에 '3곳 담음 · 코스 보기'를 표시한다. 저장(찜)과 특정 코스에 담기를 분리한다.

UX-03 · 높음

서비스가 만든 기본 일정이 곧바로 운영시간 경고를 발생시킴

직접 확인 16:00–21:00 운영인 노을 따라 가을마켓 상세에서 이 행사로 코스 짜기 → 기본 13:00–14:30에 배치되고 '예정 방문 시간이 운영시간을 벗어나요'가 표시된다.

사용자에게 생기는 부담 선택 직후 사용자 실수가 아닌 기본값을 사용자가 수정해야 한다.

개선 방향 확인된 운영시간과 방문 날짜로 가능한 시작 시간을 제안한다. 알 수 없는 시간은 시간 미정으로 두고 임의의 확정 시간처럼 표시하지 않는다.

UX-04 · 높음

일정 관리를 편집 화면 하나가 모두 맡고 있음

직접 확인 내 일정에 들어가면 일정 목록 대신 현재 일정 편집기가 열린다. 일정 전환은 긴 자동 제목의 셀렉트이며 새 일정·공유·내보내기·파일 가져오기가 상단에 노출된다. 다녀왔어요 체크는 작성 중에도 함께 보인다.

사용자에게 생기는 부담 어떤 코스를 만들었는지 고르기, 편집하기, 당일 확인하기의 목적이 한 화면에서 경쟁한다.

개선 방향 내 코스 목록 → 코스 요약/미리보기 → 편집의 구조로 분리한다. 작성 중/예정/지난 코스를 구분하고, 방문 당일에는 다음 장소·길찾기·예약 정보를 우선한다. 고급 파일 기능은 더보기로 이동한다.

UX-05 · 중간

보관함에서 여러 후보를 묶는 행동이 없음

직접 확인 보관함은 '모아둔 장소를 골라 하루 일정으로 이어보세요'라고 안내하지만 선택 모드나 묶어서 코스 만들기 없이 개별 카드의 새 코스 CTA를 제공한다. 상단 주요 버튼은 기존 기기 보관함 가져오기다.

사용자에게 생기는 부담 평소 찜해두다가 약속이 잡힌 뒤 묶어보려는 사용자가 다시 개별 생성 흐름에 들어간다.

개선 방향 여러 장소 선택 → 새 코스 만들기/기존 코스에 추가를 제공한다. 가져오기는 보조 기능으로 내린다.

UX-06 · 중간

데이트의 다음 장소를 찾는 부담이 사용자에게 넘어감

직접 확인 + 장소·휴식 추가는 이름·주소·체류시간·2인 비용을 직접 입력하는 폼이다. 화면의 같은 동네 추천은 예시 장소이며 이동시간은 직접 입력한다.

사용자에게 생기는 부담 행사 뒤에 갈 카페/식당과 현실적인 동선을 결정하려면 다른 서비스에서 조사한 뒤 돌아와 다시 입력해야 한다.

개선 방향 선택 행사 기준 주변 카페/식사/산책 후보와 거리·영업 여부 확인을 연결한다. 장소 데이터 연동 전에는 지도 검색 바로가기와 시간 미정 상태를 명확히 제공한다. 데이터 연결은 별도 구현 범위다.

UX-07 · 중간

모바일 첫 화면에서 핵심 콘텐츠가 밀림

직접 확인 390×844에서 홈은 큰 소개 영역·추천 배너·계속 만들기·필터로 첫 화면이 채워져 행사 목록 카드가 보이지 않는다. 일정 화면도 편집할 장소보다 제목·일정 전환·파일 기능·시간 입력이 먼저 보인다.

사용자에게 생기는 부담 서비스의 실제 선택지를 보거나 작성 중인 코스를 확인하려면 처음부터 스크롤해야 한다.

개선 방향 홈 소개를 줄이고 지역/날짜와 실제 후보를 앞에 둔다. 일정 화면에서는 담은 장소와 다음 행동을 먼저 보여주고 이름·종료시간 등은 접어둔다.

UX-08 · 중간 / 연동 필요

둘이 검토하고 당일 사용하는 단계가 약함

직접 확인 공유·내보내기 모달은 텍스트 복사와 파일 저장을 제공하고 공유 링크·공동 편집은 연결 전이라고 안내한다. 일정 화면은 방문 체크와 편집이 섞여 있다.

사용자에게 생기는 부담 상대방이 설치나 파일 처리 없이 같은 코스를 열어보고 의견을 주거나, 당일 다음 장소로 이동하는 경험이 부족하다.

개선 방향 먼저 읽기 전용 코스 링크/미리보기를 만들고, 그 다음 수정 제안이나 공동 편집을 검토한다. 당일 보기는 편집과 분리한다.

서비스 비교에서 가져올 기준

트리플 장소 상세는 저장하기와 일정추가를 별도 행동으로 제공한다. 우리 서비스에도 이미 저장 기능은 있지만, 모인 후보를 하나의 일정으로 묶는 연결 행동이 부족하다.

Wanderlog 공식 소개는 장소를 담으면 지도에 표시되는 경험과 일정·지도·협업 기능을 강조한다. 참고할 점은 기능 수보다 장소를 고르는 동안 일정과 공간 맥락을 유지하는 방식이다. 경쟁 서비스의 로그인 이후 전체 흐름을 직접 테스트한 것은 아니다.

다음 개편 범위와 확인 기준

  1. 현재 코스를 유지하며 후보를 여러 개 담고, 목록 스크롤도 유지한다.
  2. 찜한 장소 3개를 선택해 하나의 코스로 만들 수 있다.
  3. 16시 운영 시작 행사를 처음 골라도 서비스 기본값 때문에 운영시간 경고가 생기지 않는다.
  4. 내 코스 목록에서 여러 코스를 날짜와 지역으로 구분하고 들어갈 수 있다.
  5. 모바일 첫 화면에서 실제 후보나 작성 중인 장소를 볼 수 있다.
  6. 미확인 이동·영업 정보는 추정 완료로 표현하지 않는다.

테스트 세션에서 수집된 콘솔 오류·경고는 0건이었다. 인증·성능·전체 링크·접근성 정밀 검사는 수행하지 않아 종합 QA 점수는 산출하지 않았다. 예시 데이터와 링크 공유 미연결은 고장으로 분류하지 않고 실서비스 연동 과제로 구분했다.
