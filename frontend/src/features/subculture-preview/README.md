# 서브컬처 사용자 화면 미리보기

2026-10-08. 기존 React·Vite 프로젝트 안의 독립 진입점이다. 운영 라우터, 인증, API, DB, 수집기 및 서비스 워커를 호출하거나 교체하지 않는다.

## 실행

frontend 디렉터리에서:

```powershell
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 4190 --strictPort
```

http://127.0.0.1:4190/subculture-preview.html 로 접속한다. HTML 및 hash 경로는 운영 배포를 위한 최종 URL이 아니다.

독립 번들 확인:

```powershell
node node_modules/typescript/bin/tsc -b
node node_modules/vite/bin/vite.js build --config vite.subculture-preview.config.ts
```

## 화면 범위

- 홈과 통합검색, 대상별 탐색 목록, 한글·영문 별칭과 지역 필터, 빈 결과 안내.
- 홈은 관심과 연결된 행사·굿즈·작가를 먼저 보여주는 형태다. 캐릭터·작품은 작은 결과 필터로만 사용하고 캐릭터 소개 카드를 히어로에 반복하지 않는다. 매주 편집 특집이나 행사 판매 정보가 확보되어야 유지되는 구조를 제거했다. 검색은 헤더에서 접근한다.
- 홈 상단의 ‘홈 화면 비교’로 네 상태를 전환한다. `?homeCase=characters`(관심 캐릭터), `works`(작품만), `new`(미설정), `custom`(직접 입력만). hash 내부 쿼리이며 예: `#/?homeCase=custom`.
- 사례의 관심 버튼은 메모리에서만 동작하며 실제 저장된 관심을 덮어쓰지 않는다. ‘내 설정’으로 실제 상태로 복귀한다. 사례는 홈 화면 비교에 한정하며 다른 상세·설정 페이지는 기존 사용자 상태를 사용한다.
- 관련 소식은 해당 관심에 확인된 자료가 있을 때만 보여준다. 일정·장소 중심의 행사 안내는 독립된 목록으로 제공한다. 작가 목록도 대표 이미지나 편집 원고 없이 소개 정보로 구성한다.
- `/collections/:id`에서 선정 이유, 작품 분위기 필터, 캐릭터·작가 관심 등록, 참가 행사까지 이어진다.
- 작가 카드와 상세에 대표작을 추가했다. 별도 작품 관계로 동일 캐릭터를 여러 작가가 그리는 경우, 같은 IP의 여러 캐릭터, 오리지널 창작을 표현한다. 특집 작품과 행사 판매물은 구분한다.
- 예시 캐릭터 초상·대표작은 자체 SVG/CSS로 표현하고, 굿즈 사진은 상세 판매 정보에 사용한다.
- 관심 캐릭터와 작품 관계에 따른 작가 추천, 관심 소식, 관련 행사를 홈에서 제공한다. 실시간 인기 집계나 학습 추천 모델은 아니다.
- 검색 결과에서 다시 검색해도 선택한 대상과 지역 조건을 유지한다.
- 캐릭터·작가·굿즈·행사·참가 부스 상세.
- 관심 등록·해제와 관심 목록. 행사별 판매 확인·미확인 구분.
- 판매일 선택, 동일 날짜 중복 저장 방지, 행사에서 선택한 날짜 유지.
- 날짜별 방문 목록, 행사 미정 보관함, 메모, 개인 완료 체크, 예상 금액.
- 알림함, 읽음·안 읽음 필터, 소식에서 상세 이동.
- 이번 회차 질문·댓글, 지난 회차 후기 선택·작성·본인 예시 글 삭제.
- 행사 상세의 기본 화면은 행사 안내다. 소개·주최·관람 대상, 날짜별 운영 시간, 입장 절차, 교통·주차·접근성·시설, FAQ와 안내 기준을 제공한다. 공식 정보가 없는 항목은 미확인으로 표시한다.
- 안내 목차로 해당 부분을 이동하고, 선택 날짜를 참가 부스로 전달한다. 안내로 복귀해도 URL의 날짜를 유지한다. 지난 회차 후기 바로가기는 해당 회차를 선택해 연다.
- 내 정보와 웹 푸시 설정 모형. 실제 권한 요청·구독·발송은 없음.
- `/onboarding`은 작품 선택 → 캐릭터 선택 → 확인·저장의 3단계이며 건너뛸 수 있다. `/account/interests`는 작품/캐릭터 편집을 바로 전환하고 캐릭터 단계에서 저장한다. 기존 브라우저의 관심·방문 정보는 보존한다.
- 등록된 작품·캐릭터 목록에서 선택하는 것이 기본이다. 현재 목록은 DB 응답을 대신하는 예시 데이터이며 실제 DB API는 아직 호출하지 않는다. 목록에 없는 작품과 캐릭터는 직접 입력할 수 있다.
- 작품 종류(게임·애니메이션·만화/웹툰·소설·오리지널/기타), 작품명과 캐릭터명을 연결해 저장한다. 같은 이름의 캐릭터도 출처 작품으로 구별하며 같은 작품 안의 중복은 막는다.
- 직접 입력한 항목의 이름·작품 종류·출처를 수정할 수 있다. 마지막 단계에서 저장하며 취소하면 기존 설정을 유지한다. 수동 입력은 개인 관심으로만 보관하고 정보 연결 전까지 소식 연결 대기로 표시한다.
- 작품만 선택하면 작품 전체를, 캐릭터도 선택하면 선택한 캐릭터를 기준으로 홈의 연결된 작가·행사를 보여준다. 직접 입력한 캐릭터에 관계를 임의 생성하지 않는다.
- 모바일 하단 메뉴, 키보드 초점, Escape로 저장창 닫기, 본문 바로가기.

화면 검토용 가상 데이터만 사용한다. 상품 이미지는 기존 저장소의 assets/boothup 자료를 재사용했다. localStorage의 boothhana-subculture-ux-preview-v1 키에만 예시 상태를 보관한다. 브라우저 저장소를 사용할 수 없으면 현재 화면의 메모리 상태로 동작한다. 다른 기기·브라우저와 동기화되지 않는다.

내 정보의 ‘예시 데이터 초기화’로 테스트 내용을 되돌릴 수 있다. 초기 관심은 비어 있고 두 건의 알림은 화면 체험용 예시다. 신규 관심 등록 시 소식을 가짜로 자동 생성하지 않는다. 실제 수집·공개·알림 흐름은 별도 백엔드 구현 대상이다.

## 직접 확인한 동작

- TypeScript 검사 및 독립 Vite 빌드 성공.
- 루나/luna 검색에서 캐릭터·작가·굿즈·관련 행사 연결.
- 상품 상세에서 일요일 저장, 목록의 날짜와 가격 확인, 새로고침 후 메모 유지.
- 행사에서 선택한 일요일을 저장창에 유지, 같은 날짜 중복 저장 비활성화.
- 토요일 필터에서 일요일만 판매하는 스티커 제외.
- 행사 미확인 파우치를 날짜 없는 보관함으로 저장.
- 캐릭터 관심 등록 후 새로고침에도 유지.
- 알림 모두 읽음 후 안 읽음 목록의 빈 상태.
- 지난 회차에 작성한 글이 이번 회차에 노출되지 않음.
- Escape로 저장창 닫기 및 실행 버튼으로 초점 복귀.
- 390px 모바일에서 방문 목록·상세·후기 흐름 확인, 확인한 상세 화면의 가로 넘침 없음.
- 점검 시 브라우저 콘솔 오류·경고 없음.

서버 연동, 실제 기기 푸시, 사용자 조사, 실제 행사 정보의 정확도 검증은 이 프런트 미리보기의 범위에 포함되지 않는다.

## 사용성 보완 (2026-10-08)

- 목록·상세의 관심 조작을 44px 하트로 통일하고 모바일 본문·보조 정보의 크기와 대비를 보완했다.
- 관심 목록의 중복 요약과 온보딩 재진입 링크를 제거했다. 홈 비교 도구는 기본 접힘이다.
- 지역 필터는 행사·굿즈 목록에만 표시한다. 검색 결과에서 상세로 이동한 뒤 이전 화면으로 돌아오면 검색어와 대상 분류를 유지한다.
- 관심 해제·방문 항목 제거·본인 후기 삭제는 알림의 실행 취소로 복원한다. 방문 항목의 메모와 날짜도 함께 복원한다.
- 직접 입력 도중 출처 작품을 추가해도 캐릭터 이름을 유지한다. 후기 회차를 바꿔도 해당 화면에 머무르는 동안 회차별 초안을 유지한다.
- 모바일 하단 탐색·마이 메뉴는 하위 화면에서도 활성 상태를 표시한다.

## 홈 결과 중심 개편

- 관심 전체 또는 개별 캐릭터·작품·작가 필터에 따라 행사·굿즈·작가 결과가 함께 바뀐다. URL에 조건을 보관해 상세에서 복귀해도 유지한다.
- 행사 카드에는 캐릭터 굿즈 판매 확인, 작가 참가 확인, 작품 테마를 구분한다. 대표작 관계만으로 행사 판매를 추정하지 않는다.
- 관심 작품만 선택하면 작품 전체 결과를, 미설정이면 일반 행사·굿즈·작가를 보여준다. 직접 입력만 있고 관계가 없으면 연결 대기를 알리고 일반 행사임을 명시한다.
- 현재 관계는 화면 예시 데이터 기반이며 수집기·DB 연동은 포함하지 않는다.
