# 작가 SNS 수집

v6 CREATOR 작업과 기존 내부 API·검토 기록을 사용한다. 별도 수집기에서 임의로 운영 DB를 수정하지 않는다. 모델은 추출·검색·독립 검토 모두 `gpt-6.1-sol`이며 호출/비용 상한이나 대체 모델이 없다.

## 흐름

1. 공개된 행사 부스의 작가별 프로필, 공식 링크, 원문 출처를 독립 작가 작업 문맥으로 전달한다. 공동 부스 링크는 작가 본인의 계정이라는 확정 정보가 아니다.
2. SNS 탐색 호출이 계정 후보를 찾는다. 실제 공개 원문/API를 다시 읽고 작가 프로필·공식 부스와 계정의 양쪽 근거를 대조한다.
3. 추출 결과와 원문을 별도 LLM 호출에서 검토한다. 승인된 계정만 `collection_creator_publication.data_json.socialAccounts`에 보존한다. 기존 작가 ID와 canonical `profileUrl`은 변경하지 않는다. 과거 형식의 결과나 빈 목록으로 기존 계정을 지우지 않는다.
4. X·Bluesky는 계정별 CREATOR 후속 작업으로 게시글 5개씩 수집한다. 게시글 본문, 작성자 ID, 실제 이미지, 상품 링크, 시각을 함께 조사한다. 리포스트/인용한 다른 작가의 이미지와 일반 팬아트를 상품으로 취급하지 않는다.
5. 네이티브 API의 실제 다음 커서를 작업 큐에 저장한다. 마지막 페이지까지 검토된 뒤 최신 게시글 체크포인트를 갱신한다. 다음 주기에서는 이미 확인한 게시글에 도달하면 멈춘다. 접근 실패·이미지 실패·남은 페이지를 전체 완료로 기록하지 않는다.
6. 판매글에서 굿즈가 확인되면 해당 작가가 포함된 진행 예정 행사 부스의 SALES 작업에 원문 단서를 전달한다. 현 행사 판매는 SALES가 정확한 행사명·날짜·회차를 확인한 뒤에만 확정한다. CREATOR는 일반/과거 카탈로그만 공개한다.
7. 최초 SNS 역사 수집은 baseline으로 처리해 과거 정보 알림을 억제한다. 계정의 소유자 ID가 바뀌면 피드 수집을 중단한다. 잘못된 연결은 양쪽 원문을 독립 검토한 UNLINK로 철회하고 이전 ID를 보존한다.

## 플랫폼과 운영 설정

- Bluesky: 공식 공개 AppView API, 로그인 없이 프로필·작성자 피드·게시글 원문과 이미지를 확인한다.
- X: 공식 `/2/users/by/username`, `/2/users/{id}/tweets`, `/2/tweets/{id}` API를 사용한다. `xBearerTokenEnv`(기본 `X_BEARER_TOKEN`)가 수집기 부모 프로세스에 설정되어 있어야 한다. `collector.env`에 보관하고 모델 자식 프로세스에는 전달하지 않는다. 인증키·구매 권한이 없으면 미수집으로 남긴다. 인증을 가진 요청의 리다이렉트를 따라가지 않는다.
- 포스타입·인스타그램: 확인 가능한 공개 원문만 조사한다. 로그인·robots·접근 제한을 우회하지 않는다. 접근할 수 없는 플랫폼은 피드 수집이 완료됐다고 표시하지 않는다.

공식 JSON 응답의 실제 SHA256·확인 시각·전송 URL을 저장한다. 이미지 첨부는 분석용이며 재게시 권리 승인과 분리한다. URL·이미지 검증에는 기존 공개 IP 고정 HTTPS 전송을 사용한다.

기존 JSON 열에 검토 계정과 체크포인트를 추가하므로 DDL/기존 ID 이전은 필요 없다. 구버전 추출은 호환된다. 기존 추출 문맥과 새 문맥이 다르면 CAS가 공개를 막고 최신 문맥에서 다시 수집한다. 공개 상품 API에는 내부 체크포인트를 노출하지 않고 활성 프로필 링크만 전달한다.

공식 API 문서: [X 작성자 게시글](https://docs.x.com/x-api/users/get-posts), [Bluesky 작성자 피드](https://github.com/bluesky-social/atproto/blob/main/lexicons/app/bsky/feed/getAuthorFeed.json).
