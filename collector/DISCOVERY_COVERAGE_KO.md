# 지역 기반 행사 발견과 공식 원문 보완

## 문제와 흐름

기존 보완기는 등록된 행사만 조사하므로 처음부터 빠진 행사는 채울 수 없다. 일부 주최·시설 홈페이지와 적은 검색 작업에 의존하면 독립 공간·신규 주최·앞으로 열릴 행사도 빠진다. 서브컬처 검색에서 찾은 팝업을 공개 분야가 다르다는 이유로 버리는 문제도 있었다.

**지역·기간·분야별 발견 → 행사별 원문 검증 → 등록/기존 행사 대조 → 정보·이미지 보완 → 공개 상태 확인**으로 처리한다. 검색 결과를 그대로 공개하지 않는다.

## 유형별 탐색과 지역 탐색

- `TYPE_SOURCE` 30개를 독립 작업으로 유지한다. 생일카페·온리전·라이브 아이돌, 산업·생활·웨딩 박람회, 빛·음식·문화 축제, 판매·체험·전시형 팝업을 한 검색어의 AND 조건으로 묶지 않는다. 각 작업이 자체 검색어·시도 이력·재시도 시점을 가진다.
- 행사 유형 검색에 주최·공간 일정, TMM·네이버 예약 등 플랫폼 탐색을 함께 사용한다. 플랫폼 검색은 지역명을 강제하지 않고 실제 개최 주소를 확인해서 서울·경기 행사인지 분류한다. 지역 탐색 56개는 새로운 출처와 지역 행사를 발견하는 보조 경로다.
- 코엑스는 실제 전체 일정 경로와 대상 기간을 적용한 모든 페이지, 아로아로는 공개 예매 목록, 서울시는 모든 축제 목록의 개별 행사 링크를 순회한다. 목록에 나오는 과거 행사도 상세 문서를 읽지만 명시된 기간이 현재 범위 밖인 후보는 조사 대기열에서 제외한다. 링크가 남으면 `PARTIAL`이며 끝났다고 보고하지 않는다.
- HTML 페이지 링크로 구현되지 않은 JS 전용 페이지 넘김은 `UNRESOLVED_JS_PAGINATION`으로 남긴다. 지원하지 않는 사이트가 자동으로 완전히 지원됐다고 표시하지 않는다.

- 지원 범위는 서울·경기다. `regional_discovery.json`의 서울 25개 구·경기 31개 시·군을 14개 작업 권역으로 묶고 4개 분야별로 조사한다. 총 56개 지속 작업이며 실제 검색어는 구·시·군별로 따로 만든다.
- 서브컬처, 박람회(`EXHIBITION`), 축제, 팝업을 각각 찾는다. 성수·홍대·잠실·판교 등 별칭과 온리전·생일카페·야시장·체험관 등 다른 명칭도 보충 검색한다.
- 실행 시점부터 60일 이내의 진행 중/예정 행사를 찾는다. 최근 게시물 탐색은 별도 보조 작업이다. 게시일이 오래됐어도 대상 기간에 열리는 공식 행사는 지역 검색에서 제외하지 않는다.
- 주최 SNS, 티켓 플랫폼, 커뮤니티·지역 콘텐츠는 단서를 찾는 경로다. 공식 사이트가 없는 행사는 주최 계정의 원래 공지를 원문으로 사용한다. 로그인·접근 제한을 우회하지 않는다.
- 날짜·장소가 미확인인 단서는 `unverifiedLeads`로 받아 개별 조사 대기열에 보존한다. 추정 날짜로 등록하지 않는다. 날짜 미확인 단서도 출처가 다르면 구분한다.
- 지역·유형 발견 결과에서 로컬 검증에 탈락한 후보도 `REJECTED_DISCOVERY`로 보존한다. 행사명·회차·안전한 발견 URL·검증 탈락 사유로 개별 재조사한다. 기존 탈락 후보 15건의 재현 검사에서 15건 모두 조사 대기열로 이어졌다. 미검증 내용을 공개 데이터로 전송하지 않는다.
- 발견 작업 분야와 공개 분야는 별개다. 서브컬처 검색에서 찾은 캐릭터 팝업은 팝업으로 보내고 취향 주제는 보존한다.
- 검색하지 않은 구·시·군, 접근 실패, 부분 검색은 `PARTIAL`로 남긴다. 결과 0건과 검색 실패를 구분한다.

## 공식 목록 대조

검색에서 놓친 행사를 대조하기 위해 롯데·현대·신세계·스타필드의 공개 지점 목록과 행사 피드도 읽는다. 모든 몰을 수동 등록해야 지역 검색이 가능한 구조는 아니다.

지점 목록은 주 단위로 갱신한다. 모르는 지점은 `unmappedBranches`에 남기며 서울·경기 밖 지점도 포함될 수 있어 지역 확인이 필요하다. 새 지점이 자동으로 지원됐다고 주장하지 않는다.

| 출처 | 읽는 범위 | 확정하지 않는 항목 |
| --- | --- | --- |
| 롯데 | 공개 쇼핑뉴스 실제 페이지·개별 상세 | 원문 날짜/지점 불일치, 연도 미확인 |
| 더현대 서울 | WEEKLY POP-UP 안의 개별 행사 | 주간 글 노출 기간을 행사 날짜로 사용하지 않음 |
| 현대 기존 지점 | 행사·문화·스페셜 공개 피드 | 팝업 여부/개별 날짜 불명확한 카드 |
| 신세계 | 지점별 쇼핑정보·상세 JSON | 브랜드별 기간 상이, CMS 노출 기간 |
| 스타필드 | 행사 및 브랜드 두 피드 | 날짜 비공개, 팝업 여부 불명확 |

확정하지 못한 항목은 원문·지점·항목 ID와 함께 별도 조사 작업으로 보낸다. 팝업이라는 단어가 없다는 이유만으로 할인 공지 이외의 애매한 항목을 일괄 제외하지 않는다.

중단 시 실제 다음 페이지를 저장한다. 재개 전 각 피드 첫 페이지와 총 개수를 대조해 목록이 바뀌면 다시 시작한다. HTML 일정 목록은 링크·제목의 지문을 비교하며 nonce나 광고 문구 변화로 재시작하지 않는다. 완료한 일정도 하루 단위로 상세를 다시 확인한다. 전체 개수를 확인하기 전에는 세부 등록을 시작하지 않는다. 페이지·상세 시간 종료는 미완료이며 사라진 항목은 이력으로 보관하고 자동 취소하지 않는다.

## 주소·유형 원문 검증

발견 후보의 개별 조사에는 `eventEvidence`를 요구한다. 수집기가 실제 읽은 공식 행사/주최 문서에 행사 유형·장소 인용이 있는지, 장소 주소 인용과 입력 주소가 일치하는지 검사한다. 다른 페이지를 원문이라고 주장하거나 모르는 주소를 인용한 모델 결과만으로는 통과하지 않는다. `서울`/`서울특별시`, `2F`/`2층` 같은 같은 주소의 표기는 정규화하되 도로명·번지 차이는 허용하지 않는다.

행사명과 개최 기간도 같은 원문에 연결한다. `nameQuote`에는 원문 행사명을, `occurrenceEvidence`에는 각 `occurrenceIndex`와 실제 개최 기간의 `dateQuote`를 기록한다. 이름만 명확한 단서도 이 검증을 거친다. 원문의 연도·회차가 후보와 다르거나 다른 행사명을 인용하면 등록하지 않고 재조사로 남긴다. 날짜 인용은 원문 제목·본문 또는 행사 구조화 데이터에 실제로 있어야 하며, 후보의 연도를 빌려 보충하지 않는다. 모든 개최 구간이 원문의 구간과 일치해야 하고, 기간 일부만 잘라서 등록하거나 판매 기간을 개최 기간으로 사용하지 않는다.

구두점·연도 표기·회차 표기를 정규화해서 행사 이름을 비교하되 연도와 회차의 일치 여부는 별도로 검사한다. `AGF`처럼 짧은 영문 약칭은 독립된 토큰일 때만 인정한다. 모호한 날짜나 근거가 없는 후보는 `PARTIAL`과 후속 조사 사유로 보존한다. 이미지 보완에 사용한 모델의 설명도 행사 이름·회차 검증을 대신하지 않는다.

지역과 서울 구는 검증된 개최 주소에서 설정한다. 주최자의 사업자 주소와 전시장 주소를 혼동하지 않는다. 커피·식품 산업 박람회를 음식 축제로 분류한 경우는 개별 조사로 돌린다. 행사 유형별 원문 단서가 불충분해도 재조사로 남긴다. 예약 폼 판매 종료를 행사 종료로 사용하지 않는다.

TMM은 익명 공개 상품 API의 행사 본문을 읽는다. 행사장에서 공개한 구조화 장소 정보도 이름·주소만 사용하며 연락처나 원본 JSON을 그대로 보관하지 않는다. `fact-documents.json`은 검증용 로컬 원문 기록이고 서버 요청에는 `eventEvidence`/원문 문서를 포함하지 않는다.

코엑스 등 확인된 공식 행사장 사이트의 하단 주소는 행사장 이름과 연결해서 확인할 수 있다. 주최/판매자 사이트의 하단 주소만으로 개최 주소를 확정하지 않는다. 전시장 이름과 세부 홀은 각각 원문에서 확인한다. 일반적인 지역/층 표기 차이를 허용해도 다른 번지나 홀은 통과시키지 않는다.

개별 재조사는 지난 `previousResearchIssues`도 전달한다. 미확인 관람 안내가 있으면 기존 관람 안내 검증기로 해당 행만 분리해 `guide-validation.json`에 보존하고, 확정된 행사와 유효한 안내는 검증한다. 누락 행은 다음 보완 대상으로 남기며 근거나 확정 상태를 임의로 채우지 않는다. 안내가 미완료인 후보를 전체 조사 완료로 표시하지 않는다.

## 등록과 이미지

행사명·분야·지역·개최 날짜·출처 URL로 이미 등록된 행사를 대조한다. 여러 행사에 같은 주간 공지 URL이 사용돼도 다른 행사를 합치지 않는다. 기존 행사는 빈 정보를 보완하며 확인된 취소·연기를 일반 목록으로 덮어쓰지 않는다.

해당 원문 항목의 대표 이미지를 후보로 기록한다. 이미지 발견·사용 검토·파일 저장·사용자 대표 이미지 노출은 서로 다른 상태다. CDN 허용 목록은 사용 권리 승인이 아니다. 기존 이미지 보완기·저장 작업이 후속 처리를 담당한다.

목록 보고서에 등록/공개 상태, 저장된 대표 이미지, `missingReasons`를 별도로 기록한다. `STAGED`는 수집함 반영이며 사용자 공개 완료가 아니다.

## 실행과 운영 확인

```sh
python daily_popups.py --config /etc/boothhana/collector.json --regional-only
python daily_popups.py --config /etc/boothhana/collector.json --official-only
python doctor.py --config /etc/boothhana/collector.json --coverage
```

`--official-only`는 Codex 검색 호출이 없다. `--coverage`는 검색/DB 쓰기 없이 실행 환경과 오래된·미완료 출처를 따로 보고한다. `--dry-run`은 로컬 기록만 남기고 서버 저장/공개는 하지 않으나 웹 검색·원문 읽기는 수행할 수 있다.

기본 예산은 유형/지역 8개 작업/실행, CLI 최대 24회, 실행 최대 90분이다. 미시도·오래된 작업부터 순환한다. 공식 목록은 지점 12개, 페이지·상세 개수 제한 없이 전체 15분이다. `maxOfficialPopupPages=0`, `maxOfficialPopupDetails=0`이 개수 제한 없는 기본값이며 명시적으로 양수를 설정할 수도 있다. HTTP·실행 시간 제한은 유지하고 미완료 페이지/상세는 다음 실행에서 이어간다. 한 후보의 실패는 다음 후보를 중단하지 않는다.

`deploy/ubuntu/discovery.cron.example`은 지역 3시간 간격/공식 목록 6시간 간격의 배포 준비 예시다. 파일 추가만으로 운영 예약은 바뀌지 않는다. 기존 예약에 실제 배포 때 합친다. 공용 잠금 충돌은 최대 15분 기다린 뒤 `DEFERRED_LOCK`을 기록하고 다음 실행에서 이어간다.

지속 상태: `discovery-work-queue-v1.json`, `event-name-queue-v1.json`, `popup-source-state-v1.json`, `source-schedule-state-v1.json`.
실행별 `summary.json`, `official-popups/coverage-report.json`에 대조 결과, 상세 조사 대기, 미완료·오래된 출처를 남긴다. 인증·실행 환경 정상은 수집 완료가 아니다. `--coverage`는 미초기화/오래된/미완료 상태면 종료 코드 2를 반환한다.

## 남는 한계와 배포 상태

미색인 페이지, 비공개 SNS, 공식 공지 미발표, 이미지에만 날짜가 있는 복합 공지는 늦거나 미완료로 남을 수 있다. 대기열·원문·미완료 사유로 추적한다. 검색만으로 모든 행사를 발견했다고 증명할 수는 없다. 운영에서는 지역/분야별 마지막 성공 시간, 상세 조사 대기, 이미지 미저장 수를 확인한다.

이번 변경은 배포 대기 상태다. 운영 예약·운영 데이터·서비스 공개 상태를 변경하지 않았다.
