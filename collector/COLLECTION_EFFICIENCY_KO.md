# 수집 입력 효율화와 근거 보존

그래프 수집기는 판매 대상과 관계없는 카탈로그 영역, 보조 이미지 판독에 반복되던 문맥, 행사 장소만 설명하는 사전 읽기를 줄인다. 원문을 보존한 상태에서 모델에 제공할 범위를 구분하며, 최종 추출과 독립 검토의 근거 확인은 계속 수행한다.

이 변경에 새 설정 키나 DB 마이그레이션은 없다. 작업 임대·순환 순서·동시 실행 수의 기본 정책은 [그래프 수집기 안내](GRAPH_WORKER_KO.md)를 따른다. 운영 중 일회성으로 실행하는 병렬 runner는 이 입력 효율화의 기본 스케줄 설정이 아니다.

## Comiverse 판매 대상 범위

지원 대상은 관측한 `https://app.comiverse.kr/`의 `div.booth-item` 형식이다. 다른 경로·쿼리·호스트나 해석할 수 없는 구조에는 이 범위를 적용하지 않는다.

`SALES` 작업에서 다음 조건을 모두 만족할 때만 모델 입력을 한 부스 영역으로 제한한다.

1. 원문 문서가 실제 확보됐고 잘리지 않았다.
2. 기존 참가자의 `registrationName`과 정확히 일치하는 등록명이 원문에 한 번만 있다.
3. 기존 참가자의 이미지 또는 공식 링크가 원문의 부스 영역 한 곳에만 연결되며, 그 영역이 정확한 등록명과 일치한다. 이미지는 해당 카탈로그 페이지를 `pageUrl`로 가진 기존 이미지로 대조하며, 카탈로그 주소 자체는 공식 링크 식별 근거로 사용하지 않는다.

선택된 입력에는 부스 밖의 공통 행사 텍스트, 대상 부스의 텍스트·공개 모달 필드·링크·이미지를 제공한다. 공동 부스는 전체 등록명으로 한 영역을 선택하며 구성원 이름만으로 일부를 떼어내지 않는다. 가격·옵션·단위·조건을 요약하여 대체하지 않는다.

공개 모달의 추가 텍스트 필드는 `data-description`, `data-x`, `data-instagram`, `data-postype`, `data-prepay-url`, `data-shop`만 읽는다. 이미지 참조는 관측한 `data-catalog-image`, `data-image`, `data-info-image`, `data-info-images`에서 얻는다. 주문번호·계정 메타데이터 등 임의의 HTML 속성을 모델 입력으로 내보내지 않는다.

등록명만 일치하거나 이미지·링크가 여러 부스에 공유된 경우, 같은 등록명이 여러 번 나온 경우, 구조가 중첩·미완성·변경된 경우에는 전체 문서 입력을 유지한다. 원문 미확보·잘림 또는 `CREATOR`·`PARTICIPANTS` 등 다른 작업 종류에서도 이 선택을 적용하지 않는다. 범위를 선택했다는 사실은 상품 승인·작가 동일성 확인·행사 전체 명단 완료의 근거가 아니다.

## 원문 스냅샷과 해시

각 호출은 모델 입력을 만들기 전에 수집된 원문 문서 전체를 `source-documents.json`에 저장한다. `catalogRegions` 등 분석용 메타데이터도 이 스냅샷에 남긴다. 모델에는 문서 복사본으로 만든 입력을 전달하며 저장된 스냅샷과 추출 결과를 사후 수정하지 않는다.

선택된 문서의 기존 `sha256`은 원래 수집 원문의 해시다. 줄어든 입력 텍스트의 해시로 바꾸지 않는다. 입력 범위에는 `evidenceScope.type=SINGLE_BOOTH`, `wholeCatalogProvided=false`와 별도의 `textSha256`을 기록해 원문 해시와 구별한다. `source-selection.json`에는 선택 이유, 관측 부스 수, 원문·제공 텍스트 길이를 남긴다. 선택하지 않은 호출은 빈 `selections`를 기록한다.

독립 검토는 원문을 다시 확보하고 같은 선택 조건을 새로 대조한다. 추출 단계에서 선택한 결과나 이미지 판독 기록을 검토 단계의 새 원문 확인으로 대신하지 않는다.

## 이미지 판독 입력

이미지가 4장을 넘으면 추출과 독립 검토 각각에서 전체 대상 이미지를 4장씩 보조 판독한다. 이 보조 호출에는 해당 이미지와 `imageIndex`·SHA256 매핑, 보이는 행사명·날짜·부스·상품·옵션·가격·단위·조건 및 불확실성을 기록하는 지시만 준다. 전체 카탈로그·작업 문맥·승인 후보를 매 묶음에 반복하지 않는다.

최종 추출과 최종 독립 검토에는 각 단계의 문맥·후보·원문 입력과 보조 판독 기록, 해당 단계에서 확보한 대상 이미지 전부를 계속 첨부한다. Comiverse 범위를 선택했다면 대상 부스의 카탈로그·추가 안내 이미지를 모두 포함하며, 5번째 이후 이미지를 버리지 않는다. 보조 판독은 최종 모델이 원본을 직접 보는 절차를 대체하지 않는다. 이미지 미확보는 미확인으로 남기며 재게시 권한 승인과도 구별한다([공개 원문 브라우저 보완](BROWSER_RECOVERY_KO.md)).

묶음별 `images-*/image-mapping.json`에서 실제 첨부 이미지의 인덱스·해시를, `images-*/input-metrics.json`에서 보조 프롬프트 길이·전체 단계 프롬프트 길이·이미지 수를 확인할 수 있다. 단계별 판독 결과는 `image-observations.json`, 이미지 확보·실패 기록은 `social-images.json`에 남는다.

## 행사 장소 출처의 사전 읽기

`SALES`·`CREATOR` 작업에서 행사 `sources`에만 있는 `ORIGINAL / VENUE` 출처는 사전 읽기 목록에서 유보한다. 행사장 일반 안내를 판매자·작가의 원문으로 반복해서 읽는 비용을 줄이는 처리다.

같은 URL이 명시적 입력, 참가자 공식 링크, 작가 프로필·`creatorProvenance` 등 행사 밖 문맥, 행사 출처 외의 다른 행사 필드, `VENUE` 이외의 출처에도 있으면 계속 읽는다. 독립 검토에서 후보가 인용한 필수 원문(`requiredSources`)도 항상 우선한다. 따라서 장소로 분류된 URL이라는 이유만으로 대상 식별 근거나 후보를 반증할 원문을 제외하지 않는다. `EVENT` 등 다른 작업 종류의 사전 읽기는 이 규칙의 대상이 아니다.

추출 작업 디렉터리와 각 검토 디렉터리의 `research-plan.json`에서 읽을 URL과 유보 URL을 확인한다. 유보 사유는 `EVENT_ONLY_VENUE_REFERENCE`다. 이는 접근 성공·실패 판정이나 출처 삭제를 뜻하지 않는다. 계정별 기존 작가·공식 부스 근거는 [작가 SNS 수집 계약](docs/creator-social-collection.md)을 계속 따른다.

## 확인 방법

`tests/test_catalog_scope.py`는 정확한 등록명과 유일한 기존 근거, 공유 근거·중복 등록명·공동 부스, 전체 입력 복귀, 공개 모달 허용 필드, 스냅샷·해시 보존, 추출·검토의 새 원문과 전체 대상 이미지, 보호된 장소 출처를 검증한다.

수집기 디렉터리에서 `python -m unittest discover -s tests -p test_catalog_scope.py -v`로 해당 회귀 검사를 실행할 수 있다. 이 검사는 로컬 모의 원문·이미지를 사용하며 운영 수집량·비용 절감률이나 운영 반영 완료를 보증하지 않는다.
