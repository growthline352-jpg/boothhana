# 전체 보완 완료와 자동 승인

2026-10-06 로컬 구현. 통합 배포 대기 중이며 운영 데이터·cron·설정은 변경하지 않았다.

## 실행

```sh
python repair_all.py --config /etc/boothhana/collector.json --apply
```

1. 자동 승인 대상 행사 ID를 200건씩 끝까지 조회한다. 행사·부스·판매정보·이미지를 승인하고 공개 스냅샷을 갱신한다.
2. 현재부터 365일 기간의 정보 보완 대상 전체와 접근 실패 재확인 대상을 읽는다.
3. 미완료 정보 보완을 끝까지 처리하고, 공개 행사 이미지 대상 전체를 처리한다.

조회 페이지 크기는 처리 상한이 아니다. 실행 시작 시 확보한 유한한 대상 목록을 끝까지 처리한다.
개별 HTTP·CLI 요청 제한 시간은 유지한다. 공급자 인증·사용량이 막히면 추가 검색을 중지하고
할 수 있는 저장 작업을 계속한다. 미완료가 있으면 `PARTIAL`, 종료 코드 2로 남긴다.
`--apply` 없이 실행하면 이미지 읽기 전용 조사이며 승인·저장·공개를 하지 않는다.

runner의 기존 `images` 작업은 새 전체 보완기로 연결했다. `images-store`는 웹 검색 없이
승인 이미지 저장만 끝까지 처리한다. 운영 runner 적용은 API·수집기 통합 배포 시 진행한다.

## 완료 기준

정보 보완은 `stateDirectory/event-enrichment-attempts.json`, 이미지 보완은
`stateDirectory/image-repair-v1/queue.json`에 데이터 지문·처리 방식·완료 시각을 기록한다.

| 결과 | 처리 |
| --- | --- |
| 정보 `COMPLETE` | 필요한 정보 확보. 동일 자료 재조사 제외 |
| 정보 `UNAVAILABLE` | 원문 검토 완료, 일부 정보가 공개되어 있지 않음. 동일 자료 재조사 제외 |
| `EXHAUSTED` | 서로 다른 세 경로까지 조사 소진. 동일 자료 재조사 제외 |
| 이미지 `VERIFIED` | 저장 파일과 상세·목록 공개 이미지의 ID·URL·SHA256 확인 완료 |
| `DEFERRED` / 인증·사용량·저장·공개 오류 | 미완료. 장애 해소 후 이어서 처리 |

`UNAVAILABLE`·`EXHAUSTED`는 조사 완료이며 정보·이미지가 모두 있다는 뜻은 아니다.
보고서는 성공 보완·미공개·조사 소진·미완료를 분리해서 집계한다.
시간이 지났다는 이유만으로 완료 항목을 다시 조사하지 않는다. 행사·등록 출처·자산·정책 변화 또는
명시적 `--force`로 다시 연다. 공식 원문 변경 감지는 본문·이미지/첨부 URL·선택 문맥의 지문을 사용한다. 이 지문이 같으면 추가 CLI 분석을 생략하며, 이미지 원문 지문(`sourceDigest`)이 바뀌면 완료·조사 소진 이미지 작업도 다시 연다.

## 대체 경로

1. `SOURCE_DETAILS`: 등록된 개별 원문·본문·첨부 이미지 확인.
2. `ORGANIZER_SEARCH`: 행사명·회차·주최자로 공식 홈페이지·개별 SNS 공지 검색.
3. `VENUE_SEARCH`: 행사명·회차·장소로 행사장 일정·공식 예매처·공공기관 공지 검색.

직전 시도·실패한 원문·검색어를 다음 단계에 전달한다. 같은 실패 검색어만 반복하지 않는다.
소진된 접근 실패는 서버 재확인 큐에서도 제외하며 행사 자료 버전이 바뀌면 다시 연다.
공급자 인증·사용량 또는 승인/완료 기록 저장 실패를 원문 소진으로 처리하지 않는다.

정보 보완의 `PARTIAL`도 미완료다. 원문 접근 실패 재확인 대상은 세 방법의 서버 수집 결과가 모두 `SUCCESS`일 때만 `EXHAUSTED`로 기록한다. 일부 방법이 실패하거나 부분 수집이면 마지막 방법이 성공해도 `DEFERRED`로 유지한다. 서버에는 최신 행사 버전과 각 방법의 성공 상태를 보내 `source-completion-v2` 완료 표식을 남기며, 저장 실패 시 완료 시각을 제거하고 다시 시도한다. 이전 정책의 실패·부분 수집 완료 기록과 구버전 서버 완료 표식은 재조사 대상으로 복구한다.

## 자동 승인

백엔드 `COLLECTOR_AUTO_APPROVE` 기본값은 `true`이며 수집기
`autoApproveCollectedData=true`와 함께 사용한다. 수집기 `drainEventEnrichments=true`가 전체 정보 처리를 선택한다.
원문 변경 감지의 확인된 변경도 자동 승인·공개 반영한다. 기존 수동 수정값은 보존한다.
동일 자료 재수집만으로 공개 시각을 갱신하지 않는다. 소유권 주장·거래 승인은 이 정책의 대상이 아니다.

명시적 제외 행사·부스와 거절 이미지는 되살리지 않는다. 잘못된 형식·다른 행사/회차·내부 주소·차단 원문·
파일 검증 실패는 승인 정책으로 우회하지 않는다. 자동 승인은 사용 권리 계약이 확보되었다는 의미로 기록하지 않는다.
검증된 원문 이미지의 공개 CDN은 수동 호스트 등록 없이 저장 경로에 연결하며 HTTPS·공개 IP·robots·바이트 검증은 유지한다.

롤백 시 백엔드 `COLLECTOR_AUTO_APPROVE=false`, 수집기 `autoApproveCollectedData=false`로 수동 정책을 복원한다.
`drainEventEnrichments=false`와 `image_repair.py --no-drain --max-events 100 --max-minutes 60`은 제한 실행용이다.
한도가 필요한 수동 실행에서만 사용한다. 자동 승인 원문·이미지 상태는 나중에 관리자 화면에서 변경할 수 있다.

## 배포 후 확인

2026-10-06 코드 리뷰 보완:

- 정보/이미지 보완의 timeout·접속/검색 실행 오류는 완료로 기록하지 않는다. 다른 경로까지 실패하면 재시도 상태와 시간을 유지한다. 이전 코드가 실패 이력을 `EXHAUSTED`로 기록한 항목도 재검사 대상으로 복구한다.
- 공식 목록 checkpoint는 출처별로 보존한다. COEX처럼 기간이 URL에 들어가는 목록은 진행 중 검색 기간을 유지한 채 끝까지 순회하고, 완료 후 새 기간으로 갱신한다.
- 롯데 팝업은 `NON_POPUP`과 `OUTSIDE_WINDOW`를 구분한다. 기간 밖 후보와 이전 복합 사유로 제외한 후보는 검색 기간이 바뀌면 다시 확인한다.
- 이미지 제목/alt/주변 문구가 행사 연도·회차와 충돌하면 힌트 URL이나 행사 영역 판정으로 우회하지 않는다. 기존 배너도 `matchesEdition=true`인 동일 이미지/원문 연결만 자동 승인한다.
- 자동 관측은 수집 원문 payload를 보완하고 수동 override는 유지한다. 사전검증도 실제 적용과 같은 `원문 → 관측값 → 수동 수정값` 순서로 최종 상태를 검사한다. 자동 수집값을 수동 override 영역에 저장하지 않는다.

API → 수집기 → runner 순서로 같은 릴리스를 적용한다. 이번 정책에는 추가 SQL이 없다.
첫 전체 실행 보고서 `repair-all-v1/<runId>/report.json`, 각 단계의 미완료 사유와 실제 공개 상세·목록을 확인한다.
다음 실행에서 동일 완료 버전의 조사 건수가 0인지 확인한다. 이미지 조사 소진을 이미지 공개 성공으로 집계하지 않는다.
