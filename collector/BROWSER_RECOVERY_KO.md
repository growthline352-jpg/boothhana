# 공개 원문 브라우저 보완

## TMM 공개 행사 화면

`https://takemm.com/event/@핸들/{timeline,info,store}`는 초기 HTML에 날짜가 비어 있을 수 있으므로 공개 화면을 렌더링해 읽는다. 실제 페이지에서 확인한 타임라인·행사 정보·상품&부스 경로를 함께 조사하며, 추출과 검토는 각각 새 익명 Chromium 컨텍스트를 사용한다. 현재 보이는 텍스트·링크만 전달하고, 로그인 정보·브라우저 저장소·API 응답 원문·비공개 장소는 내보내지 않는다. 현재 화면은 전체 명단·전체 상품의 완료 증거가 아니며, 실제 다른 출처의 이어받기는 계속 유지한다.

DNS를 공개 주소로 고정하고 `takemm.com`, `static.takemm.com`, `api.takemm.com`의 HTTPS GET/HEAD만 허용한다. Chromium 샌드박스, 기존 seccomp, 비 root 및 no-new-privileges를 유지한다. 봇 User-Agent와 robots 검사에 같은 수집기 식별자를 사용하며, 각 호스트의 명시적인 Disallow를 따른다. `robots.txt`의 4xx 부재는 [RFC 9309 §2.3.1.3](https://www.rfc-editor.org/rfc/rfc9309.html#section-2.3.1.3)에 따라 처리하되, 429·5xx·통신 실패에서는 멈춘다. 이 처리는 robots 파일에만 적용하며 실제 원문/API의 403을 허용으로 바꾸지 않는다.

원문 HTML 해시와 렌더링한 공개 자료의 정규화 해시는 구별한다. 공개 화면을 읽지 못하면 초기 HTML을 미확인·부분 자료로 남기며 일정·참가자·상품을 생성하지 않는다. 텍스트·링크 확보는 이미지 판독·저장·재게시 권리 승인과 별개다.

## X 공개 브라우저 동작

공식 API가 미설정 또는 401/403/429/5xx이면 `xBrowserFallback: true` 구성에서 익명 공개 브라우저를 시도한다. 2026-10-19 운영자 요청에 따라 X의 공개 프로필·게시물만 대상으로 추가한 읽기 경로다. 기존 수집 차단 호스트는 해제하지 않는다. 로그인·CAPTCHA·HTTP 차단을 우회하거나 검색엔진으로 위장하지 않는다.

## 원문 확보와 공개 검토

1. 새 익명 Chromium 컨텍스트로 공개 X 프로필·게시물의 본문과 해당 게시물에 귀속된 이미지를 읽는다. 저장된 사용자 브라우저 프로필이나 API 인증값을 브라우저에 전달하지 않는다.
2. 자동 브라우저도 읽지 못하면 `stateDirectory/browser-captures/`에 일회성 nonce가 있는 보완 요청을 기록한다. 데스크톱 공개 브라우저를 담당하는 CUA 실행자가 `browser_capture_bridge.mjs`의 `fulfillPending`으로 실제 페이지를 방문하고 응답한다.
3. 요청·URL·시각을 검증하고, 공개 본문·출처 URL·이미지 URL만 LLM에 전달한다. 응답 해시는 정규화된 DOM 필드의 해시로 표시한다. HTTP 응답 바이트를 확보한 것으로 표시하지 않는다.
4. 추출과 별도 검토는 각각 새 브라우저 요청을 생성한다. 오래된 캡처나 추출용 응답을 검토용으로 재사용하지 않는다. 실제 이미지 파일을 두 단계에 각각 첨부해 판매표 글자와 옵션을 대조한다.
5. 공개·저장 여부는 기존 서버 검증과 별도 LLM 검토를 통과해야 한다. 이미지 후보 수집이 이미지 재게시 허용을 뜻하지 않는다.

코믹인포 `comicw.net/g/숫자`의 공식 인포 표지(`/data/info/cover/`)와 본문(`/data/info/editor/`) 이미지는 원문 문서에 함께 연결한다. 다른 호스트, 검색·프로필 페이지, 기본 썸네일·아이콘은 포함하지 않는다. 판매·작가 수집은 이 원본을 실제로 내려받아 Sol에 첨부하며 검토 단계도 새로 내려받는다. 표지 그림 자체를 상품으로 추정하지 않고, 판독한 상품명·옵션·가격과 작가·회차 귀속만 별도로 검증한다. 외부 주문폼이 차단돼도 공식 인포에서 직접 확인한 상품 정보는 수집할 수 있다.

이미지가 4장보다 많으면 원본을 4장씩 별도 gpt-6.1-sol 호출에 모두 첨부하고 본문·상품·가격을 읽는다. 최종 구조화 판단과 최종 검토에는 판독 기록과 함께 원본 이미지 전체도 첨부한다. 그래프 수집은 기존 CLI 래퍼의 4장 제한을 명시적으로 해제하되, 각 파일의 크기·일반 파일·심볼릭 링크 검사는 유지한다. 검토 단계도 새 원본으로 동일한 전체 이미지 묶음을 다시 읽는다. 다섯 번째 이미지를 버리거나 별도 판독 요약만으로 원본 검토를 대체하지 않는다.

`graph_worker.py --watch`는 기존 서버 정책에서 APPROVED인 카탈로그 이미지의 저장을 별도 작업으로 계속 처리한다. LLM 조사와 저장이 서로 막지 않으며, 저장 전 승인 상태·revision을 다시 확인하고 파일 형식·해시를 검증한다. 상태를 수동 승인으로 변경하지 않는다. `catalog_media_store.py --config ... --asset ...`로 특정 승인 후보만 다시 처리할 수도 있다.

이미지 원본 서버가 HTTP 429를 반환하면 `Retry-After`의 초 단위 또는 HTTP 날짜를 해석해 해당 호스트의 나머지 다운로드를 대기한다. 값이 없거나 잘못되면 1시간, 유효한 값은 1초~7일 범위로 기록한다. 그래프 이미지 작업의 호스트 대기 시각은 `stateDirectory/catalog-image-host-cooldowns.json`에 저장해 재시작 후에도 유지한다. 대기 항목은 저장 완료나 사용 승인으로 바뀌지 않는다. 전체 이미지 큐는 200개씩 ID 커서로 순회해, 첫 페이지의 대기 호스트가 다른 호스트를 막지 않게 한다. 따라서 이 변경은 커서를 지원하는 백엔드를 먼저 배포한 뒤 수집기에 적용한다. 기존 커서 없는 이미지 API의 정렬과 특정 이미지 ID 재처리는 유지한다.

## 실행 조건과 미처리 상태

Python `playwright` 및 `python -m playwright install chromium`이 필요하다. Docker 이미지는 동일 런타임과 Chromium을 포함한다. Docker의 비 root 사용자와 Chromium 샌드박스를 유지한다.

Docker 실행에는 `deploy/ubuntu/chromium-seccomp.json`도 함께 배포한다. Compose의 수집기 두 서비스는 이 프로필을 사용해 Chromium 샌드박스에 필요한 `clone`·`setns`·`unshare`를 허용한다. `no-new-privileges`와 비 root 실행은 유지하며 `--no-sandbox`, privileged, seccomp 전체 해제는 사용하지 않는다. 프로필은 [Playwright 공식 Docker 프로필](https://github.com/microsoft/playwright/blob/main/utils/docker/seccomp_profile.json)의 복사본이며 SHA256은 `cc3e61cabda6bbc1e53e54d27ba4d55a9d3be829b6dd1a596f4a7b31b1cc7849`이다. 익명 브라우저 기동 성공과 실제 X 원문 열람 성공은 별도로 확인한다. X가 HTTP 403을 반환하면 원문 확보 성공으로 기록하지 않는다.

데스크톱 브라우저 보완 요청은 CUA 실행자가 연결되어 있어야 처리된다. CUA 연결이 없는 서버에서 자동 브라우저가 403이면 요청은 DEFERRED로 남고 작업은 실패·재보완 상태가 된다. 따라서 이 구성만으로 모든 X 페이지를 24시간 자동으로 읽을 수 있다고 주장하지 않는다. 읽기 실패를 빈 판매목록의 완료로 승인하지 않는다.

그래프 작업은 X 원문이 대기 중이어도 다른 공식 원문을 확보했다면 그 문서의 확인된 사실을 계속 추출·독립 검토한다. 대기 출처는 `available=false, browserPending=true`로 보존하며 원문 해시나 열람 기록을 만들지 않는다. 이 경우 명단·판매·작가 범위는 부분 상태로 유지한다. 확보한 원문이 하나도 없으면 기존처럼 `BrowserPending`으로 재보완 대기에 남긴다.

승인 적용이 서버의 구조화된 `400 INVALID_REQUEST`로 확정 거절되면 동일한 불변 추출 결과에 더 엄격한 `ENRICH` 판정을 기록한다. 서버가 반환한 사유는 다음 추출의 보완 입력으로 전달한다. 이로써 거절된 추출을 승인 대상으로 무한 재전송하지 않는다. 응답을 알 수 없는 타임아웃, 임대 만료·권한 오류·409 충돌은 이 방식으로 변경하지 않으며 기존 재시도와 임대 검증을 따른다. 서브컬처 그래프의 행사 유형은 공유 분류 `SUBCULTURE`만 허용하고 다른 분야를 함께 사용하는 기존 수집 스키마는 유지한다.

브라우저 프로필에서 보이는 게시물 묶음은 부분 범위다. 실제 전체 이력 커서와 계정 숫자 ID를 만들지 않는다. 이미 API 숫자 ID로 소유자가 확인된 계정은 브라우저 핸들만으로 동일 소유자를 재확정하지 않는다. 기존 API 커서는 브라우저 페이지 주소로 변환하지 않는다.

보완 요청에는 인증값·쿠키·요청 헤더가 없다. 공개 페이지의 네트워크는 지정한 X 도메인·미디어 호스트의 공개 IP에 고정하고, 다른 호스트·사설 주소·비 HTTPS 요청을 차단한다.
