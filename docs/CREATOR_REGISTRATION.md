# 크리에이터 행사 부스 등록 (0.2.7.0)

- 공개 행사 상세 → 내 부스 등록 → 기본 부스 선택 → 이번 행사 부스 소개 입력 → 등록하고 공개.
- 기본 부스가 없으면 먼저 생성하고 ‘행사 부스 등록으로 돌아가기’를 선택합니다.
- 내 부스 목록 / 내 공개 행사·부스에서 행사별 소개와 상품을 수정합니다. 기본 부스는 여러 개 만들 수 있으나 같은 행사에는 계정당 1개만 등록·연결할 수 있습니다.
- 수집된 기존 부스는 부스 상세의 운영자 연결 요청 후 관리자 승인을 받습니다. 요청 중에는 권한이 없으며 승인 시 모든 해당 행사에서 계정의 기존 부스 연결을 다시 검사합니다.
- 직접 등록은 주최 측 참가 승인·현장 배정이 아닙니다. 공개 화면에 ‘직접 등록’으로 표시합니다. 인증된 운영자 배지를 만들지 않습니다.
- 운영일·전시장 묶음도 같은 행사로 계산합니다. 서로 다른 행사에서 사용하는 이름·소개·판매 상품은 독립적입니다.
- 공개 제외된 직접 등록 부스도 계정 한도에 포함해 중재를 우회한 재등록을 막습니다. 삭제·소유권 이전은 이번 버전에서 제공하지 않습니다.
- 수집기 판매 조사에서 직접 등록한 부스를 제외하며, 기존 공개 스냅샷 중 해당 부스만 갱신합니다. 행사나 다른 부스의 미검토 수집 내용은 공개하지 않습니다.
- 기존 예약·판매 행사에서는 신규 등록과 재등록을 즉시 활성화합니다. 과거 대기 내역은 사용자가 ‘등록하고 공개’를 누를 수 있습니다. 과거 데이터는 자동 승인하거나 삭제하지 않습니다.

## 데이터 및 운영

`catalog_creator_booth`는 직접 등록자의 계정·기본 부스·행사 참가자를 연결합니다. 운영자 승인인 `exhibitor_manager`와 분리됩니다. 계정 행 잠금으로 중복 등록과 승인 경쟁을 직렬화하고 `(event_id,user_id)` 유일 제약을 추가합니다. RLS는 기존 서버 정책명으로 적용하며 익명/클라이언트 역할에는 권한을 부여하지 않습니다.

배포 순서: 백업 → SQL024 → API → 프런트엔드 → readiness 및 공개/인증 경계 확인. 이전 API로 되돌릴 때 새 테이블과 등록 데이터는 유지합니다. 수집기는 직접 등록 부스 보호가 있는 새 API와 함께 사용합니다.

이미지 변경은 기존 권리 검토 절차를 사용합니다. 공개 수집 행사 등록이 예매·예약·재고/POS를 생성하지는 않습니다. 예약·판매 운영은 해당 기능이 제공되는 별도 행사에서 사용합니다.
