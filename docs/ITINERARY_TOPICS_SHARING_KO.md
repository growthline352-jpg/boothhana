# 일정의 서브컬처 주제 선택과 링크 공유

2026-10-05. `codex/itinerary-topics-sharing`에서 구현. **운영 미배포**. 기존 v0.3.1.1 배포와 구분한다.

## 주제 선택

- 일정 만들기 → 행사 참여 → 서브컬처에서 취향 주제를 선택한다. 애니·만화, 게임, 보컬로이드, 버튜버 등 기존 공통 분류를 사용한다.
- 작품·캐릭터 등 세부 주제는 앞으로 90일의 공개 행사 `subjects`에서 가져온다. 예: 애니·만화 → 은혼 또는 사카타 긴토키. 수집 자료에 없는 작품명을 만들어 추천하지 않는다.
- 큰 주제 여러 개는 OR, 세부 주제 여러 개도 OR다. 두 그룹을 함께 선택하면 AND로 적용한다. 공통 분류의 별칭과 행사 태그를 대조하며, 소개글만 보고 관련 행사라고 추측하지 않는다.
- 선택 날짜의 실제 개최 장소·행사 ID를 사용한다. 취소·연기 행사와 팝업 분야는 제외한다. 해당 날짜에 일치하는 행사가 없으면 다른 개최일의 관련 행사 최대 3개를 보여준다. 사용자가 선택할 때만 날짜를 바꾼다.
- 선택 조건은 브라우저 저장 일정에 남고, 완성 코스에 추가하는 주변 서브컬처 행사에도 적용한다. 다른 분야로 변경하면 선택 행사와 주제 조건을 초기화한다.
- 새 수집 데이터가 공개되면 다음 조회에 주제 목록도 갱신된다. 태그가 누락된 행사는 검색될 수 있지만 해당 주제에 일치한다고 표시하지 않는다. 주제 데이터의 수집·분류 품질 관리는 계속 필요하다.

## 공유 흐름

1. 완성 일정의 **공유** 버튼을 누른다. 저장 버튼과 공유 버튼은 별개이며, 개인 초안을 자동 업로드하지 않는다.
2. 공유할 장소·주소·방문 시간을 확인한다. 장소별 메모는 기본 제외하고 체크한 경우에만 포함한다.
3. 링크를 만들고 복사한다. 기기가 Web Share를 지원하면 기기의 공유 메뉴도 사용할 수 있다.
4. 링크를 받은 사람은 로그인 없이 일정·지도·시간 확인 사항을 본다. 모바일은 일정/지도 탭으로 전환한다. 지도 핀을 고르면 해당 일정 카드로 이동한다.
5. **내 일정으로 복사**하면 새 일정 ID·장소 ID로 브라우저에 저장하고 편집 화면을 연다. 원본이나 공유본을 덮어쓰지 않는다.
6. 공유 후 원본을 수정하면 **현재 일정으로 새 링크 만들기**를 사용한다. 기존 링크에는 공유 당시 내용이 유지된다. 작성한 브라우저에서 기존 링크를 종료할 수 있다.

### 공개 범위와 보관

- 공개 목록·검색 색인·방문 통계 대상에 포함하지 않는다. 공유 HTML/API에는 `noindex,nofollow`, `no-store`와 `no-referrer`를 적용한다. HTML 미리보기의 제목·설명은 공통 문구이며 개인 일정 내용을 조회하지 않는다.
- 지도 타일 이미지에는 `referrerPolicy: origin`을 별도로 적용한다. 공유 토큰·경로는 보내지 않고 사이트 출처만 전달해 지도 공급자의 출처 확인을 충족한다. [OSM 타일 정책](https://operations.osmfoundation.org/policies/tiles/)에 따라 타일을 미리 수집하거나 오프라인 저장하지 않는다.
- 공유 링크는 90일 동안 열람 가능하다. 링크를 아는 사람은 열 수 있다. 일정당 현재 브라우저에서 관리하는 활성 링크는 최대 5개다.
- 관리 키는 작성한 브라우저의 계정/게스트별 저장 공간에 보관한다. 서버에는 해시만 저장하며 읽기 응답에 관리 키·작성자 계정 정보를 반환하지 않는다. 브라우저 데이터를 지우거나 다른 기기로 이동하면 관리 키를 사용할 수 없고, 링크는 만료일까지 유효하다.
- 종료 시 공개 접근을 차단하고 서버의 일정 본문을 즉시 비운다. 만료 자료는 새 링크 생성 시 최대 100건씩 정리한다. 만료 시각에 모든 행을 물리적으로 삭제하는 예약 작업은 아직 없다.
- 링크는 공유 당시의 스냅샷이다. 이후 공식 행사 변경·취소를 자동 반영하거나 알림을 보내지 않는다. 계정 간 일정 동기화, 공동 편집, 실제 이동 시간 계산도 이번 범위에 포함되지 않는다.

## API·저장 구조

| 요청 | 용도 |
| --- | --- |
| `POST /api/public/itinerary/shares` | `requestId`, `managementKey`, `plan`, `includeNotes`로 링크 생성. 동일 요청 재시도는 같은 링크 반환 |
| `GET /api/public/itinerary/shares/{token}` | 만료·종료 전 스냅샷 조회 |
| `POST /api/public/itinerary/shares/{requestId}/revoke` | 관리 키 확인 후 종료. 완료 여부가 불명확한 생성 요청도 취소 가능 |

- 기존 Spring CSRF 검증을 사용한다. 비회원도 링크를 만들 수 있다.
- 읽기 토큰은 암호학적 난수 128비트, 관리 키는 256비트다. 읽기 토큰으로 링크를 종료할 수 없다.
- HTTP 본문은 80KB, 일정 JSON은 60KB로 제한한다. 날짜·시간·한국 내 좌표·장소 최대 20개·문자열 길이를 검사한다. 공유 필드는 허용 목록으로 추출하고 HTTPS 또는 행사 상세 링크만 허용한다.
- 시간 충돌은 공유 화면에도 표시한다. 충돌이 있는 초안도 공유할 수 있지만 캘린더 내보내기의 기존 시간 검증은 유지한다.
- 동일 요청 ID의 다른 내용은 409, 다른 관리 키는 403, 종료·만료 링크는 404다. 종료는 204를 반환한다.
- 요청 완료 여부를 모를 때는 관리 정보를 업로드 전에 저장해 같은 내용으로 재시도한다. 취소된 생성 요청이 늦게 도착해도 다시 공개되지 않도록 종료 기록을 남긴다.
- 시간당 클라이언트 주소 기준 60건·전체 1,000건의 생성/종료 제한을 둔다.
- SQL028의 `itinerary_share`는 서버 전용 RLS·권한을 적용한다. 공개 DB 역할의 직접 접근을 허용하지 않는다. 운영 준비 상태 검사에도 테이블·열·권한을 포함한다.

## 운영 반영 순서

1. 운영 DB 백업 후 `database/028_itinerary_shares.sql`을 기존 서버 JDBC 역할 설정으로 적용한다.
2. API 배포 후 준비 상태와 비회원 CSRF·생성·조회·종료를 확인한다.
3. 프런트엔드 배포 후 공유 링크의 직접 진입·분야 도메인에서 포털로 이동·모바일·복사 편집을 확인한다.

이번 작업은 로컬/격리 테스트 환경에서만 확인했다. 운영 SQL·API·프런트 변경은 아직 실행하지 않았다.
