# 팝업 운영 분류

팝업 사이트의 목표 대표 주소는 `https://popup.boothana.kr`입니다. 코드에 주소를 추가한 것과 실제 도메인 연결·공개 완료는 별개이며 아래 출시 순서로 확인합니다. 행사 유형은 판매형, 체험형, 전시형, 복합형이며 관심 주제는 캐릭터·IP, 애니·만화, 게임, 패션, 뷰티, 먹거리·음료, 생활·리빙 등입니다. 온보딩과 내 정보에서 각각 설정합니다.

## 팝업과 서브컬처 분리 (2026-10-04)

- 기존 `POPUP_STORE`와 새 `POPUP_*`는 팝업 분야에서만 노출합니다. 캐릭터·애니·게임·보컬로이드·버튜버 주제도 팝업 안의 취향 주제로 유지하며 서브컬처 목록·캘린더·추천·인기순으로 교차 노출하지 않습니다.
- `POPUP_STORE`는 기존 ID와 저장 내역을 보존하는 호환 코드입니다. 공개 필터에서는 판매형 팝업으로 통합하고 신규 수집에는 현대 팝업 코드만 사용합니다. 기존 관리자 수정 화면은 호환 코드를 그대로 편집할 수 있습니다.
- 서브컬처는 동인·온리전·생일카페·팬 행사·관련 공연 등 공식 행사 목적에 맞는 분류를 유지합니다. 제목에 팝업이나 캐릭터가 있다는 이유만으로 자동 이동시키지 않습니다.
- 상세 정보·저장·댓글·부스 소유권은 행사 ID 하나에 연결합니다. 교차 분야 상세 URL은 대표 주소로 이동하며 사이트맵에는 대표 주소만 넣습니다.
- 기존 서브컬처 주소의 `POPUP_STORE` 상세·부스 링크는 팝업 대표 주소로 308 이동하며 방문일·지도 문맥을 보존합니다. 사이트맵도 팝업에만 포함합니다.
- 기존 관심 설정의 서브컬처 `POPUP_STORE` 선택은 읽을 때 팝업의 네 유형으로 옮겨 제공합니다. 다른 서브컬처 취향·유형과 이미 선택한 팝업 주제를 보존합니다. 조회 시 DB나 revision을 바꾸지 않고 다음 저장 시 현행 분류로 기록합니다.
- 추가 DB 마이그레이션·행사 재등록은 필요 없습니다. API·프런트엔드·수집기의 공통 분류를 같은 릴리스에 반영해야 합니다.
- 일반 브랜드의 팝업을 캐릭터 행사로 추정하지 않습니다. 상설 체험관을 팝업으로 추정하거나 티켓 사용기한을 행사 종료일로 쓰지 않습니다. 기간이 미확인인 후보는 검토 전 공개하지 않습니다.

## 출시 순서

1. 전체 릴리스 게이트를 통과한 소스의 API/수집기 이미지를 준비합니다.
2. DB 백업 후 SQL026을 적용합니다. 기존 데이터 변경은 없습니다.
3. API CORS 허용 목록에 팝업 출처를 추가하고 준비 상태·수집기 doctor를 검증합니다.
4. Vercel Production 도메인 연결 및 DNS/TLS 확인 후 사용자 화면을 공개합니다.
5. robots·사이트맵·대표 URL을 운영에서 확인한 뒤 Search Console의 boothana.kr 도메인 속성에 팝업 사이트맵과 홈 색인 요청을 제출합니다.

색인 요청 접수와 Google의 실제 검색 노출은 별개입니다. 요청 성공 여부를 운영 기록에 남깁니다.

동네 팝업 탐색과 일일 팝업 수집의 공급 시범·공개 스위치는 [행사 탐색·방문 준비 구현 안내](DISCOVERY_IMPLEMENTATION_KO.md)를 따릅니다. 전용 도메인 연결과 동네 탐색 공개는 각각 검증합니다.
