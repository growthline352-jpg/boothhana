# 운영 화면 동기화 · v0.2.4.0

## 관리자

기본 진입은 `/admin/subculture`의 **공개 행사 관리**입니다. 예약·참가신청 행사와 POS 굿즈는 별도 메뉴로 표시합니다.

- 이름·장소 검색, 분야, 검토 상태, 공개 여부와 미반영 변경을 조회합니다. 검색 조건과 페이지는 URL에 남습니다.
- 행사 편집에서 회원 온보딩과 동일한 분야별 **행사 유형 / 취향 주제**를 지정합니다.
- **방문 안내**에서 입장권, 프로그램, 회차별 FAQ, 판매·선입금 공지, 정보 수집 상태를 입력합니다. 확인한 사실에는 원문 주소·확인일을 함께 저장합니다.
- 저장은 검토 대기 또는 검토 완료입니다. 사용자 공개는 별도의 **공개본 갱신**을 실행해야 합니다.
- 현재 저장된 행사 정보와 공개 행사 정보의 차이·원문을 비교할 수 있습니다. 이 비교는 행사 정보 범위이며 부스·이미지 변경 전체를 나타내지는 않습니다.
- 부스 위치의 참가일은 근거 상태와 함께 수정합니다. 참가일 미확인/행사 기간만 확인 상태에서는 날짜를 비우며, 참가일 확인 상태에서는 시작·종료일과 검토 메모를 기록합니다.

## 업체·주최자

`/support/management`가 공개 행사·부스 관리의 진입점입니다. 기존 예약·판매 화면은 예약·참가신청·POS 기능을 관리합니다.

- 서버가 반환한 관리 권한에 따라 소개·판매 안내·상품 수정 링크를 표시합니다.
- 공동 부스는 전체 직접 수정 대신 정정 요청으로 이동합니다. 판매정보가 없는 부스에는 판매·상품 수정 링크를 열지 않습니다.
- 주최자의 입장권·프로그램·FAQ 변경은 출처가 포함된 변경 요청으로 접수하고 관리자가 검토·공개합니다.
- 직접 수정이 허용된 판매 안내는 자동 생성된 상품 요약에 덮이지 않고 사용자 부스 상세의 판매·선입금 안내에 표시됩니다.

## 같은 회차의 운영일·전시장 묶음

관리자는 공개 행사 상세의 **운영일 묶음**에서 같은 회차의 2~14개 공개 기록을 연결합니다. 분야가 같은 행사만 묶으며, 이름·공식 출처·확인일이 필요합니다. 다른 회차는 기존 **행사 회차 연결**에서 관리합니다.

묶음 저장·해제는 확인 후 즉시 공개 표시 설정에 반영됩니다. 각 원본 행사의 ID, 참가 부스, 배치도, 저장, 댓글, 관리권은 유지합니다.

- 목록은 묶음 단위로 페이지를 계산하고 달력은 실제 운영일을 표시합니다.
- 같은 날 복수 전시장이 있으면 운영 행사·전시장을 선택합니다. 저장·공유는 선택한 원본 행사에 연결합니다.
- 인기순은 묶음 내 원본 행사를 저장한 회원을 중복 제거해 집계합니다.
- 댓글은 공개된 묶음 구성원의 댓글을 함께 조회하고 원래 작성 대상 ID를 유지합니다.
- 디페스타 기존 공유 주소와 연결된 구성은 고정하며, 다른 묶음은 해제할 수 있습니다.

## 배포와 복구

1. 변경 커밋의 전체 release-verification에서 실제 PostgreSQL·HTTP·권한 회귀를 통과합니다.
2. 운영 DB를 백업하고 복원 목록을 확인합니다.
3. 관리자 DB 연결의 동일 세션에서 실제 런타임 역할을 `boothhana.backend_role`로 설정하고 SQL022를 적용합니다. 기존 SQL001~021은 재실행하지 않습니다.
4. API를 배포해 준비 상태·공개 API·보호된 관리자 API를 확인한 뒤 프런트를 반영합니다.
5. SQL022는 두 묶음 테이블과 기존 공개 판매 요약의 출처 메타데이터를 추가합니다. 기존 텍스트·ID·저장·댓글·관리권은 변경하지 않습니다. 필요하면 이전 API/프런트 이미지로 복구하며 추가 테이블은 유지합니다.

실제 배포 완료 여부는 해당 커밋의 CI와 운영 확인 기록으로 판단합니다.
