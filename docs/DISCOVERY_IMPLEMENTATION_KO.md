2026-10-04. 계획 재검토에서 선정한 초기 범위를 구현했다. 초기 구현 검증 당시 로컬 코드와 격리된 테스트 DB에서 확인했고 운영 배포·DNS·운영 DB 변경·수집 스케줄 활성화는 보류했다.

같은 회차의 여러 운영일은 비교 슬롯과 팝업 목록에서 중복하지 않는다. 비교에는 공개된 각 운영일의 장소·입장 조건을 보존하며 일부 운영일이 비공개로 바뀌면 해당 정보가 빠진다. 비공개 후보·관리자 메모는 공개 응답에 포함하지 않는다.

입장·시간 미확인을 무료·예약 불필요·현재 방문 가능으로 추정하지 않는다. 같은 날 장소가 여러 개인 저장 항목은 장소를 먼저 확인하게 하며 임의의 장소·캘린더 시간을 고르지 않는다.

캘린더 파일은 선택한 방문일 한 날짜를 내보낸다. 명확한 시간이 있으면 한국시간을 UTC로 변환하고, 시간이 없거나 여러 시간대이면 종일 일정으로 만든다. 취소·연기 또는 유효하지 않은 날짜는 내보내지 않는다. 개인 메모·계정 식별자는 파일에 포함하지 않으며 변경 사항을 자동 동기화하는 기능은 아니다.

## 수집과 정정 운영

### 공식 원문 재확인

- 신규 검색과 구분해 이미 등록된 공식 행사·장소·주최 계정의 원문만 직접 읽는다. 제공된 본문 추출은 별도의 실행 감사 기록을 남기고 실제 본문 발췌가 있어야 변경 후보로 기록한다.
- 접근 실패, 추출 실패, 원문 미공개, 변경 검토를 구분한다. 이미지에만 있는 사실·잘린 본문·읽지 못한 하위 페이지는 확인 완료로 처리하지 않는다.
- 실제 본문 해시와 행사 버전이 같고 직전 추출이 성공했으면 AI 추출을 생략한다. 실패한 추출의 해시로 이후 재시도를 생략하지 않는다.
- 누락·빈 문자열로 기존 사실을 지우지 않는다. 새로운 사실도 운영 공개본에 자동 반영하지 않는다. 관리자에서 원문 근거와 전후 값을 검토하고 선택한 항목을 수정본에 반영한다.
- 관측 뒤 행사 버전이 바뀌면 기존 관측의 반영을 차단한다. 부분 반영 후 나머지는 새 버전의 검토 대기로 남긴다.
- 관리자 현황에 기한이 지난 작업 수, 7일 이내 행사 원문 확인 건수, 오래된 검토 대기 행사, 검토 건수·시간을 표시한다. 시간에는 화면을 열어둔 시간이 포함된다.

기본 재확인 주기는 진행 중/7일 이내 행사 24시간, 먼 행사 7일이다. 실패 시 6시간부터 최대 7일까지 재시도 간격을 늘린다. 하루 실행은 최대 25행사·25회 추출, 30분의 작업 시작 한도를 사용하며 서비스 종료 한도는 40분이다. 공급량이 한도를 넘으면 지연 작업을 기록한다. 이 설정만으로 모든 행사의 24시간 갱신을 보장하지 않는다.

### 팝업 공급 시범

`collector/daily_popups.py`는 기존 수집기의 후보 큐와 검색 감사·검토 절차를 사용한다. 하루 출처 탐색 2개, 후보 상세 확인 최대 5개, CLI 최대 7회, 45분 한도다. 참가 부스·판매품·이미지 수집 예산을 사용하지 않는다. 기존 주간 수집의 팝업 작업 수 기본값은 0으로 유지했다.

현재 출처 프로필은 성수 공간 공지와 연남 브랜드·지역 공지 두 개의 시작 설정이다. 검색 후보를 공식 이번 회차 원문으로 검증하며 후보 등록 후 기존 관리자 공개 절차를 거친다. 두 출처가 충분한 팝업을 지속 공급한다는 결론은 아직 낼 수 없다.

14일 동안 동네별 후보 밀도, 날짜·장소 정확성, 시간·입장 조건 확인 비율, 재확인 지연과 검토 시간을 기록해야 한다. 기준 미달 동네는 공개 범위를 줄이거나 공급 출처를 보강한다. 기존 계획의 95% 적시 확인·동네당 후보 5개 등은 시범 목표이며 달성한 실적이 아니다.

## 공개 스위치와 배포 준비

추가 기능의 기본값은 꺼짐이다. localhost에서는 검토를 위해 화면을 볼 수 있다. API는 로컬에서도 서버 설정이 필요하다.

| 설정 | 역할 |
| --- | --- |
| `EVENT_COMPARE_ENABLED` | 공개 비교 조회 API. 방문 준비도 이 API를 사용하므로 필요 |
| `POPUP_EXPLORE_ENABLED` | 공개 동네 팝업 조회 API |
| `VITE_EVENT_COMPARE_ENABLED` | 비교 화면·진입 버튼 |
| `VITE_POPUP_EXPLORE_ENABLED` | 동네 탐색 화면·진입 버튼 |
| `VITE_VISIT_PREPARATION_ENABLED` | 보관함 방문 준비 패널 |
| `VITE_KAKAO_MAP_KEY` | 선택 사항. 설정하지 않아도 목록·외부 지도 링크 사용 가능 |

1. 전체 릴리스 검증과 DB 백업 후 추가 방식 SQL026·027을 순서대로 적용한다. SQL027은 비공개 재확인·관측·장소 테이블이며 익명/회원 직접 조회를 금지한다. 서버 준비 상태는 57개 테이블·490개 컬럼의 타입까지 검사한다.
2. API·수집기 이미지를 배포하고 스위치를 끈 상태로 확인한다. 프런트엔드 빌드 시 스위치 값을 적용한다.
3. 팝업 후보와 동네를 검토하고 수집기를 수동으로 시범 실행한다. 실제 공급·검토 부담이 확인되기 전 동네 탐색을 공개하지 않는다.
4. `popup.boothana.kr`의 호스팅·DNS·TLS·CORS·대표 URL·robots·sitemap을 검증한다. 팝업 카테고리 사이트 공개 조건은 `docs/POPUP_LAUNCH_KO.md`를 함께 따른다. 현재 팝업 도메인 연결과 Google 색인 요청은 이번 작업에서 하지 않았다.
5. `deploy/ubuntu/systemd/boothhana-popups.*`, `boothhana-rechecks.*`는 기존 Docker 수집 실행기를 호출하는 템플릿이다. 한국시간 06:05·07:10으로 준비했지만 기존 설치 스크립트가 새 타이머를 자동 활성화하지 않는다. `/opt/boothhana`에 해당 릴리스가 설치된 것을 확인한 뒤 활성화해야 한다.
6. 화면 공개 전 모바일 실제 지도, OAuth와 회원 보관함, 운영 호스팅·도메인 이동을 확인한다. 문제 발생 시 화면/API 스위치와 새 작업을 중단하고 개인 저장 데이터를 유지한다.

- 브라우저의 팝업·관리자 테스트 자료는 명시적으로 표시한 가상 데이터다. 실제 운영 공개·데이터 공급량 검증과 구분한다.

전체 운영 릴리스 게이트 통과, 14일 공급 시험, 실제 사용자 과제 시험, 실제 지도 키로 렌더링, 운영 OAuth·발송 검증을 완료했다고 주장하지 않는다. 푸시·변경 알림 발송, 자동 데이트 코스, 일정 편집기, 확장 후기와 상품 인포는 이번 구현 범위에서 보류했다.

## 후속 코드·사용성 검토 (2026-10-04)

배포 대기 변경을 다시 검토하고 아래 8건을 수정했다. 이 후속 검토 기록 작성 시점에는 커밋·운영 배포 전이었다.

- CLI 출력 스키마에서 지원하지 않는 `uniqueItems`를 제거했다. 수집 결과의 로컬 중복 검증은 유지한다.
- 요청 형식·사용량 제한·인증 오류는 해당 실행의 후속 AI 호출을 중단한다. 미처리 대상과 후보 재시도 횟수를 보존한다. 승인 이미지 저장, 캐시 재사용과 이미 알려진 허용 배치도 처리는 계속 가능하다.
- 먼 행사에 설정된 7일 재확인 예약도 행사가 임박하면 마지막 성공 확인 후 24시간에 다시 대상이 된다. 행사 버전 변경과 실제 운영일을 반영하고, 같은 버전의 실패 대기 간격은 유지한다.
- 같은 날 여러 장소에서 열리는 행사는 부스가 없어도 행사 안내에서 장소를 선택할 수 있다. 주소·입장 조건·공식 안내가 함께 전환된다.
- 비교 모드 열기·선택·선택 초기화·닫기는 행사 목록 페이지와 스크롤 위치를 유지한다.
- 비교 후보가 모두 이미 선택된 회차라면 빈 목록의 이유와 다시 찾는 방법을 안내한다.
- 단일 도메인 사이트맵에 팝업 카테고리 URL을 포함했다.
- 팝업 카드의 지도·비교 링크 터치 높이를 약 26px에서 최소 44px로 늘렸다.

후속 검증은 프런트엔드 45파일 233테스트, SEO 23테스트, 수집기 362테스트를 통과했다. 별도 PostgreSQL 16에 SQL001~027을 적용한 DB/HTTP 16테스트는 건너뛴 항목 없이 통과했고 bootJar도 성공했다. 프런트엔드 빌드·타입 검사 성공, 린트 오류 0개이며 기존 경고는 남아 있다. 이는 전체 운영 릴리스 게이트를 다시 실행한 결과는 아니다.

로컬 브라우저에서 메인 겹침, 모바일 비교, 목록 2페이지 비교 동작, 여러 장소 안내 전환, 긴 부스 이름·소개, 상품 검색·가격 정렬, 팝업 빈 결과 복귀·동네 변경, 방문 준비의 날짜 미선택 안내·저장을 확인했다. 브라우저 데이터는 저장된 공개 스냅샷과 명시한 가상 자료이며 운영에 쓰지 않았다.

후속 검토 수정까지 커밋했고 사용자가 운영 배포를 승인했다. 실제 적용 완료 여부와 운영 검증 결과는 해당 릴리스의 CI·배포 기록을 따른다.

- 행사 비교와 방문 준비는 API·화면 스위치를 함께 켜서 공개할 대상으로 준비한다.
- 동네 팝업 탐색·선택형 지도는 실제 공급과 지도 검증 전까지 비공개로 유지한다. 팝업 전용 도메인은 DNS·호스팅·TLS 검증이 필요하다.
- 공식 원문 재확인과 일일 팝업 수집의 새 타이머는 수동 시범 실행 후 활성화한다. 기존 이미지 누락·원문 접근 오류를 이 릴리스만으로 모두 복구했다고 보지 않는다.
