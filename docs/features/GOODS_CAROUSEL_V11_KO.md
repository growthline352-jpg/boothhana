# 메인 판매 굿즈 캐러셀 · 집계/공개 계약

## 1. 데이터 출처와 순위

외부 카탈로그 수집 결과는 상품·가격·판매 안내이며 실제 판매수량을 갖고 있지 않습니다. 현재 자동 집계 출처는 **부스하나 POS 기록**입니다. 기록 수량을 이용한 순위이지 PG 결제 검증이나 전체 시장 점유율이 아닙니다. 판매자가 기록하는 POS의 입력 정확성은 별도 운영 검토 대상입니다.

| 항목 | 규칙 |
|---|---|
| 지표 | `sum(pos_sale_item.quantity)`, 매출금액 아님 |
| 기간 | 응답 시각 기준 직전 30×24시간, 시작 포함/현재 시각 미포함 |
| 판매 상태 | `pos_sale.status='SOLD'`만 포함, `CANCELED` 제외 |
| 예약 | 예약 생성/수령 건수는 집계하지 않음. 같은 판매를 예약 수령과 POS에서 중복 가산하지 않음 |
| 집계 단위 | 기본 상품 `product.id`별로 여러 행사 판매기록 합산 |
| 공개 조건 | 해당 행사 PUBLISHED/ENDED, 승인·공개 행사 부스, 공개 행사 상품. 비공개 전환된 판매 경로의 수량 제외 |
| 노출 선택 | `goods_showcase.enabled=true` 및 메인 분야 일치 |
| 제외 예시 | `MOCK-` 판매번호, 상품·부스·행사명에 `[MOCK]`가 있는 개발 seed |
| 순서 | 수량 내림차순 → 마지막 정상 판매시각 내림차순 → 기본 상품 ID 오름차순 |
| 최대 | 12개, 조건에 맞는 상품이 적으면 있는 만큼만 |
| 상세 연결 | 공개중 행사 상품 우선, 이어서 최근 행사/상품을 선택. 없으면 공개된 종료 행사 상품의 이력 안내 |
| 가격·품절 | 현재 공개 상품의 값이며 과거 판매 당시와 다를 수 있음. 종료/품절 상태를 카드에서 구분 |
| 이미지 | 기존 R2 공개 이미지 기준. 무관한 외부 이미지를 자동 핫링크하지 않음 |

상품별 실판매수량·매출·구매자·판매번호·결제수단은 공개 캐러셀 응답에 넣지 않습니다. 관리자 후보 화면에서만 30일 기록 수량을 확인합니다. 관리자도 순위 숫자/판매량을 직접 수정할 수 없습니다. 출처/승인 철회는 다음 응답에서 필터링되며 별도 공개 캐시를 생성하지 않습니다.

외부 쇼핑몰의 검증 가능한 판매량을 향후 가져오더라도 누적/기간·단위·범위가 다를 수 있습니다. 이번 코드에서 POS와 섞거나 `subculture_catalog_product`를 이름만 보고 운영 `product`에 연결하지 않습니다. 외부 수집 굿즈까지 순위화하는 연결은 별도 데이터 계약이 필요합니다.

## 2. 관리자 사용 절차

1. 운영 상품을 크리에이터에서 등록하고 행사·부스·상품을 공개합니다.
2. 실거래에 해당하는 POS 판매 기록을 정상 저장합니다. 운영 DB에 시안/가상 기록을 넣지 마세요.
3. ADMIN 계정의 **메인 굿즈**에서 상품 검색 → 분야 선택 → 메인 노출 허용 → 저장.
4. 공개 조건이 맞아도 30일 정상 기록이 0이면 노출되지 않습니다. 기존 상품은 기본 노출 비허용이므로 최초 선택이 필요합니다.
5. 비공개/제외/판매 취소 후 다음 조회에서 순위가 갱신되는지 점검합니다.

서브컬처 메인에 먼저 연결했습니다. 박람회·축제는 기존처럼 준비 화면이며 설정만 변경해 해당 분야 수집/카탈로그가 구현되지는 않습니다.

## 3. 화면 동작

- 홈 소개/검색과 행사 목록 사이에 노출. 아래 행사 날짜 검색과 캐러셀의 30일 집계는 별개입니다.
- 자동 회전 없음, 이전/다음 버튼, 목록 초점의 좌우 방향키, 터치 가로 스크롤. 카드 링크 초점에서 방향키를 가로채지 않습니다.
- 로딩/집계없음/서버 오류를 구분. 기록없음은 인기없음이 아니며 가짜 대체 목록을 제공하지 않습니다.
- 상품 카드 클릭은 기존 `/products/{eventProductId}`로 이동합니다. 수집 부스와 운영 상품의 ID를 혼용하지 않습니다.
- 순위·이미지·상품명·가격·부스·행사·상태·집계기준 제공. 이미지 실패 시 같은 카드의 대체표시.
- `prefers-reduced-motion` 사용자는 부드러운 스크롤을 사용하지 않습니다. 별도 타이머가 없습니다.

## 4. API

`GET /api/public/goods/bestsellers?category=SUBCULTURE`: `basis=POS_LOGGED_UNITS`, `windowDays=30`, `from/to/asOf`, `items`.

`GET /api/admin/goods-showcase?q=&page=0&size=20`: 공개된 운영 상품 후보, 기록 수량, 현재 노출 설정. ADMIN 필요.

`PUT /api/admin/goods-showcase/{productId}`: `{category,enabled,revision}`. ADMIN 세션+CSRF 필요. DB에서 상품을 잠그고 revision 확인, 오래된 화면은 409. 원시 판매량이나 순위 입력 항목은 없음.

참고: 접근성 패턴은 W3C [Carousel Tutorial](https://www.w3.org/WAI/tutorials/carousels/) 및 [수동 캐러셀 예제](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/examples/carousel-1-prev-next/)를 참고했습니다. 전체 WCAG 적합성 인증은 아닙니다.
