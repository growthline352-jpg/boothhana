# 수집 자동 승인과 관리자 비공개 철회

## 공개 정책

- 새 수집 입력은 검증 후 자동 검토·공개한다. 관리자 수동 보정값과 제외 상태를 보존한다.
- 자동 모드에서는 관리자가 **검토 대기(PENDING)**로 저장한 내용도 다음 자동 승인 대상에 포함된다. 이 동작은 2026-10-06 사용자 결정에 따라 유지한다.
- 관리자가 **비공개로 전환**하면 `publication_withdrawn=true`를 행사에 저장하고 공개 스냅샷을 삭제한다. 반복 철회도 같은 상태를 유지한다.
- 자동 승인 목록에서 철회 행사를 제외한다. 철회 전에 조회한 자동 승인 요청, 동일 입력 재수집, 변경된 입력 재수집, 원문 관측도 철회를 해제하지 않는다.
- 철회 후에도 새 원문 관측은 수집값을 갱신할 수 있다. 공개 스냅샷은 생성하지 않는다. 관리자의 명시적 **공개**가 검토 버전과 내용 검증을 통과한 뒤에만 철회를 해제한다.
- 철회·공개·자동 승인은 같은 공개 잠금 후 행사 행 잠금을 잡는다. 철회 상태 변경 자체는 원문 사실의 `revision`을 올리지 않는다.

## 원문 관측과 이미지 보완

자동 모드에서는 관측값을 원래 수집값(`payload_json`)과 비교한다. 새 원문 값이 수동 보정 후 화면 값과 같아도 수집값을 갱신하고 관측 이력을 남긴다. 수동 보정은 유지하며, 나중에 **최신 수집값 사용**을 선택하면 새 원문 값을 사용한다. 검토 확인 시각만 바뀐 경우는 기존처럼 사실 변경으로 취급하지 않는다. 수동 검토 모드의 수정 제안은 기존 화면 값과 비교한다.

`GET /api/internal/subculture/v4/image-repair-events` 각 항목의 `sourceDigest`는 `catalog_source_check.digest`의 최신 값이다. 아직 원문 관측이 없으면 `null`이다. 공개 행사 정보와 공개 버전이 같아도 원문 지문은 바뀔 수 있으며, 실패 관측도 최신 지문을 노출한다. 이미지 보완 완료 기록은 이 지문 변화로 재검증을 시작한다.

원문 관측의 `CONFIRMED` 값은 실제 인용문과 값 검증을 함께 통과해야 한다. 날짜는 원문의 행사·예매 필드 문맥과 전체 기간에 연결하며, ISO 날짜·시간은 서울 시간대로 정규화한다. 주소·장소·입장 정보·상태·구조화된 관람 안내도 직접 입증할 수 있는 값만 전달한다. 불일치하거나 모호한 추출은 실패로 기록하여 기존 사실을 유지한다.

본문이 80자 미만이거나 추출 범위를 넘는 원문도 읽은 이미지·첨부·연결 페이지의 지문은 보존한다. 필드 추출 자격과 이미지 버전 감지를 분리하여 짧은 포스터 페이지에 새 이미지가 게시되면 완료된 이미지 보완 작업도 다시 확인한다.

## 배포와 기존 철회

DB 백업 후 **SQL029 → SQL030**을 적용하고 새 백엔드 준비 상태를 확인한 뒤 컬렉터를 재시작한다. SQL030은 기존 서버 전용 행사 테이블에 `boolean not null default false` 컬럼 하나를 추가하며 기존 권한과 RLS를 유지한다. 전체 준비 상태와 검증 기준은 SQL001~030, 60개 테이블·513개 컬럼이다.

이전 스키마는 공개 스냅샷이 없는 행사에서 **공개 전 검토만 완료한 상태**와 **공개 후 철회한 상태**를 구분하지 못한다. SQL030은 과거 상태를 추정해서 변경하지 않는다. 배포 전에 기존 철회 목록을 확인하고, 새 API에서 해당 행사에 비공개 전환을 다시 적용한 뒤 자동 컬렉터를 시작해야 한다. 이 문서의 배포 순서는 아직 운영에서 실행하지 않았다.

이번 회귀는 철회 전 큐에 들어간 요청·동일/변경 입력 재수집·새 관측 후 비공개 유지·수동 재공개, 수동값과 같은 최신 원문 갱신 및 보정 제거, 사실 변경 없는 원문 지문의 이미지 API 노출을 격리 PostgreSQL 통합 테스트로 확인한다. 실제 실행 결과는 `output/deployment-review-final-fixes-20261006/`에 기록한다.
