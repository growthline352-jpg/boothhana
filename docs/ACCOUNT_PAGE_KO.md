# 내 정보 화면

경로: `/account`. 햄버거 메뉴와 모바일 하단 메뉴에서 접근한다.

## 정보 구조

1. 계정 정보: 실제 AuthProvider의 표시 이름·프로필 사진과 권한. 로딩·인증 오류·비회원·회원 상태를 구분한다. 회원은 닉네임(2~20자)과 사진을 수정하거나 사진 사용을 해제하고 변경사항을 저장할 수 있다.
2. 내 활동: 보관함(메모·방문 기록), 기기별 오프라인 저장본, 예약 내역. 기존 기능으로 연결하며 별도 목록을 복제하지 않는다.
3. 행사·부스 운영: 소유권 인증 및 승인 정보 관리. 크리에이터·관리자 작업 공간은 해당 권한일 때만 노출한다. 실제 접근 권한은 기존 서버가 검증한다.
4. 고객지원: 문의·신고 답변, 행사 추가 요청.
5. 저장 정보 안내 및 로그아웃: 계정/기기 저장 차이를 안내하고 실제 로그아웃 동작을 사용한다.

관심분야 설정에서는 서브컬처·박람회·축제를 각각 선택하고 분야별 행사 유형·취향 주제를 여러 개 고른 뒤 `관심분야 저장`을 누른다. 분야를 선택하고 세부 항목을 비워 두면 그 분야 전체를 보여 주며, 세부 항목을 고르면 하나 이상 일치하는 행사만 포함한다. 계정에 저장하므로 기기와 분야 도메인이 달라도 같은 설정을 사용한다.

신규 카카오 회원은 `/onboarding`에서 `선택 완료` 또는 `나중에 선택하기`를 눌러 안전한 원래 내부 경로로 돌아간다. 기존 회원에게 온보딩을 강제하지 않으며 내 정보에서 언제든 설정할 수 있다. 분야별 홈은 `내 관심분야`·`전체 인기`를 전환하고, 저장된 일치 행사가 없으면 같은 조건의 `새로 공개된 행사`를 보여 준다.

계정 유형과 행사·부스 소유권 인증은 서로 다른 개념임을 표시한다. 이메일·전화번호·가입일·로그인 제공자는 현재 User 응답에 없으므로 추측해서 노출하지 않는다. 회원 탈퇴 기능은 아직 제공하지 않는다.

## 개인정보와 이후 작업

- 공개 검색 메타데이터는 `내 정보 | 부스하나`, noindex이며 실제 계정 이름은 메타데이터에 포함하지 않는다.
- 조회는 기존 인증 상태를 사용하며 오류/로딩 시 이전 사용자 정보를 숨긴다. 프로필 저장은 CSRF가 적용된 `PATCH /api/me/profile`을 호출한 뒤 인증 정보를 갱신한다.
- 사진은 로그인 사용자의 `profile` 업로드 대상으로 서버 검증을 거친다. JPG·PNG·WebP·GIF, 최대 10MB이며 다른 사용자의 이미지 키를 사용할 수 없다. 사용자 지정 닉네임은 재로그인 후에도 유지한다.
- 프로필 기능에는 `database/019_user_profile.sql`이 필요하다. 회원 탈퇴를 추가하려면 예약·보관함·소유권 처리 정책을 먼저 정의해야 한다.
- 관심 설정은 `GET /api/me/interests`와 CSRF가 적용된 `PUT /api/me/interests`를 사용한다. 현재 계정 ID·수정 revision을 함께 보내며 다른 화면에서 설정이 바뀌면 최신 설정을 다시 불러온 뒤 저장한다. 신규 관심 기능에는 `database/020_category_interests.sql`이 필요하다.

## 검증

초기 내 정보 화면은 회원/비회원/인증 오류/권한별 SSR 테스트로 확인했다. 프로필 화면 검사는 `frontend/src/pages/AccountPage.test.tsx`, 서버 저장·이미지 권한 검사는 `PlatformServiceTests`·`R2UploadServiceTests`, HTTP·DB 검사는 `ReleaseIntegrationTests`에 있다. 이번 배포의 실제 실행 결과는 CI와 배포 수락 결과를 기준으로 확인한다.
관심 항목 분리·안전한 복귀 경로는 프런트 관심 설정 테스트, 옵션 검증은 `InterestTaxonomyTests`, 계정·CSRF·revision·실DB 저장은 `LibraryIntegrationTests`로 검사한다. 전체 검증과 브라우저 수락 범위는 [관심분야 검증 및 배포 계획](CATEGORY_INTERESTS_TEST_PLAN.md)에 있다.
