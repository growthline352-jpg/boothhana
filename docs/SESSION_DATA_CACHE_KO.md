# 화면 조회 데이터 재사용

같은 화면·조회 조건으로 돌아올 때는 앱이 처음 받은 결과를 즉시 표시한다. 캐시는 현재 로드한 앱의 메모리에만 보관하며 브라우저 새로고침으로 초기화된다. 서브컬처뿐 아니라 행사 탐색, 보관함, 일정, 고객센터, 작가·관리자 화면에 공통으로 적용한다.

## 공통 조회

`useRemote(namespace, load, dependencies)`에 고정된 리소스 이름과 모든 조회 조건을 넣는다. 이름이 다른 결과나 다른 행사·캐릭터·검색 조건은 분리하며, 동일 조건으로 돌아오면 완료된 결과와 진행 중인 요청을 공유한다. 실패한 조회는 재진입 또는 다시 시도에서 재조회한다. 빈 목록과 `null`도 정상 결과로 재사용한다.

API 계층은 URL·메서드·요청 헤더·조회 본문별 읽기 요청을 재사용한다. `cache: 'no-store'`는 HTTP 저장을 막으며, 앱 메모리 재사용은 별도로 적용한다. 한 화면의 취소 신호는 다른 화면이 공유하는 요청을 중단하지 않는다.

공개 정보 일괄 조회와 고객센터 대상 조회는 POST지만 조회 전용으로 표시한다. 조회 완료가 자기 자신을 저장으로 취급해 다시 요청하지 않도록 한다. 접수·결제 등 이전 쓰기 결과 확인과 명시적인 계정 확인은 재사용하지 않는다. 첨부 다운로드·저장·업로드·알림 설정은 사용자 작업으로 계속 실행한다.

## 갱신과 계정 경계

성공한 저장은 API 읽기 캐시를 무효화한다. 표시 중인 리소스는 현재 내용을 유지하면서 갱신하고, 떠나 있는 화면은 다음 진입에 갱신한다. `setData`로 확인된 저장 결과를 반영한 뒤 늦게 도착한 GET이나 오류가 그 결과를 덮어쓸 수 없다. `reload()`와 `fresh: true`는 의도적인 새 조회다. 기기 보관함 상세는 로컬 변경 버전도 조회 조건에 포함한다.

일반적인 브라우저 focus·visibilitychange·pageshow에서는 데이터를 재조회하지 않는다. 다른 창에서 실제 계정·권한이 변경됐는지는 공개 가능한 비인증 신호의 SHA-256 지문만 비교한다. 지문이 변경되면 이전 캐시와 진행 중인 계정 상태를 제거하고 서버의 `/api/me`로 다시 확인한다. 이 신호는 로그인이나 권한 부여의 근거가 아니다. 운영의 분야 사이트는 같은 상위 도메인에서 이 신호를 공유한다. 기기 저장이 제한돼도 서버의 401 처리는 유지한다.

로그아웃·확인된 계정 변경·세션 만료는 모든 화면 캐시를 제거한다. 이전 계정의 리소스·응답·콜백은 새 캐시를 복원할 수 없다. 보관함의 30초 자동 갱신은 제거했고 개인 일정 저장소도 화면을 떠났다가 돌아올 때 재사용한다.

## 검증

회귀 테스트는 재진입, 진행 중 요청 공유, 별도 조회 조건, 빈 결과, 재시도, 저장 반영, 계정 경계, 호출자별 취소, 조회 전용 POST, 다른 탭의 계정 신호를 검사한다. 실제 공개 API를 연결한 로컬 브라우저에서 홈·캐릭터 목록·상세·작가 목록 재방문 시 추가 요청 0건과 로딩 상태 0건을 확인했다.
