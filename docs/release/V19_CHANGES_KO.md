# 부스하나 v19 · 코드리뷰 및 오류 수정

2026-09-18 · 기준: `BoothHana2-full-v18-20260918.zip` · **운영 배포 승인: false**

## 결과 요약

v18의 서울·경기 / 서브컬처·박람회·축제 범위는 유지하면서, 오프라인 자료의 삭제·동시 저장·권한 재확인·다중 탭 표시 오류를 보완했습니다. 서버 DB용 신규 SQL은 없으며 SQL001~016은 원본과 동일합니다. 실제 운영 데이터·수집 실행·외부 계정·GitHub·배포를 변경하지 않았습니다.

이번 신규 회귀 테스트는 저장소/네트워크/화면 대역을 사용하는 18개입니다. 동일한 테스트를 원본 v18 모듈에 실행하면 17개 실패·1개 통과, 수정 모듈에서는 18개 모두 통과했습니다. 17개 실패는 17개 독립 결함 또는 실제 브라우저 오류를 뜻하지 않습니다. 동일한 원인의 여러 시나리오가 포함되어 있습니다.

**호환성 주의: v19는 기기에 내려받은 임시 오프라인 자료만 새 저장 형식으로 전환합니다. v18에서 받은 오프라인 행사 사본은 다시 내려받아야 합니다. 회원/비회원 보관함의 기존 저장 기록·메모·서버 DB는 이 전환 대상이 아닙니다.**

## 검토 범위와 실제 수정

### R19-01 · 삭제한 자료가 늦은 다운로드로 되살아나는 문제

원본은 다운로드 시작 후 행사별 삭제 여부를 충분히 구분하지 않아, 사용자가 삭제했는데 늦게 완료된 요청이 다시 저장할 수 있었습니다. 아직 저장되기 전의 첫 다운로드를 삭제한 경우도 재현했습니다.

수정: 행사별 변경 토큰을 유지하고 저장 직전 하나의 IndexedDB 트랜잭션에서 계정 세대·행사 변경 토큰·사본 식별자를 검사합니다. 삭제는 파일이 없는 경우에도 토큰을 바꾸며, 자료가 변경되면 늦은 저장을 거절합니다. 성공한 새 사본을 이전 다운로드가 덮어쓰지 않습니다.

파일: `frontend/public/offline/store.mjs`의 `readContext`, `deletePack`, `commitPack`, `downloadEvent`.

### R19-02 · 늦은 계정 처리와 재확인이 다른 계정의 사본에 영향을 주는 문제

계정 확인은 비동기입니다. 원본에서 이전 계정의 `syncOwner` 작업이 늦게 실행되면 새 계정의 자료를 지울 수 있고, 저장 시각만 같은 서로 다른 사본을 오래된 권한 확인 응답이 혼동할 수 있었습니다.

수정: 계정 검사를 실제 저장소 요청의 콜백에서도 다시 수행하고, 계정별 epoch와 사본별 UUID를 사용합니다. 삭제 응답(401/403/404/410)도 계정·행사 변경 토큰·사본 ID가 모두 일치할 때만 적용합니다. 인증 확인중/오류를 비회원으로 간주하지 않습니다.

파일: `store.mjs`, `OfflinePrivacyGuard.tsx`, `offlineModule.ts`, `OfflineDownloadPanel.tsx`.

### R19-03 · 공개에서 제외된 판매 요약·예전 출처 표시가 사본에 남는 문제

원본 서버가 공개자료를 거르지 못한 문제가 아닙니다. 서버의 현재 공개 응답을 받더라도 오프라인 사본에 이전 판매 요약이나 이미지 출처표시가 남을 수 있었던 문제입니다.

수정: 현재 공개 응답으로 행사·부스·상품의 공개 문구를 다시 구성하고, 실제 기기에 받아둔 이미지 중 현재 허용되는 동일 URL 자료만 유지합니다. 숨긴 상품과 판매 요약은 제거하고 출처표시를 갱신합니다. 선택한 상품이 제거되었을 때 자동으로 선택됐던 부스 표시도 해제하되, 사용자가 직접 선택한 부스 표시는 구분하여 유지합니다.

재확인은 원래 사본을 제자리에서 수정하지 않고 새 사본으로 커밋합니다. `checkedAt`은 갱신하지만 최초 `savedAt` 및 7일 만료일은 연장하지 않습니다. 신규 이미지는 재확인만으로 자동 다운로드하지 않습니다. 네트워크 확인이 실패하면 유효기간 안의 기존 사본을 표시하며, 오프라인에서 권리 철회를 즉시 알 수 있다고 보장하지 않습니다.

파일: `policy.mjs`의 `refreshedPackage`, `store.mjs`의 `revalidate`.

### R19-04 · 다른 탭에서 지운 이미지가 열린 화면에 계속 남는 문제

원본에서 저장소는 변경됐지만 이미 열어둔 상세 화면의 이미지·내용이 갱신되지 않는 경로를 재현했습니다. 또한 늦게 도착한 행사 목록 응답이 이후에 연 행사 상세를 덮어쓸 수 있었습니다.

수정: 저장소 변경 알림을 받으면 현재 커밋된 사본을 다시 읽어 표시합니다. 이 경로에서는 네트워크 재확인을 시작하지 않아 탭끼리 알림→재조회가 반복되는 것을 막습니다. 요청 세대 번호로 이전 화면 응답을 무시하고, 교체할 때 이전 이미지의 Blob URL을 해제합니다. BroadcastChannel이 지원되지 않는 브라우저에서는 페이지 재진입·가시성 변경 시 재확인으로 보완합니다.

파일: `frontend/public/offline/app.mjs`.

### R19-05 · 검색할 때 이미지 URL 누적 / 열린 화면의 만료 미반영

검색 입력마다 같은 이미지의 Blob URL을 새로 만들고 즉시 정리하지 않아, 한 화면을 계속 사용하면 URL이 누적됐습니다. 행사 상세를 계속 열어두면 만료 시점이 지나도 화면이 그대로 남는 경로도 있었습니다.

수정: 동일 사본에서 이미지 키별 URL을 재사용하고 화면 교체·종료 시 해제합니다. 만료 타이머와 다시 보이는 시점의 조회로 만료 자료를 화면에서도 제거합니다. 브라우저가 백그라운드 타이머를 늦출 수 있으므로 기기가 잠긴 순간까지 정확한 시간에 실행된다고 보장하지 않습니다.

파일: `app.mjs`의 `blobURL`, `dispose`, `renderPack`, `load`.

### R19-06 · 배치도 파일이 없는데 있는 것처럼 판단 / 잘못된 실패 안내

배치도 URL이 허용되었다는 사실만으로 저장 성공 여부를 판단하던 부분을 실제 Blob 다운로드 성공 기준으로 수정했습니다. 6번째 행사나 총량 초과는 계정 오류가 아닌 저장 한도로 안내합니다. JSON MIME 검사도 `text/not-json`처럼 이름만 포함한 잘못된 응답을 거절하도록 엄격하게 했습니다. 일부 이미지가 제외된 이유를 모두 개수 한도라고 단정하지 않도록 안내도 수정했습니다.

파일: `store.mjs`의 `boundedFetch`, `downloadEvent`, `commitPack`; `app.mjs`.

### R19-07 · 이전 Service Worker / 행사 이동 / 선택 목록 미완료 경계

기본 파일을 확인할 때 설치 중인 새 worker보다 이전 active worker를 먼저 선택하지 않도록 수정했습니다. 새 버전 설치·활성화와 버전 응답을 확인한 뒤 다운로드를 진행합니다.

행사 상세 이동 시 이전 다운로드는 저장 허용 콜백에서 현재 행사 ID까지 검사하고, 동의·저장 결과 UI를 초기화합니다. 선택 목록이 아직 로딩 중인데 빈 목록을 조용히 저장하지 않도록 하며, 사용자가 선택 표시 포함을 해제하면 공개 정보만 저장할 수 있습니다.

파일: `store.mjs`의 `ensureShell`, `sw.js`, `OfflineDownloadPanel.tsx`.

이 영역의 React/worker 연동 전체는 실환경 검증이 남아 있습니다. 로컬 타입 계약과 기존 대역 검사 통과를 실제 휴대폰 통과로 바꾸어 표현하지 않습니다.

### R19-08 · 현재 안내와 검사 진입점 정리

활성화된 박람회·축제 선택지에 남아 있던 ‘준비 중’ 표시를 정리하고 서버의 오래된 설명 주석을 교정했습니다. 현재 검증 진입점과 CI는 v19 회귀 검사를 포함합니다. v18의 루트 안내 원문은 `docs/history/v18-review-baseline/`에 보존했습니다. 과거 로그와 릴리스 파일은 이번 버전의 성공 근거가 아닙니다.

## 유지한 범위

서울특별시·경기도, 인천 제외, 세 분야의 15개 하위 분류, 기존 수집기 일정/예산, SQL001~016, 기존 의존성 버전과 잠금 파일, 회원/비회원 보관함, 예약/POS 정책, 이미지의 별도 오프라인 허용, 7일·5개 행사·60MiB 한도는 유지했습니다. 오프라인 구매·수령 상태 변경, 서버 동기화, 실시간 재고·혼잡·알림을 새로 구현하지 않았습니다.
