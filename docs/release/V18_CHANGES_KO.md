# 부스하나 v18 변경 내역

## 1. 서울·경기 범위

수집 프롬프트, JSON 규격, Python/Java 검증, 실행 scope, 공개 조회 SQL, 지역 필터, 소개·메타 문구를 서울특별시와 경기도로 맞췄습니다. 인천은 제외합니다. 경기 전시장을 이름 때문에 서울로 저장하지 않으며, 주소와 지역 코드가 다르면 거절합니다. 주소 미공개를 추적하지 않고 지역 근거가 없으면 미확인으로 남깁니다. 기존 SEOUL-only 수집 기록은 그대로 보존됩니다.

새 주간 체크포인트는 `weekly-v18`입니다. 이전 `weekly-v5` 폴더를 삭제하지 않습니다. CLI의 `--resume`은 새 서울·경기 scope만 이어갑니다. stage wire의 runnerVersion=5 및 내부 `/subculture/` URL, 테이블명은 기존 식별자/외래키 호환 때문에 유지했습니다. 실제 예약 작업을 등록·실행하지 않았습니다.

## 2. 서브컬처·박람회·축제 공통 카탈로그 연결

세 분야 각각 5개 하위 분류(총15개)를 수집부터 검토·공개·검색·상세·기기 저장까지 사용하는 공통 구조에 연결했습니다. 목록 SQL은 요청 분야에 속한 하위 분류만 검색하고 지역을 서울·경기로 제한합니다. 박람회 요청에 서브컬처 결과를 대신 내보내지 않습니다. 분류는 이름 추측이 아니라 수집/검토된 명시적 하위 코드에서 결정합니다. 관리자 행사 수정에 지역·하위 분류 선택도 추가했습니다.

박람회: 주류·와인, 웨딩, 생활·취미, 디자인·아트, 창업·산업.
축제: 걷기·거리, 불꽃·빛, 음악·공연, 먹거리, 지역·문화.

**데이터를 이미 수집·배포했다는 뜻은 아닙니다.** 운영자가 실제 출처와 분류를 검토하고 공개한 행사만 표시합니다. 일반 축제의 공연 시간표 전용 데이터 모델, 무대별 프로그램, 실시간 혼잡·재고·취소 알림은 새로 구현하지 않았습니다. 공연 출연자를 판매 부스로 자동 변환하지 않습니다. 서브컬처에 특화된 문구/운영 정책을 모든 분야에서 실사용 검증한 것도 아닙니다.

## 3. 명시적 행사 오프라인 저장

행사 상세의 [이 행사 오프라인 저장]에서 기기 저장에 동의하면 공개 행사 일정·장소·설명·출처, 참가 부스번호와 공개 상품 텍스트를 IndexedDB에 저장합니다. 옵션으로 현재 개인 보관함에서 선택한 이 행사 부스/상품의 선택 표시를 포함합니다. 기존 기기 저장소/회원 보관함 전체를 복제하지 않습니다.

계정 메모·계정명·주문번호·결제·예약 내역·수령 완료 상태는 저장하지 않습니다. 따라서 이번 버전의 목록은 구매 관심/방문 준비용 공개 선택 목록이지 공식 선입금·수령 확인표가 아닙니다. 오프라인 메모 수정·구매/수령 체크·서버 동기화는 후속 범위입니다.

오프라인 진입점은 **`/offline/index.html`** 이며 특정 행사는 `#행사ID`로 엽니다. 기본 화면 파일은 `/offline/` 범위의 Service Worker+Cache Storage, 행사 공개 데이터와 허용 이미지 Blob은 IndexedDB에 보관합니다. 별도 React 빌드 없이 존재하는 정적 리더지만 실제 프런트 배포에는 기존 정상 빌드가 필요합니다. 일반 사이트 전체, 계정/관리자/판매자 화면을 오프라인으로 만드는 기능은 아닙니다.

자료를 먼저 표시하고 온라인일 때 공개·이미지 사용 상태를 별도로 확인합니다. 부스번호·부스명·상품명 검색, 선택한 부스만 보기, 이미지 배치도 확대·축소, 행사별/전체 삭제, 저장/만료 시각과 부분 저장 표시가 있습니다. 지도 자동 경로 계산은 없습니다.

### 저장 한도 및 정합성

저장 후 7일, 최대5행사, 합계60MiB, 행사당20MiB, 이미지당8MiB, 행사당 이미지24개. 배치도를 우선하며 선택한 부스/상품 이미지와 허용 대표 배너가 대상입니다. 텍스트 한도는 참가부스2,000개·상품5,000개 및 공개 응답4MiB입니다. 한도는 초기 보호값이지 성능 보장 수치가 아닙니다.

빠진 이미지·배치도 상태 조회 실패·CORS 오류를 완전 저장으로 표현하지 않습니다. 새 저장 실패 시 기존 유효 사본을 먼저 지우지 않습니다. 계정 확인 오류를 비회원으로 바꾸지 않으며, 확인된 계정 변경/로그아웃을 온라인 화면이 관측하면 이전 패키지를 비우고 epoch로 늦은 다운로드 쓰기를 차단합니다. 명시적 취소 역시 저장 직전 검사합니다.

### 개인정보 및 권리 경계

오프라인 리더는 로그인 화면이 아닌 **이 기기 사용자가 열 수 있는 명시적 공개 자료 사본**입니다. 선택 목록 자체도 관심사가 드러날 수 있어 저장 전에 안내/동의를 받습니다. 공용 기기에서는 사용 후 삭제해야 합니다. 인터넷 없이 서버 계정 변경·권리 철회를 실시간으로 알아낼 수는 없습니다. 서버 공개 철회/이미지 허용 철회를 온라인 재확인하면 로컬 자료를 삭제·제외하되, 타인이 이미 복사한 파일까지 소급 회수할 수는 없습니다.

이미지 `offlineAllowed`는 기본 false입니다. 관리자가 기존 공개 사용 승인과 별도로 임시 기기 저장 허용 근거를 확인해야 합니다. 관리 배치도는 READY 상태와 저장 허용이 함께 필요하며 변경된 관리 배치도의 오래된 원본으로 되돌아가지 않습니다. 외부 이미지 URL 후보 자체는 저장하지 않습니다. 공개 API 요청에는 Cookie/Authorization을 전달하지 않고 리다이렉트·과대 파일·잘못된 MIME을 거절합니다.

브라우저 저장 유지/홈 화면 설치/저장 용량은 기기마다 다릅니다. 사용자의 데이터 삭제나 저장공간 회수로 사라질 수 있습니다. 저장 시점 자료이지 당일 재고/판매 중/실시간 일정이라는 보장은 없습니다.
