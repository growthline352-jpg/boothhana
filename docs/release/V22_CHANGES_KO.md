제품 회귀 시나리오 22개를 같은 테스트로 비교했습니다. 원본 v21에서는 **14개 실패·8개 통과**, 수정본에서는 **22개 통과**입니다. 여러 경계를 검사한 결과이며 실패14개를 독립 결함14개로 세지 않습니다. 실제 사용자 피해나 운영 중 악용을 확인한 결과도 아닙니다.

## R22-01 · 저장 성공을 오래된 조회 성공/실패가 덮는 문제

**원인**: `useRemote.setData`는 해당 조회 영역이 살아 있는지만 확인했습니다. 이미 진행 중인 GET의 요청 번호는 그대로라서 저장/추가답변 성공을 화면에 반영한 뒤에도 오래된 GET 결과가 이를 덮거나, GET 실패가 성공한 내용을 지우고 오류 화면으로 바꿀 수 있었습니다.

**수정**: 명시적인 `setData` 반영도 조회 번호를 진행시킵니다. 그 이전의 GET 성공·실패는 더 이상 화면을 변경하지 못합니다. 값 전달/함수형 갱신 모두 적용하고, 이후 사용자가 새로 시작한 조회는 정상적으로 반영됩니다. 다른 조회 영역으로 이동한 뒤 이전 setter가 영향을 주지 않는 기존 보호도 유지합니다.

파일: `frontend/src/app/useRemote.ts`.

경계: 화면 상태의 순서를 바로잡는 것이며 이미 서버에서 실행된 저장을 취소하거나, 모든 동시 변경의 서버 revision을 비교하는 기능은 아닙니다.

## R22-02 · 종료한 비회원 문의의 늦은 응답과 다른 접수의 조회키 혼용

**원인**: 비회원 문의의 추가 답변은 현재 ref의 조회키로 전송하고, 완료하면 무조건 ticket 상태에 반영했습니다. 사용자가 ‘조회 종료·키 지우기’를 누른 뒤에도 늦은 답변 성공이 문의 내용을 다시 표시할 수 있었습니다. 조회A에서 보관된 이전 callback이 조회B를 연 뒤 실행되면 B의 현재 키로 A의 초안을 보낼 수도 있었습니다.

**수정**: 조회 단위의 번호와 당시 접수ID·조회키를 함께 캡처합니다. 보내기 전과 응답 후 현재 조회와 일치하는지 확인합니다. 조회 종료·다른 접수 열기·같은 접수 재열기·컴포넌트 종료는 이전 조회를 무효화합니다. 처음 조회/신규 접수의 늦은 응답·오류도 유효한 조회에만 반영합니다. 답변 폼은 접수별로 구분합니다.

파일: `frontend/src/features/support/GuestSupportPage.tsx`.

조회키를 URL·localStorage·서버 로그에 추가 저장하지 않습니다. 비회원 문의는 기존 `guestEnabled` 설정이 켜진 경우의 기능이며 자동으로 활성화하지 않았습니다. **이미 전송한 답변이 서버에 접수된 사실을 되돌리는 것은 아닙니다.** 결과가 불확실하면 해당 접수로 다시 조회해야 합니다. 네트워크 대기 중 closure의 키까지 암호학적으로 즉시 지운다고 보장하지 않습니다.

## R22-03 · 열린 보관함 편집 화면에 철회된 과거 판매정보가 남는 문제

**원인**: v21은 서버 보관함 응답/검색에서 철회된 판매 요약을 정리하지만, 이미 열린 편집 화면은 이전에 받은 개인 entry를 유지합니다. 공개정보만 재확인하면 current는 갱신되지만 과거 saved 요약·태그는 남아 ‘저장 당시 정보’에서 다시 표시될 수 있었습니다.

**수정**: 개인 entry와 새 공개 응답을 합치는 `refreshedEntry`를 추가했습니다. 같은 대상인지 전체 식별자를 확인하고, 공개 부스의 별도 판매정보가 없으면 화면용 과거 판매 요약/태그를 서버 정책과 동일하게 정리합니다. 공개 확인 중/오류/대상 불일치/전체 철회에는 예전 공개 문구·이미지를 표시하지 않습니다. 새 공개정보로 변경 여부도 계산합니다.

파일: `frontend/src/features/library/memory.ts`, `frontend/src/features/library/LibraryPage.tsx`.

개인 메모·방문일·장소메모·방문기록·revision 및 편집기 key는 유지합니다. 원본 entry 객체나 서버 saved_json을 수정하지 않습니다. 따라서 공개 확인을 이유로 편집기를 재생성해 입력 중 메모를 지우지 않도록 했습니다. 실제 입력 유지의 브라우저 동작은 별도 수락검사 대상입니다. **즉시 실시간 철회를 보장하지 않으며**, 기존 공개정보 재확인/캐시 주기는 그대로입니다. 오프라인 사본의 철회 경로를 변경한 것도 아닙니다.

## R22-04 · 경기도 행사에서도 장소 지도·주소 복사가 숨겨지는 문제

**원인**: 수집·서버·분야는 서울·경기로 확대했지만 행사 상세의 `usableAddress`는 여전히 서울 주소만 허용했습니다. 경기도의 명시적인 공개 도로명 주소가 있어도 두 버튼을 숨겼습니다.

**수정**: 서울/서울특별시, 경기/경기도를 단어 경계와 함께 허용하고 양끝 공백을 정리합니다. 인천·다른 지역, 비공개·미정·모처·미확인, 번호 없는 주소는 계속 거절합니다. `서울특별시X로 123` 같은 잘못된 지역 접두사도 허용하지 않습니다.

파일: `frontend/src/features/visit/visit.ts`.

공개된 주소로만 기존 지도 연결/복사를 허용합니다. 주소를 추정하거나 행사장의 비공개 위치를 보완하지 않으며, 외부 지도 사이트의 실제 검색 결과 정확성을 이번 검사로 보장하지 않습니다.
