# v16 변경사항 · 보관함과 기존 탐색 연결

## R15-01 인증 확인과 저장 위치

`AuthSession`은 `checking / authenticated / anonymous / error`를 명시적으로 관리합니다. 정상 로그인 응답과 HTTP401 또는 성공한 로그아웃만 저장 주체를 확정합니다. 403·5xx·네트워크·시간초과·잘못된 성공 응답은 `error`입니다. 이때 기존 회원을 비회원으로 해석하지 않습니다.

확인 중·오류에는 이전 사용자 객체를 노출하지 않고 개인 목록·쓰기 기능을 보류합니다. 공개 행사 탐색은 유지하며 계정 다시 확인을 제공합니다. 중복 인증 조회는 한 요청으로 합치고, 종료·새 계정 확인 뒤 도착한 이전 응답은 버립니다. `/api/me`는 no-store/15초 조회 제한입니다.

LibraryProvider의 변경 요청은 React가 재렌더되기 전에도 현재 인증 스냅샷과 세대값을 확인합니다. 비회원 저장의 공개 정보 조회가 끝나는 동안 계정이 바뀌면 기기에 쓰지 않습니다. 이미 서버에 도착한 요청의 서버 커밋을 클라이언트가 취소한다고 주장하지 않으며, 늦은 결과를 다른 계정 화면의 성공으로 표시하지 않습니다.

보관함 메모 초안은 페이지 메모리 안에서 같은 계정·같은 항목 revision일 때만 잠깐의 인증 재확인 뒤 복원할 수 있습니다. 개인 초안을 새로 localStorage에 복제하지 않습니다. 확정된 계정 변경·로그아웃이나 명시적 닫기에는 버립니다. 서버 revision이 바뀌면 예전 초안을 새 값으로 자동 저장하지 않습니다. 실브라우저 포커스·미저장 경고는 스테이징 검증 대상입니다.

핵심 코드: `frontend/src/app/AuthSession.ts`, `AuthContext.tsx`, `AuthStatusNotice.tsx`, `features/library/LibraryProvider.tsx`, `MemoryDrafts.ts`.

## R15-02 상품의 확인 수준 보존

현재 공개 스냅샷의 `ProductRow.verification`을 별도 필드로 추출해 `Current.verification`으로 전달합니다. 상태는 CONFIRMED_CURRENT/NOT_RECONFIRMED/LEGACY이고 마지막 확인 시각은 lastSeenAt입니다. 없는 과거 자료를 최근 확인 완료로 만들지 않고 LEGACY로 표시합니다.

보관함 카드와 메모 상세에 재확인 미완료·과거 수집 이력 경고를 표시합니다. 품절·취소·행사 관련성·원문 경고는 함께 유지됩니다. 확인 시각은 한국시간으로 표시하되 실시간 재고 보증으로 표현하지 않습니다. 비공개 상품은 current/saved/image 자체를 노출하지 않는 정책을 유지합니다. 기존 메모나 스냅샷은 재작성하지 않습니다.

핵심 코드: `LibraryModels.java`, `LibraryTargets.java`, `features/library/types.ts`, `VerificationNotice.tsx`, `LibraryPage.tsx`.

## R15-03 방문일 일치

행사 카드에서 하나의 visitDay를 계산해 상세 링크와 SaveButton에 전달합니다. 10/1~5 행사에 10/3~4 조건이면 둘 다10/3입니다. 비연속 일정의 공백을 운영일로 생성하지 않습니다. 이미 저장한 방문일은 사용자의 의도일 수 있으므로 수정하지 않습니다.

## R15-04 다시 찾기의 페이지 보존

`navigation.ts`가 q/event/type/visited의 실제 변경에만 page를 초기화합니다. item 열기/닫기와 group은 page를 유지합니다. 삭제 등으로 마지막 페이지가 범위를 벗어나면 마지막 유효 페이지로 조정합니다. URL 변경에 preventScrollReset을 유지하고 기존 dialog 초점 복귀를 사용합니다. 실제 Router/브라우저 back 동작은 별도 검증합니다.

일괄 SQL에는 원래 공개 행사·참가자·판매정보 조건과 승인/저장된 자산 조건을 유지합니다. 대표 배너를 명시 선택한 뒤 승인 철회하면 예전 배너로 몰래 돌아가지 않습니다. 전체 SQL은 사용자 데이터를 문자열로 직접 삽입하지 않습니다.

**왕복 호출 수 감소와 실제 응답 속도는 다릅니다.** 동일 SQL 안의 JSON/LATERAL 처리 비용과 네트워크·동시성은 실제 DB로 측정해야 합니다. 200개 상한·기존128KiB 요청 크기는 전역 DoS 방어가 아니므로 기존 프록시 제한을 유지합니다.

메모 편집 중에는 공개 정보만 별도로 재검증하고 같은 항목의 편집기를 주기적으로 초기화하지 않습니다. 서버가 공개 상태를 바꿨을 때의 지연은 다음 재검증까지이며 강제 push/다운로드 파일 회수가 아닙니다.

## 선언된 TypeScript 설정과 문법 일치

기존 GuestStore와 TradeSubmission의 constructor parameter properties를 명시적 필드 선언·대입으로 바꿨습니다. `erasableSyntaxOnly` 설정을 끄거나 의존성 버전을 낮추지 않았습니다. 공개 공식 설정 설명: https://www.typescriptlang.org/tsconfig/erasableSyntaxOnly.html . 이는 실제 전체 빌드 통과가 아니라 로컬 타입/문법 검사에서 확인한 보완입니다.

## 유지한 범위

추가 SQL 없음(001~015 유지,43테이블), 기존 localStorage 키 유지, 수집 프롬프트·스케줄·자료, 예약/POS 정책·요청 ID, 신고/문의·원문 사용 승인·공개 검토를 유지합니다. 관심 자동 가져오기, 과거 저장 방문일 일괄 변경, 실시간 재고·박람회/축제 수집은 추가하지 않았습니다.
