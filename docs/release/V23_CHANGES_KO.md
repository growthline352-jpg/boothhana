실제 제품 변경은 **프런트 11개 파일(신규 CSS 1개 포함)**입니다. 백엔드·SQL001~016·수집기·의존성·잠금 파일과 `/offline/` 실행 파일은 v22와 동일합니다. 기존 메모·방문계획·오프라인 사본을 초기화하지 않습니다.

## 1. 재현해 수정한 코드·상태 문제

### R23-01 · 중첩 창을 다른 순서로 닫으면 배경 스크롤 잠금이 남음

기존 `openCatalogDialog`는 창마다 열기 전의 `body.style.overflow`를 보관했습니다. 메모 편집기에서 QR 창을 열고 부모 편집기부터 정리하면, 부모가 먼저 잠금을 해제하고 QR의 나중 cleanup은 `hidden`을 복원합니다. 페이지 스크롤이 계속 막히거나 초점이 닫힌 창에 남을 수 있습니다.

문서별 공유 모달 스택과 중복 구독 횟수로 바꿨습니다. 마지막 활성 창이 닫힐 때만 원래 overflow를 복원하고, 남은 최상위 창 또는 유효한 실행 버튼으로 초점을 돌립니다. 닫힌 부모 내부로 초점을 돌리지 않으며, 실행 버튼이 사라지면 공개 본문으로 이동합니다. 중복 cleanup과 showModal 실패도 검사했습니다.

수정: `frontend/src/features/catalog/dialogLifecycle.ts`.

실제 Chromium의 **독립 HTMLDialogElement 화면**에서 원본 v22의 부모 우선 닫기 오류를 재현했습니다. 같은 독립 DOM 검사에서 v23은 정상·부모 우선·중복 정리 3가지가 통과했습니다. 이 검사는 실제 React 앱에서의 모달 재조정 전체를 검증한 것은 아닙니다.

### R23-02 · ‘저장한 부스’ 조건이 남아 검색 초기화가 불완전함

기존 빈 부스 목록의 초기화는 검색어와 전시관만 지우고 URL의 `my=saved`/`my=visited`를 유지했습니다. 사용자가 초기화해도 계속 0개를 보게 될 수 있었습니다.

`resetVisitFilters`로 검색어·전시관·개인 목록 조건·선택 부스/상품/지도 강조를 함께 해제합니다. 방문 날짜와 현재 보기 방식은 유지하고 뒤로가기용 모달 상태도 정리합니다. 현재 적용 조건과 해제 버튼을 결과 위에 보여줍니다.

수정: `visit.ts`, `CatalogPublicPage.tsx`.

### R23-03 · 관심 목록 조회 실패를 ‘부스 없음’으로 표시함

계정 확인중·보관함 로딩·오류에도 빈 index를 기준으로 ‘소개된 부스 0곳’이 표시될 수 있었습니다. 이제 확인되지 않은 개인 목록을 실제 없음으로 판단하지 않고 별도 대기/오류 안내를 보여줍니다. 확인 전에는 개인 필터 선택을 막고 전체 공개 부스로 돌아가거나 보관함에서 확인할 수 있게 합니다. 배치도에도 확인되지 않은 개인 강조 ID를 전달하지 않습니다.

전체 공개 부스 탐색은 개인 목록 오류와 별개로 계속 이용할 수 있습니다. 새로운 서버 권한이나 인증 우회 기능을 추가한 것은 아닙니다.

수정: `CatalogPublicPage.tsx`.

### R23-04 · 잘못된 날짜를 0개 결과처럼 표현 / 적용 기간이 보이지 않음

시작일이 종료일보다 늦는 등의 오류를 검색 결과 없음과 구분했습니다. 날짜 필드에 오류 연결을 추가하고, 날짜 수정 또는 기간 조건만 해제하는 경로를 제공합니다. 기간 하나만 적용된 경우도 해당 조건을 표시·해제할 수 있습니다. 지역·검색어는 개별 해제 시 보존합니다.

수정: `DiscoveryPage.tsx`, `browse.ts`.

### R23-05 · 사라진 페이지에서 복귀하면 다른 필터까지 지워짐

공개 목록이 줄어 유효 범위 밖의 페이지가 된 경우, 같은 조건의 첫 페이지로 돌아가도록 했습니다. 지역·검색어·기간은 유지합니다. `31 / 2`처럼 범위를 벗어난 페이지 숫자를 유효한 페이지네이션처럼 표시하지 않습니다.

수정: `DiscoveryPage.tsx`.

## 2. 사용성·디자인 개선

| 영역 | 확인한 부족점 | 반영 내용 |
|---|---|---|
| 행사 탐색 | 탐색 중 추천 상품과 긴 소개를 먼저 거치고, 조건 확인이 분산됨 | 직접 탐색 결과를 먼저 배치하고 추천 상품은 결과 아래로 이동. 일정 찾기·보관함·현장 열기 바로가기 제공 |
| 필터 | 선택 항목의 뜻을 다시 해석해야 하고 기간 단독 조건이 불명확 | 지역·기간·정렬의 보이는 라벨, 적용 조건 칩, 개별/전체 해제, 오류와 빈 결과 분리 |
| 행사 상세 | 긴 내려받기 설명이 부스 검색보다 먼저 나옴 | 부스 검색·지도·행사 안내를 먼저 배치. 짧은 이동 메뉴에서 현장용 저장 구역에 접근 |
| 오프라인 내려받기 | 정책·동의·선택 항목이 한 번에 길게 노출됨 | 요약 카드 + 펼치는 저장 옵션. **동의와 실행 버튼은 같은 펼침 영역**에 유지. 기존 자료 열기는 항상 노출 |
| 보관함 | 관심 저장과 오프라인 다운로드를 혼동하기 쉬움 | 두 기능의 차이와 행사 상세에서 내려받는 경로 안내 |
| 보관함 검색 | 입력 후 갱신만 있어 실행·지우기가 불분명함 | 검색/검색어 지우기 버튼, Enter 제출 즉시 반영. 자동 검색의 기존 지연 동작도 유지 |
| 선택된 행사 | 그룹 정보를 못 읽으면 선택 상자가 비어 보일 수 있음 | ‘선택한 행사 · 이름 미확인’ 임시 라벨. 무조건 계속 로딩 중이라고 주장하지 않음 |
| 기기 저장 안내 | 비회원에도 계정 기록 영구 유지처럼 읽히는 보조 문구 | 비회원은 저장일 기준90일 임시 기록으로 표시 |
| 모바일 이동 | 작은 상단 링크에서 보관함·현장 자료를 다시 찾아야 함 | 하단 고정 메뉴: 행사 찾기 / 내 보관함 / 오프라인 자료. safe-area와 하단 여백 반영 |
| 시각적 위계 | 영역별 글씨·버튼·메타 정보가 일관되지 않음 | 핵심 입력·버튼 크기, 보조 글씨, 여백·테두리·초점 표시 정리. 다운로드 구역은 녹색 계열로 구분 |
| 모달 | 긴 내용에서 닫기 버튼을 다시 찾기 어려움 | 보관함·QR 창 머리글과 닫기 동작을 상단에 유지 |

현재 브랜드 로고·분야별 색상·승인된 이미지 정책을 유지했습니다. 무단 행사 사진이나 가짜 상품을 제품 데이터로 넣지 않았습니다. 미리보기만 별도의 가상 행사/업체 자료를 사용합니다.

## 3. 명확한 경계

- 개인 저장/메모를 자동으로 오프라인 복사하거나, 내려받기를 동의 없이 시작하지 않습니다.
- 오프라인 읽기 전용 정책, 이미지 별도 허용, 기존 7일·5개 행사·60MiB 한도를 바꾸지 않습니다.
- 이번 CSS는 공개 방문자 화면 중심입니다. 관리자·판매자 전체 폼과 대형 카탈로그 관리 화면을 전면 개편하지 않았습니다.
- 키보드/터치 사용성을 고려했지만 WCAG 준수 인증이나 모든 장애유형·보조기술 검사를 마친 결과는 아닙니다.
- 사용자 인터뷰/A·B 실험은 수행하지 않았습니다. 사용시간 단축·전환율 개선·실사용 수요를 수치로 주장하지 않습니다.
