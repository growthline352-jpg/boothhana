# BoothHana2 프로토타입 역기획 및 불일치 분석

## 문서 상태

- 분석 단계: 1단계 — 역기획 및 불일치 분석
- 작성일: 2026-08-09
- 문서 성격: 구현 전 1단계 분석 기록. 이후 구현 상태와 실행 방법은 루트 `README.md`, 확정 결정은 승인 계획을 기준으로 한다.
- 분석 대상: [GitHub `prototype`](https://github.com/dkskrn2/booth/tree/main/prototype)의 HTML/CSS/브라우저 렌더링
- 비교 자료: `안건정리_20260801_1653 .txt`, `부스플랫폼_기능명세_초안.xlsx`, 승인된 Lean CRUD 계획
- 기준 우선순위: 최신 안건 정리 → 승인 계획 → 엑셀 초안 → 프로토타입 화면

## 근거 표기

- **[관찰]** 프로토타입 HTML, CSS 또는 브라우저로 렌더링한 화면에서 직접 확인한 내용
- **[명세]** 최신 안건 정리 또는 승인된 계획에서 확정된 내용
- **[명세-초안]** 엑셀 초안에 적혀 있으나 최신 합의로 변경되거나 제외될 수 있는 내용
- **[추정]** 화면과 명세를 연결하기 위해 에이전트가 예상한 구현안. 아직 확정된 요구사항이 아님

별도의 이미지 파일로 된 스크린샷은 제공되지 않았으므로, 이 문서에서 말하는 화면 관찰은 정적 HTML을 실제 브라우저로 렌더링한 결과를 뜻한다.

## 분석 요약

- **[관찰]** 프로토타입에는 총 73개 HTML이 있다. 루트 3개, 팬 16개, 크리에이터 27개, 관리자 18개, 공통 9개다.
- **[관찰]** 화면 지도 표기는 팬 18개, 크리에이터 27개, 관리자 17개, 공통 10개로 되어 있어 실제 파일 수와 일치하지 않는다.
- **[관찰]** HTML 간 로컬 링크의 누락 파일은 발견되지 않았다.
- **[관찰]** 총 125개 버튼, 87개 입력창, 57개 선택창, 12개 텍스트 영역, 43개 표가 있으나 실제 서버 통신이나 저장은 없다. 화면은 대부분 샘플 데이터와 제한적인 프런트 동작만 가진 정적 프로토타입이다.
- **[명세]** 구현 대상은 프로토타입 전체가 아니라 승인 계획의 포함 범위뿐이다.
- **[명세]** 온라인 결제·정산·통계·신고·관심·견적·통합 검색·엑셀 업로드·관리자 사용자 관리는 제외한다.
- **[명세]** React 화면, Java API, Supabase PostgreSQL, Cloudflare R2를 사용하며 카카오 OAuth와 지정 카카오 계정 관리자 규칙을 적용한다.

- **[관찰]** 상단 브랜드 영역, 데스크톱 내비게이션, 역할별 사이드바, 모바일 역할 메뉴, 본문 컨테이너, 하단 서비스 링크가 반복된다.

## 2. 명세서에 정의된 기능

### 2.1 현재 구현 대상으로 확정된 기능

- **[명세]** 역할 사전 선택 없는 카카오 OAuth 로그인, 모든 로그인 사용자의 팬·크리에이터 권한과 지정 카카오 계정 ID의 추가 관리자 권한
- **[명세]** 관리자 행사 CRUD, 공개·종료, 행사 참가 신청 목록·승인·반려
- **[명세]** 크리에이터 기본 부스 CRUD, 행사 참가 신청, 승인된 행사별 부스 정보 CRUD
- **[명세]** 상품 CRUD, 이전 행사 상품 정보 복사, 행사별 가격·공개·예약 가능 설정
- **[명세]** 단일 통합 재고, 유한·무한 재고, 재고 수량과 독립적인 수동 `SOLD OUT`
- **[명세]** 부스·상품 이미지를 Cloudflare R2에 서버 제어 서명 방식으로 직접 업로드
- **[명세]** 팬의 공개 행사·부스·상품 목록·상세 조회
- **[명세]** 한 부스 안에서 상품과 수량을 선택하는 직접 예약, 예약번호·QR 표시
- **[명세]** 팬의 내 예약 목록·상세·취소
- **[명세]** 크리에이터의 예약 목록·상세·예약번호 검색·수령 완료
- **[명세]** 간단 POS 판매 생성·목록·상세·취소, 현금·계좌이체·기타 결제수단 메모
- **[명세]** 부스 공지 CRUD와 부스당 최대 한 개의 상단 고정 공지
- **[명세]** 종료 행사의 기존 공개 주소 읽기 전용 유지, 신규 예약·POS 차단, 기존 예약 취소 허용

### 2.2 엑셀 초안에는 있으나 최신 합의에서 제외된 기능

- **[명세-초안]** 장바구니, 주문서, 온라인 결제, 결제 실패·환불 상태
- **[명세-초안]** 사전구매 재고와 현장판매 재고의 분리
- **[명세-초안]** 재고 변동 이력과 중복 수령 방지 중심의 강한 정합성
- **[명세-초안]** 상품별·채널별·결제수단별 판매·매출 요약
- **[명세-초안]** 이메일 또는 소셜 가입 선택, 상세 계정 상태
- **[명세]** 위 항목은 최신 안건 정리와 승인 계획에 따라 현재 구현 대상이 아니다.

## 4. 화면만으로 알 수 없는 사항

- **[관찰]** 정적 HTML에는 실제 인증 토큰, 세션 수명, 역할 판정 방식이 없다.
- **[명세]** 관리자 판정은 지정 카카오 계정 ID로 한다.
- **[추정]** 서버가 Kakao subject와 허용 목록을 비교해 역할을 내려줘야 한다.
- **[관찰]** 입력 필드의 필수 여부, 길이, 허용 파일 형식·크기, 저장 실패 시 메시지는 대부분 알 수 없다.
- **[관찰]** 삭제가 물리 삭제인지, 연결 데이터가 있을 때 차단되는지 알 수 없다.
- **[관찰]** 행사 종료가 종료 시각에 따라 자동인지 관리자의 명시적 조작인지 알 수 없다.
- **[관찰]** 한 카카오 계정이 팬과 크리에이터 역할을 동시에 가질 수 있는지 알 수 없다.
- **[명세]** 이후 승인에서 모든 로그인 사용자가 팬·크리에이터 기능 권한을 함께 가지는 것으로 확정했다.
- **[관찰]** 예약번호 형식과 QR payload가 예약번호인지 상세 URL인지 알 수 없다.
- **[관찰]** 예약 취소·수령 완료·POS 취소가 재고에 미치는 구체적 순서와 실패 결과는 화면에 없다.
- **[관찰]** 이전 행사 상품 복사 시 이미지·설명·가격 중 무엇을 복사하고 무엇을 새로 입력하는지 알 수 없다.
- **[관찰]** 공지 고정 변경 시 기존 고정 공지를 자동 해제할지 확인 대화상자를 띄울지 알 수 없다.
- **[관찰]** 목록 데이터가 많아졌을 때 정렬·페이지 처리 방식을 알 수 없다.
- **[명세]** 고급 검색·필터와 성능 최적화는 제외한다.
- **[추정]** 첫 MVP에서는 작은 목록을 전제로 단순 전체 조회 또는 최소 페이지 처리만 고려한다.

## 9. 구현 전에 확인했던 사항과 확정 결과

### 9.1 데이터 구조 또는 핵심 흐름에 영향을 주므로 확정이 필요한 사항

1. **한 카카오 계정의 기능 권한**
   - **[관찰]** 프로토타입은 로그인 전에 팬/크리에이터 유형을 선택한다.
   - **확정 결과:** 로그인 전 선택을 없애고 모든 로그인 계정에 팬·크리에이터 권한을 함께 파생한다. 지정 계정에는 관리자 권한만 추가하며 `User.role`은 저장하지 않는다.

2. **연결 데이터가 있는 항목의 삭제 규칙**
   - **[명세]** 행사·부스·상품 CRUD에는 삭제가 포함된다.
   - **[관찰]** 프로토타입은 제거·비공개 버튼을 보여주지만 연결 예약·판매가 있을 때의 결과는 없다.
   - **[추정]** 예약·POS가 연결된 행사/부스/상품은 삭제를 막고 비공개·종료로 전환하는 편이 데이터 손실을 줄인다.
   - **확정 결과:** 예약·판매가 연결된 행사 부스와 상품의 물리 삭제를 막고 상태 변경을 사용한다.

3. **행사 종료 판정 방식**
   - **[명세]** 관리자가 행사를 종료하고 종료 후 읽기 전용이 된다.
   - **[관찰]** 화면에는 종료일과 상태 선택이 모두 있다.
   - **[추정]** MVP에서는 관리자 수동 종료를 기준으로 하고 종료일은 표시·검증용으로 쓰는 방식이 가장 단순하다.
   - **확정 결과:** 관리자 수동 종료를 사용하고 자동 종료 작업은 만들지 않는다.

4. **이전 상품 복사 범위**
   - **[명세]** 상품 정보 복사와 행사별 가격·재고 재설정이 포함된다.
   - **[명세-초안]** 과거 재고·판매·주문 기록은 복사하지 않는다.
   - **[추정]** 상품명·설명·이미지를 복사하고 가격·재고·공개·예약·SOLD OUT은 새 행사 값으로 입력한다.
   - **확정 결과:** 이름·설명·이미지만 복사하고 가격·재고·공개·예약·SOLD OUT 값은 새 행사에서 입력한다.
