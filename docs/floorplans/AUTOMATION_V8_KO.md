# 배치도 자동화 v8

이 문서는 **구현 내용**입니다. 실제 외부 행사 도면에서 인식 정확도나 전체 서비스 연동을 검증 완료했다는 의미는 아닙니다.

## 처리 흐름

일요일 03:00 KST 기존 행사→참가자→판매정보 배치를 유지합니다. 새 `run_scheduled.py`가 기존 배치 종료 후 배치도 수집을 실행합니다. 기존 배치가 PARTIAL 또는 실패 코드여도 배치도 단계는 별도로 시도합니다. 월요일~토요일 04:00 KST에는 개최 14일 이내 또는 진행 중인 행사만 배치도를 보완 확인합니다. 이는 PC/서버에 제공 스케줄을 설치해야 실행되며, 파일을 받는 것만으로 예약이 등록되지 않습니다.

1. DB의 기존 행사에서 미확보/재확인 시점이 된 대상을 선택합니다. 행사가 신규 검색 결과에 안 나와도 기존 대상으로 남습니다.
2. Codex CLI에 공식 행사·회차·날짜와 확인된 링크를 전달해 배치도를 찾습니다. NOT_FOUND, ANNOUNCED, ERROR를 구분하고 원문·확인일·다음 확인일을 저장합니다.
3. 행사 배치도 후보에 원본 게시 URL, 이미지 URL, 전시관·구역·개별 적용일을 저장합니다. 접근 실패나 목록 미발견으로 이전 배치도를 삭제하지 않습니다. 행사 종료 후에는 자동 탐색 대상에서 제외합니다.
4. 관리자가 원본 저장·이미지 분석·웹 배치도 변환에 필요한 사용 근거를 승인하고, 수집 PC `imageAllowedHosts`에 실제 원본/CDN 호스트를 허용합니다. LLM과 수집 토큰은 승인 권한이 없습니다.
5. 수집 프로그램이 실제 파일을 내려받아 10MiB/2,500만 화소, MIME, SHA-256, 방향·애니메이션을 검사합니다. HTTPS/443, 목적 호스트 허용 목록, 공개 IP 고정 연결, 리다이렉트마다 재검사 규칙을 사용합니다. 승인된 변환 대상은 일반 이미지 작업과 중복 저장하지 않도록 분리합니다.
6. 원본 해시+적용 범위로 불변 버전을 생성하고 원본 bytes를 R2의 `verified/floorplan/` 경로에 저장합니다. 같은 URL의 파일 내용이 바뀌면 새 버전입니다. 원본을 재인코딩하거나 기존 버전 위에 쓰지 않습니다.
7. 큰 도면은 **전체 축소 이미지 + 겹치는 구역 이미지**를 Codex `--image`에 붙여 해석합니다. 기본 구역 크기 1400px·겹침240px입니다. 작은 도면은 1개 구역입니다. 모델은 도형·번호 JSON을 출력하며 HTML/SVG/스크립트를 생성·실행하지 않습니다. OCR 라이브러리는 사용하지 않습니다.
8. 구역별 좌표를 원본 정규화 좌표(0~1)로 합치고 중복을 제거합니다. 범위 밖·비정상 좌표·자기 교차·잘린 영역은 차단하거나 검토 경고로 남깁니다. 겹치는 부스, 같은 도면의 중복 번호, 불확실 판독은 자동 확정하지 않습니다.
9. 행사·날짜·전시관·구역·부스번호를 대조해 참가자를 연결합니다. `A-03a`, `A-03b`, `B01`, `B1`을 임의로 합치지 않습니다. 날짜가 다르면 같은 도형에 날짜별 다른 참가자 연결을 둘 수 있습니다. 한 참가자의 여러 영역 연결도 가능합니다.
10. 관리자 검토에서 영역 꼭짓점 이동·사각형 추가·번호 수정·직접 연결이 가능합니다. 좌표 JSON 편집도 제공합니다. 저장 후 재매핑하고, 부분 결과 공개는 별도 확인을 받아야 합니다.
11. 공개 승인은 원본/좌표/연결을 하나의 스냅샷으로 선택합니다. 행사 자체의 공개는 기존 카탈로그 승인으로 별도 처리합니다. 공개되지 않은 참가자의 이름·ID 후보·내부 검토 메모는 공개 배치도에서 반환하지 않습니다.
12. 방문자는 HTML 내 SVG에서 확대/축소·원본배경 전환·날짜/전시관 선택·부스 검색을 사용할 수 있습니다. 부스 클릭은 기존 판매정보 드로어와 연결됩니다. 미연결 영역을 누르면 추측한 업체가 아닌 미연결 안내를 표시합니다.

## 늦은 발표와 변경

- 14일 이후 행사: 기본 7일 후 재확인. 14일 이내: 기본 1일 후. 오류: 6시간 후 대상 가능(실제 다음 실행은 스케줄 주기에 따름). 공개 예정일이 확인되면 그 날짜도 고려합니다.
- 일일 보완 쿼리는 이전 주간 nextCheck가 뒤여도 임박 행사를 하루 단위로 다시 확인합니다.
- 권한 미승인 후보는 이미지 처리 한도를 차지하지 않습니다. 원본별 마지막 처리 시각 순으로 돌아가며 오류도 시도 시각을 남깁니다.
- 동일 이미지가 재확인되면 CLI 이미지 분석은 재사용합니다. 참가 명단만 달라졌으면 매핑만 다시 계산하고 검토 대기로 바꿉니다. 수정한 관리자 연결도 유효한 참가자 ID인지 다시 확인합니다.
- 새 bytes가 관측되거나 적용 범위·참가 명단이 바뀌면 옛 위치 연결을 최신처럼 계속 표시하지 않습니다. 원본 사용 승인 철회도 공개 시 확인합니다.
- 공개된 행사/참가자 스냅샷의 위치가 현재 명단과 다르면 `PUBLICATION_STALE`로 숨깁니다. 기존 행사·참가자 검토 및 카탈로그 공개 갱신 후 배치도 공개를 확인하세요.
- 같은 날짜·전시관으로 확정된 별도 이미지 URL들은 같은 공개 범위의 후보가 될 수 있습니다. **새 URL이 이전 파일의 공식 교체본인지 자동 확정하지 않습니다.** 관리자가 해당 범위에서 새 버전을 선택하거나 이전 버전 공개를 중지합니다. 범위가 불명확하면 자동 병합하지 않습니다.
- 끝난 행사는 자동 탐색을 중단하지만 원본·좌표·공개 이력은 보관합니다. 실제로 배치도가 없는 행사는 관리자가 ‘해당 없음·탐색 중지’로 설정할 수 있습니다.

## 저장 데이터

SQL009의 5개 테이블: `subculture_floorplan_watch`(탐색 상태·임대), `subculture_floorplan_source`(출처·변환 허용·범위), `subculture_floorplan_version`(원본·좌표·매핑·수동 수정), `subculture_floorplan_publication`(공개 스냅샷), `subculture_floorplan_receipt`(발견 결과 재전송 중복 방지). 모든 신규 테이블에 RLS를 활성화하고 public/anon/authenticated에 직접 접근을 주지 않습니다.

기존 운영 행사·예약·재고·POS는 그대로입니다. 수정은 수집 카탈로그와 공개 탐색 영역에만 연결됩니다. 원본 키/버전/해시를 분리하며 이전 파일이나 데이터를 자동 삭제하지 않습니다. 저장소 정리 정책은 별도 운영 작업입니다.

## 예외 및 정확도 한계

- JPG/PNG/WebP/정적 GIF 대상입니다. PDF 배치도는 기존 원문 링크 안내만 유지하며 PDF 페이지 렌더링·벡터 추출을 추가하지 않았습니다.
- EXIF 회전 JPEG, 애니메이션, 낮은 해상도/너무 많은 구역/큰 파일은 추측 변환하지 않고 실패·검토 대상으로 남깁니다. 원본 방향을 정규화한 공식 파일을 별도 확보해야 할 수 있습니다.
- 한 이미지에 여러 전시관과 반복 번호가 섞여 있고 적용 범위가 불명확하면 자동 매핑을 보류합니다. 도면 범위 확인 또는 수동 영역·연결 검토가 필요합니다.
- `complete`는 추출기의 보고이며 전수 정확성 보장이 아닙니다. 실측 동선 안내, 최단 경로, 실시간 재고 기능은 아닙니다.
- 최초 또는 변경 결과 공개는 관리자 검토가 필요합니다. 사람 확인 없이 모든 지도·권한을 자동 승인하는 기능은 없습니다.
- 현재 작업 환경에서는 실제 Codex 계정과 외부 공식 배치도를 사용한 end-to-end 실행/정확도 측정을 하지 않았습니다.

공식 CLI 계약 확인: https://developers.openai.com/codex/cli/reference/ (`--image`, `--output-schema`), https://developers.openai.com/codex/noninteractive/ . 설치한 CLI 버전에서 `codex exec --help`로 함께 확인하세요. 사용 모델이 이미지 입력을 지원해야 합니다.
