# 주최자·부스 운영자 확인과 행사 회차 연결

## 사용자 흐름

행사 상세 또는 부스 상세에서 로그인 후 인증을 신청한다. 공식 계정 소유 또는 담당자 위임 근거를 제출하고, 관리자가 고객지원의 인증 심사 화면에서 승인·보완 요청·반려한다. 승인 이후에도 관리권을 회수할 수 있다. 신청자 본인은 자신의 신청을 승인할 수 없다.

행사는 `주최자 확인`, 부스는 확인된 업체 이름과 함께 `운영자 확인`을 표시한다. 이 표시는 운영 관계 확인이며 행사 품질, 실제 참석, 거래 안전 보증이 아니다. 비공개 증빙과 계정 식별자는 공개 API에 노출하지 않는다.

## 관리 범위

- 행사의 관리권은 승인된 한 회차에만 적용한다. 주최 단체가 같아도 다른 회차를 자동으로 부여하지 않는다.
- 행사 관리자는 소개·장소명·주소·입장 안내·일시를 수정한다.
- 부스 운영자는 현재 공개된 본인 단독 부스의 소개·공식 링크·판매 안내와 기존 공개 상품의 이름·설명·가격·판매 상태를 수정한다.
- 공동 부스 전체, 행사/부스 식별 정보, 참가 근거, 새 상품, 이미지·배치도는 직접 편집하지 않는다. 기존 증빙 첨부 정정 요청과 관리자 검토를 이용한다.
- 기존 `CORRECTION_REQUEST` 권한은 자동 승격하지 않는다. 재심사를 통해 `CATALOG_EDIT`를 명시적으로 부여한다.
- 직접 수정은 기존 카탈로그 override에 저장해 재수집으로 덮어쓰지 않는다. 현재 공개 스냅샷에는 해당 수정 필드만 반영하고, 아직 검토하지 않은 수집 데이터 전체를 함께 공개하지 않는다.
- 상품 수정은 개별 상품 ID의 `owner_overrides_json`에 저장한다. 전체 판매 상품 배열을 대체하지 않아 다른 미공개 상품과 이후 수집 상품이 유지된다. 원본 식별자로 상품 ID를 연결한 뒤 표시용 수정값을 적용하므로 상품명을 바꿔도 이미지·상품 연결이 유지된다.
- 서버가 매 요청마다 권한·현재 참가업체 연결·버전을 검증한다. 권한 회수 또는 다른 계정의 수정은 거부한다.

## 행사 회차

`event_series`와 `event_series_member`로 개별 행사들을 묶는다. 관리자가 동일 이름 후보를 검색하고 공식 근거를 확인하여 연결·분리한다. 이름 유사성만으로 자동 병합하지 않는다. 공개 행사 화면에서 같은 시리즈의 다른 공개 회차로 이동할 수 있고, 각 회차의 댓글·일정·부스·주최자 권한은 분리해 유지한다. 이 기능은 자동 수집기의 시리즈 자동 승인 기능이 아니다.

## 주요 진입점

- 사용자 관리: `/support/management`
- 관리자: 인증 심사 메뉴, 행사 회차 연결 메뉴
- API: `/api/public/ownership`, `/api/me/ownership`, `/api/admin/ownership`
- 마이그레이션: `database/018_verified_organizers_series.sql`

## 검증 및 운영 반영

이 변경은 로컬 개발이며 운영 배포나 운영 DB 변경을 수행하지 않았다. 로컬 컴파일·단위 테스트와 계약 검사를 수행했으며, PostgreSQL이 없는 환경에서는 실제 DB 통합 테스트가 실행되지 않는다.

배포 전 별도 테스트 PostgreSQL에 기존 001~017과 018을 순서대로 적용한다. 기존 배포 절차에 따라 `boothhana.backend_role`을 설정하고, 실제 런타임 역할의 권한/RLS 및 SchemaContract를 확인한다. ReleaseIntegrationTests의 신청→승인→수정→재수집→회수, 회차 연결/분리 테스트를 실제 DB 환경에서 실행해야 한다.

사용자·타 계정·관리자 세 계정으로 신청/보완/승인/회수와 공동 부스 제한, 상품 수정, 공개 표시, 이전 회차 이동을 브라우저에서 검증한다. 백엔드는 새 테이블을 전제로 하므로 검증된 DB 마이그레이션을 먼저 적용하고 서버와 프론트를 배포한다. 데이터가 생긴 이후 테이블을 삭제하는 롤백은 하지 않는다.
