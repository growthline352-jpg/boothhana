## 적용
1. 기존 코드와 DB를 백업하고 새 브랜치·스테이징에서 비교합니다.
2. ZIP 안 `BoothHana2`의 **내용물**을 기존 저장소 루트에 반영합니다. `.git`, 실제 `.env`, Codex 인증·수집기 설정은 보존하되 Git/ZIP에 올리지 않습니다.
3. 기존 DB가 014까지 적용돼 있으면 `database/015_personal_library.sql`만 **검토 후 직접 적용**합니다. 이전 버전이면 미적용 SQL을 순서대로 실행합니다. 실제 JDBC 역할과 일반 API 역할을 먼저 구분하세요.
4. 프런트·백엔드를 함께 빌드·배포합니다. readiness가 새 `memory_item`, `memory_visit`을 검사하므로 SQL015를 먼저 적용합니다.
5. 아래 문서의 실제 로그인·권한·보관함·공유·모바일·SQL 검증을 수행합니다. 여기서 실제 Spring/React 전체 빌드·DB 연동은 성공하지 못했습니다.

## 들어가는 곳
- `/library`: 내 보관함. 전체·행사별·종류·방문 표시 필터, 개인 메모 검색.
- `/discover`: 행사 카드 저장 버튼.
- `/discover/:eventId`: 행사 저장, 전체/저장한/방문 표시한 부스, 지도 강조.
- 부스 드로어: 부스·개별 상품 저장, 공개 주소 공유·QR PNG.

이번 개인 보관함은 **수집 카탈로그(CATALOG)의 공개 행사/참가 부스/개별 상품** 대상입니다. 기존 `/events` 운영 행사·POS/예약 상품에는 별도의 저장 버튼을 추가하지 않았습니다. 숫자 ID만 같다고 두 데이터 체계를 합치지 않습니다.

- 기존 계정 메모나 방문 계획과 다른 기기 기록은 덮어쓰지 않고 기기에 남깁니다. 가져오기 중 계정이 바뀌면 거절합니다.
