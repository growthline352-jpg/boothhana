## 이번 구현

고객센터 `/support`, 문의·신고·업체 관리권 신청, 본인 내역·추가 내용, 관리자 신고 `/admin/reports`·문의 `/admin/inquiries`·관리권 `/admin/ownership`, 내부 메모·처리 이력, 공개 변경 확인 후 신고 완료, 검토본 공개·비공개 처리 연결, 비공개 첨부, 로그인 장애용 비회원 문의, 업체 관리 관계 승인·회수, 반려 사유·재신청·대기 신청 철회, 안전한 로그인 복귀를 포함합니다.

**팬과 업체는 같은 계정의 기능 권한입니다. 업체 관리권은 수집된 특정 업체의 `정정 요청` 관계이며 다른 업체·공동 부스·행사·예약·POS 편집권이 아닙니다.** 일반 회원 정지/전체 계정 관리, 팬↔업체 채팅, 이메일/SMS 답변 알림은 이번 범위가 아닙니다.

## 적용 순서

1. 기존 소스와 DB를 백업하고 배치·동시 관리자 변경을 중지합니다. 별도로 수정한 소스는 비교 후 합칩니다.
2. DB 검토 체크리스트를 먼저 확인합니다. 실제 001~011 적용 완료라면 **012만**; 신규라면 001~012를 순서대로 적용합니다. GitHub push나 `ddl-auto: validate`는 SQL을 실행하지 않습니다.
3. SQL 적용은 **사용자 환경의 DBA/운영 담당자**가 합니다. 이 작성 환경에서는 실행하지 않았습니다.
4. 압축 안 `BoothHana2/`의 내용물을 저장소 루트에 반영합니다. `.git`, 실제 `.env`, `collector/config.local.json`, Codex 인증은 보존하고 Git에는 넣지 않습니다.
5. 프런트·백엔드를 함께 빌드·배포합니다. `event_booth.version`이 없으면 JPA 검증, 새 테이블이 없으면 readiness와 지원 기능이 실패합니다.
6. 본문 신고·문의는 추가 외부 서비스 없이 사용합니다. **비회원 접수와 첨부는 기본 꺼짐**이며 아래 조건 확인 후 각각 활성화합니다.
7. 스테이징에서 역할·개인정보·정정·예약 회귀를 확인하고 기존 배치를 재개합니다. 일요일03시 전체수집/월~토04시 배치도보완 설정은 변경하지 않았습니다.

## 새 설정

| 서버 환경변수 | 기본 | 켜기 전 확인 |
|---|---|---|
| `SUPPORT_GUEST_ENABLED` | `false` | 로그인 장애 비회원 접수. 조회키·남용방어·보관정책·30일 만료 안내 |
| `SUPPORT_RATE_SECRET` | 빈값 | 비회원 기능에 필요한 **32자 이상 임의 서버 비밀값**. 운영 비밀 관리에 보관 |
| `SUPPORT_ATTACHMENTS_ENABLED` | `false` | 별도 private R2 버킷과 실제 소유권 차단·다운로드 검증 |
| `SUPPORT_PRIVATE_BUCKET` | 빈값 | 기존 `R2_BUCKET`과 **다른 비공개 버킷**. public URL/R2.dev/custom domain 금지 |

첨부는 JPG·PNG·WebP 파일당5MiB, 접수당5개이며 생성 후 추가합니다. 비회원 첨부·자동 이메일 발송은 없습니다. 비회원은 접수 ID+비밀 조회키로 30일 동안 직접 답변을 확인합니다. 만료는 DB 자동 삭제가 아닙니다.

## 코드 검증

```powershell
cd frontend
pnpm install --frozen-lockfile
pnpm lint
pnpm build
cd ../backend
.\gradlew.bat test
.\gradlew.bat bootJar
```

독립 검사: 저장소 루트 `python verification/v12/run_checks.py`. 테스트용 stub/모의 API 검사는 실제 서비스 빌드·DB·Kakao·R2·브라우저 통합을 대체하지 않습니다. 현재 전체 프로젝트 빌드는 의존성 설치/DNS 제한으로 완료하지 못했습니다.

`preview/v12/`는 가상 자료의 정적 시안이며 접수·답변·로그인이 동작하지 않습니다. 원본 행사 연구 결과를 실제 신고나 문의 seed로 넣지 않았습니다.
