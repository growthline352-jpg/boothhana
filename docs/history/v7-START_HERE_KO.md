# 부스하나 전체 소스 v7 · 적용 안내

**v6 전체 소스에 코드리뷰 6건을 반영한 전체본입니다.** 이전 패치나 생성기를 추가 실행하지 않습니다. GitHub 저장소·운영 DB·배포 서비스에는 직접 변경하지 않았습니다.

## 1. 코드 반영

기존 코드·DB를 백업하고 작업 브랜치에서 압축 안의 **BoothHana2 폴더 내부 내용**을 저장소 루트에 반영합니다. 폴더를 한 겹 더 만들지 마세요. 기존 `.git`, 실제 `.env`, `collector/config.local.json`, Codex 인증은 유지하며 Git에는 비밀정보를 올리지 않습니다. 원본 이후 별도 수정한 코드는 비교 후 합쳐야 합니다.

이번 ZIP은 collector 코드를 바꾸지 않습니다. 기존 **Codex CLI 검색 + Python 연결 + 일요일 03:00 Asia/Seoul 배치**를 유지합니다. 배포 중 API 혼용을 피하려면 진행 중 작업을 정상 종료한 뒤 일시 중지하고 검증 후 재개하세요. v5/v6 체크포인트를 이번 화면 수정 때문에 변환하거나 삭제할 필요는 없습니다. 더 오래된 v4 체크포인트는 기존 v5 정책대로 강제 재개하지 않습니다.

## 2. 필수 DB 적용 — SQL 008 추가

| 현재 DB | 추가 적용 |
|---|---|
| v5/v6의 SQL 007까지 적용 | **008_catalog_presentation.sql** |
| v4의 SQL 006까지 적용 | 007 → 008 |
| 원본 001·002까지 적용 | 003 → 004 → 005 → 006 → 007 → 008 |
| 신규 DB | 001부터 008까지 순서대로 |

새 SQL은 대표 배너 선택용 테이블을 추가하며 기존 업무 데이터·이미지·선택 상태를 삭제하지 않습니다. **새 백엔드 배포 전에 008을 적용**해야 합니다. GitHub 업로드만으로 SQL이 DB에 실행되지는 않습니다. `database/dev`는 운영 자동 실행 대상이 아닙니다.

## 3. 프런트·백엔드를 함께 빌드·배포

```powershell
cd frontend
pnpm install --frozen-lockfile
pnpm lint
pnpm build
cd ../backend
.\gradlew.bat test
.\gradlew.bat bootJar
```

이번 소스는 위 전체 빌드를 작성 환경에서 성공시키지 못했습니다. 새 백엔드는 대표 배너 선택을 반환하고, 새 프런트는 명시적 `banner:null`을 기본 표시로 해석합니다. 구버전 프런트를 혼용하면 대표 이미지 정책과 다르게 표시할 수 있으므로 한 릴리스로 맞춰 배포하세요.

## 4. 변경된 사용 흐름

- 행사 카드에서 선택 기간에 맞는 운영일·다음 운영일을 우선 표시합니다. 원문 일정과 휴무 구분은 보존합니다.
- 행사 상세의 참가 부스에서 ‘판매정보 보기’를 누르면 **우측 드로어**가 열립니다. 모바일은 전체 폭이며 닫기/Escape 뒤 원래 부스 카드로 초점이 돌아갑니다.
- 행사 배치도는 별도 섹션에 저장 이미지·확대 보기·출처를 표시합니다. 자동 좌표나 미확인 날짜·전시관을 생성하지 않습니다.
- 공개 부스 검색에 작가·별칭·상품명·품목·판매/상품 주제를 포함합니다.
- 관리자 `/admin/subculture` → 행사 → 배치도·이미지 탭의 **대표 배너**에서 이미지를 지정합니다.

### 대표 배너 정책

사용 승인·파일 저장이 완료된 해당 행사 배너만 선택 가능합니다. 대표 선택은 사용 승인과 별개이며 **이미 공개된 행사의 목록·상세에도 다음 조회부터 반영**됩니다. 공개되지 않은 행사가 이 선택만으로 공개되지는 않습니다.

선택하지 않은 기존 행사는 사용 가능한 최초 등록 배너를 사용하는 이전 동작을 유지합니다. 명시적으로 지정한 이미지의 사용 승인이 철회되거나 저장 상태가 실패로 바뀌면 다른 과거 포스터로 대체하지 않습니다. 목록은 기본 카드, 상세는 배너 없이 표시됩니다. 다른 이미지를 지정하거나 ‘자동 선택으로 되돌리기’로 변경할 수 있습니다.
