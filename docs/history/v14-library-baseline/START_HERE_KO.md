# v14 전체 소스 적용 안내

이 ZIP은 패치가 아닌 전체 소스입니다. **첨부 v13 검토본을 기준으로 실제 코드 수정과 패키징을 완료**했습니다. 예전에 생성되지 않은 v14 작업본/검사 결과를 재사용하지 않았습니다.

## 이번 변경

| 항목 | 구현 |
|---|---|
| 정정 완료 판정 | 행사/부스/상품/이미지/배치도의 업무 내용 투영을 분리. 가격 확인일·수집 시각·공개 시각만으로 정정 완료하지 않음 |
| 예약·POS 재전송 | 사용자+작업+요청 UUID에 유일성 부여, 입력 해시·결과 ID 보관. 동일 요청 재전송은 기존 결과, 같은 ID 다른 입력은409 |
| 사용자 복구 화면 | 처리 여부 불명확 시 입력 잠금·저장 결과 조회·동일 요청 재전송. 같은 사용자·부스별 UUID만 sessionStorage에 보관 |
| DB 연결 점유 | HTTP 지원 요청의 횟수 확인을 업무 트랜잭션 전에 수행. 첨부는 짧은 준비/확정 DB 단계와 네트워크 전송을 분리 |
| 검증·배포 | 실제 전체 SQL001~014·최소권한 역할·Spring HTTP·JPA/JDBC·거래 경쟁 테스트 및 CI 추가. 배포는 자동 수행하지 않음 |

## 적용 순서

1. 현재 Git 변경을 커밋/백업하고 DB 백업·복원을 검토합니다. 배치와 관리자 쓰기, 예약/POS 생성 요청이 실행 중이지 않은 유지보수 창을 준비합니다.
2. 압축 안 `BoothHana2`의 **내용물**을 저장소 루트에 반영합니다. 저장소 안에 `BoothHana2`를 한 겹 더 만들지 마세요. 별도 로컬 변경은 비교·병합하고 `.git`, 실제 `.env`, 수집기 설정/Codex 인증을 보존합니다.
3. v13에서 SQL013까지 적용했다면 **`database/014_trade_idempotency.sql`만** 추가 검토·적용합니다. v12의012까지라면013→014입니다. 현재 DB 상태가 불명확하면 [DB 검토표](docs/deployment/V14_DATABASE_REVIEW_KO.md)부터 확인합니다.
4. **프런트·백엔드를 함께 배포**합니다. 신규 거래 API는 requestId가 필수입니다. 구형 화면과 신형 서버를 섞지 마세요. 쓰기 요청을 잠시 제한한 상태에서 DB→백엔드→프런트 순으로 전환하고, 브라우저 새로고침 후 거래를 재개합니다.
5. 스테이징에서 실제 빌드/테스트와 권한·재전송·첨부·로그인·정정 공개를 확인합니다. 배포 CI의 required check/보호 브랜치는 저장소 관리자가 설정해야 합니다.
6. 검증 후 운영 쓰기와 기존 스케줄을 다시 엽니다. **수집기·주간/배치도 스케줄 자체는 변경하지 않았으므로 재등록할 필요는 없습니다.**

## 환경변수 추가 — 모두 기본값 있음

```text
DB_POOL_SIZE=10
DB_CONNECTION_TIMEOUT_MS=5000
SUPPORT_ATTACHMENT_CONCURRENCY=4
```

이는 안전성이 입증된 동시 처리량이나 부하 목표가 아닙니다. DB 전체 연결 한도·서버 인스턴스 수·요청 크기·업로드 읽기 제한시간과 함께 부하 검증해야 합니다. 기존 private R2/고객센터 활성 설정·수집 토큰은 그대로 사용합니다.
