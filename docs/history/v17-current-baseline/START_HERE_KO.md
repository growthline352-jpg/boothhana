## 적용 순서

1. 운영 코드·DB·설정을 백업하고 새 브랜치에서 비교합니다. ZIP 안 `BoothHana2` 내용물을 저장소 루트로 사용합니다. 실제 `.env`·인증·수집기 로컬 설정은 덮어쓰거나 Git에 올리지 않습니다.
2. **SQL015까지 적용된 환경에 추가 SQL은 없습니다.** 스키마·기기 보관함 키·기존 회원 기록·예약/POS 정책은 변경하지 않았습니다. SQL016을 실행하지 않습니다.
3. 프런트/백엔드를 함께 반영합니다. 프런트의 `package.json`에는 `build:hosting`과 패키지 매니저 버전 지정만 추가했고 의존성 버전 및 잠금 파일은 유지했습니다.
4. 검색·공유용 HTML에는 **실제 공개 주소 설정과 Node 함수 배포**가 필요합니다. `VITE_PUBLIC_SITE_URL`과 `PUBLIC_SITE_URL`은 동일한 HTTPS 원점, `VITE_API_BASE_URL` 및 `SEO_API_BASE_URL`은 실제 백엔드 원점으로 설정합니다. 예시 도메인을 운영에 쓰지 않습니다.
5. [배포 검증](docs/deployment/FULL_V17_KO.md)대로 의존성 설치·빌드·격리 PostgreSQL·브라우저·실연동 검증을 마칩니다. 미실행/실패 항목은 통과로 바꾸지 않습니다.

초안은 탭 메모리에만 있습니다. 인증 재확인·동일 계정의 화면 복귀에는 유지되지만 새로고침·탭 종료·명시적 로그아웃에는 폐기합니다. 업로드 도중의 파일·미리보기 URL은 보관하지 않습니다. 이번 초안 보호 범위는 위 세 편집 화면이며 모든 콘솔 폼을 일괄 전환한 것은 아닙니다.

**중요:** 일반 `pnpm run build`는 로컬 점검용 `dist/index.html`을 만듭니다. Vercel은 `pnpm run build:hosting`을 사용합니다. 이 명령은 템플릿을 공개 `dist` 밖의 `seo-template/index.html`로 옮겨 정적 파일이 서버 메타 생성을 우회하지 않게 합니다. `frontend`를 Vercel 프로젝트 루트로 사용합니다. 상세 설정은 배포 문서에 있습니다.
