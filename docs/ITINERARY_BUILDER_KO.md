# 목적별 하루 일정 만들기 — 로컬 구현

2026-10-04. 브랜치 `codex/itinerary-builder`. 운영 배포 전 로컬 검토본이다.

## 사용자 흐름

1. **행사 다녀오기 / 데이트 코스 만들기** 중 목적을 고른다.
2. 날짜, 동네, 하루 시작·종료 시간, 방문 분위기를 설정한다.
3. 행사 참여는 공개 행사와 도착 시간을 고른다. 행사 상세에서 들어오면 해당 행사·운영일을 먼저 선택한다.
4. 공개된 운영일·장소를 확인한 행사, 주변 음식점·카페로 코스를 만든다.
5. 마지막 화면에서 시간·체류 시간·순서·메모를 바꾸고, 장소를 교체하거나 직접 추가한다. 예약한 시간·장소를 고정할 수 있다.
6. 이 브라우저에 저장한 뒤 **내 일정 → 열고 수정하기**로 다시 편집한다. 시간 충돌이 없으면 캘린더 파일을 내보낸다.

### 목적별 규칙

| 목적 | 코스 구성 | 수정 동작 |
| --- | --- | --- |
| 행사 참여 | 중심 행사 시간·장소 고정 → 식사 → 카페. 굿즈 구매는 장시간 행사 체류를 늘림 | 고정 해제 전 시간·체류 시간·교체·삭제 차단. 추가 행사에는 같은 분야, 겹치는 취향 주제를 우선 적용 |
| 데이트: 전시·팝업 구경 | 당일·동네 행사 중 팝업·전시 우선 → 식사 → 카페 | 모든 항목 수정 가능 |
| 데이트: 먹고 쉬기 | 식사 → 운영 시간과 하루 범위에 맞는 행사 → 카페 | 행사가 없어도 직접 장소 추가 가능 |
| 데이트: 가볍게 둘러보기 | 행사 체류 시간을 짧게 시작 → 식사 → 카페 | 추천 체류 시간을 사용자가 조정 |

공연·팬 이벤트 선택은 목적 입력과 기본 코스 구성에 포함한다. 개별 공연 시간표를 해석해 프로그램을 자동 예약하거나 추천하지 않는다.

## 지도·편집

- PC: 왼쪽 방문 순서, 오른쪽 지도. 모바일: 일정 / 지도 전환.
- 번호 핀 선택과 일정 카드 선택을 연결한다. 가까운 장소의 핀이 겹치면 한 핀에 번호를 묶고, 펼친 목록에서 각각 선택한다.
- 지도 크기 변경·모바일 지도 전환 시 전체 위치를 다시 맞춘다. 지도 이동·확대 후에는 **전체 동선**으로 복귀한다.
- 점선은 **방문 순서**다. 도로 경로·대중교통 소요 시간으로 표시하지 않는다.
- 행사 좌표가 없으면 임의로 동네 중앙에 표시하지 않는다. 위치 미선택 개수를 보여주고, 이름·주소 검색 또는 지도 클릭으로 확인해 표시한다.
- 동네 중심 좌표는 주변 장소 검색의 기준으로만 사용한다. 중심 행사 좌표를 확인하면 행사 주변을 검색한다.
- 순서를 바꿔도 입력·고정한 시간은 자동으로 변경하지 않는다. 앞 일정과 겹침, 하루 시간 범위 초과, 행사 운영일·시간 불일치를 표시한다.
- 음식점·카페 사이 자동 배치는 30분의 계획 여유를 둔다. 실제 이동 시간 계산이 아니다.

### 2026-10-04 사용성·디자인 보완

- 목적 선택을 간결한 두 카드와 명확한 다음 행동으로 정리했다. 행사 참여는 날짜 → 중심 행사 → 도착 시간 순서로 선택한다.
- 하루 시작·마무리의 상세 설정은 접어서 기본값을 먼저 보여준다. 추천 중에는 설정을 잠가 뒤늦은 응답이 다른 날짜의 설정에 적용되는 것을 막는다.
- 일정 편집에 진입하면 화면 위와 제목으로 이동한다. 전체 장소 목록을 먼저 보여주고 **수정**을 누른 한 장소만 편집한다. 지도 핀 선택은 수정창을 자동으로 펼치지 않는다.
- 시간·장소 고정 시 제한된 항목과 **고정 해제** 동작을 함께 표시한다. 기존의 임의 체류 시간도 선택 옵션에 유지한다.
- 시간 충돌은 해당 카드와 하단 요약에 표시한다. 요약의 **수정**을 누르면 정확한 장소의 시간 입력으로 이동한다. 이름이 같은 장소도 항목 ID로 구분한다.
- 메모는 수정창을 접어도 카드에서 두 줄까지 미리 볼 수 있다.
- 저장 상태와 저장 버튼은 하단에 고정한다. 모바일의 공통 하단 메뉴와 겹치지 않게 배치한다. PC 편집 중 개선 의견은 공통 서비스 메뉴·푸터에서 보낸다. 저장 후 수정하지 않았다면 저장 완료를 표시하고 반복 저장을 막는다.
- 모바일의 일정 / 지도 전환에 편집 내용과 선택 장소를 유지한다. 주요 수정·추가·순서 이동 버튼은 최소 44px 높이를 확보한다.
- 장소 추가·교체 창은 제목으로 초기 초점을 옮기고 Escape로 닫으면 실행 버튼으로 초점을 복원한다. 교체는 음식점·카페 또는 직접 입력 유형에 맞는 창으로 시작한다.

## 데이터와 저장

### 행사

기존 공개 행사 API의 `publicCatalogApi.calendar`를 선택 날짜와 네 분야로 조회한다. 운영 장소·운영일을 분리해 사용하며 취소·연기·일정 변경 상태는 제외한다. 조회 실패를 행사 없음으로 처리하지 않고 재시도 동작을 제공한다. 행사 상세에서 시작할 때 주소가 비어 있으면 같은 행사 ID의 당일 공개 목록 정보를 보완한다.

팝업 좌표는 기존 `/api/public/catalog/popups` 응답의 행사 ID와 주소가 모두 일치할 때만 사용한다. 현재 운영 응답은 404이므로 좌표 없이 동작하며 사용자 위치 선택을 제공한다.

### 장소와 지도

로컬에서 OpenStreetMap / Photon 실제 검색 결과를 사용했다. 음식점·카페는 검색 중심 반경 1.2km 이내 장소를 직선거리로 정렬한다. 평점·인기·현재 영업·예약 가능 여부를 확인한 결과는 아니다. 국내 장소 누락이 있고 주소가 도로명 일부로 반환될 수 있다.

자동완성·반복 폴링 없이 명시적인 검색·추천 버튼에서만 요청한다. 같은 검색은 1시간 캐시하고 진행 중 요청을 공유한다. 실패 시 행사 일정과 직접 입력을 계속 사용할 수 있다.

| 환경변수 | 응답 계약 |
| --- | --- |
| `VITE_ITINERARY_SEARCH_URL` | Photon 호환 GeoJSON 이름·주소 검색 |
| `VITE_ITINERARY_NEARBY_URL` | Photon 호환 GeoJSON 역검색, `osm_tag=amenity:restaurant` 및 `amenity:cafe` |
| `VITE_ITINERARY_TILE_URL` | Leaflet `{z}/{x}/{y}` 타일 URL |

장소 검색 데모 기본값은 `localhost` / `127.0.0.1`에만 적용한다. 운영에서는 검색 제공자·한국 장소 커버리지·요금·허용량을 정하고 위 계약의 서버 연동을 마련해야 한다. API 비밀키를 Vite 환경변수로 노출하지 않는다. Kakao Local 등의 응답을 사용할 경우 서버에서 이 계약으로 변환하거나 별도 어댑터를 구현한다.

지도는 OSM 공개 타일과 출처 표기를 사용한다. 오프라인 타일 저장·대량 사전 다운로드·위치 권한 요청은 구현하지 않았다.

자료: [Leaflet](https://leafletjs.com/reference.html), [Photon](https://github.com/komoot/photon), [Photon API](https://github.com/komoot/photon/blob/master/docs/api-v1.md), [OSM 타일 정책](https://operations.osmfoundation.org/policies/tiles/).

### 개인 일정

- 계정·게스트별 `localStorage` 이름 공간에 최대 20개 저장한다. 로그인 상태 확인 중에는 이전 사용자 일정을 노출하지 않는다.
- 작성 중 일정은 `sessionStorage`에 보관한다. 계정 변경·비동기 완료 순서가 바뀌어도 이전 작업이 새 사용자 일정에 덮어쓰지 않도록 작업 토큰을 검사한다.
- 저장 성공은 실제 저장 후 표시한다. 저장 실패 시 오류를 알린다. 깨진 데이터·잘못된 좌표·중복 항목 ID·잘못된 운영일 정보는 복구 목록에서 제외한다.
- **서버 저장·다른 기기 동기화·공유·변경 알림은 아직 구현하지 않았다.** 기기나 브라우저가 바뀌거나 사이트 데이터가 삭제되면 이 일정은 복구되지 않는다.
- ICS는 한국시간 `Asia/Seoul`을 사용한다. 제목·주소를 이스케이프하고 한글 줄 길이를 제한한다. 개인 메모는 내보내지 않는다. 내려받은 캘린더와 사이트 일정을 자동 동기화하지 않는다.
- 저장 시점의 행사 정보를 보관한다. 저장한 일정을 다시 열 때 공식 변경 사항을 자동 반영하거나 알리지 않는다.

## 진입점과 로컬 실행

- `/itinerary`, 공통 메뉴 **내 일정**
- 메인 **일정 만들기**
- 행사 상세 / 방문 준비 **이 행사로 일정 만들기**
- 일정 페이지는 별도 지연 로딩 청크. 개인 일정은 `noindex,follow`.

```powershell
# frontend에서 각 서버를 별도 터미널로 실행
pnpm run build:local-preview
node node_modules/vite/bin/vite.js preview --host 127.0.0.1 --port 4185 --strictPort
node scripts/preview-public.mjs
```

로컬 확인 주소: `http://127.0.0.1:4186/itinerary`.

프록시는 운영 공개 GET/HEAD 응답만 읽는다. 운영 API 변경 요청은 차단하고 `/api/me`는 게스트 상태를 반환한다. 이번 작업에서 운영 데이터나 배포를 변경하지 않았다.

## 운영 연결 시 남은 일

1. 국내 장소 데이터 제공자 및 서버 어댑터, 행사 좌표 수집·검증.
2. 계정 소유권 검증을 포함한 서버 일정 저장·수정 API와 기기 간 동기화.
3. 실제 도보·교통 경로, 영업시간·예약 확인. 확인할 수 없는 항목은 추정하지 않기.
4. 행사 공개 버전 변화 감지와 저장 일정 변경 알림.
5. 이용 동의를 받은 공유·권한·삭제 흐름 및 지속 운영 데이터 품질 점검.
