# 행사 유형·취향 주제 운영 기준

분야는 서브컬처·박람회·축제 중 하나다. 행사 유형은 개최 방식과 목적을, 취향 주제는 관심 내용을 나타낸다. 작품·캐릭터명은 취향 주제와 함께 보존하는 원문 태그다. 행사 운영 구조인 `eventFormat`(MULTI_BOOTH/SINGLE_HOST/UNKNOWN)은 별개다.

## 공통 분류표

`taxonomy/catalog.json`이 기준이다. 수정 후 `python scripts/sync-taxonomy.py`로 서버 Java, 수집기 JSON·스키마·프롬프트, 웹/SEO 자료를 생성한다. CI는 `--check`로 불일치를 차단한다. 배포별 사본을 포함하므로 Docker 빌드나 Vercel 실행 시 저장소 밖 파일을 읽지 않는다.

- 서브컬처: 팬카페·카페 이벤트, 팝업스토어, 카드·수집 행사, 팬 컨벤션을 추가했다. 취향 주제에는 보드게임·인형·카드·코스프레·퍼리를 추가했다.
- 박람회: 기존의 넓은 주제를 유지하며 반려동물, 육아·어린이, 식품·음료, 커피·차, 주거·인테리어, 교육·유학, 금융·재테크, 뷰티·건강, IT·기술, 스포츠·아웃도어, 미술·공예, 콘텐츠·지식재산을 추가했다.
- 축제: 단독 공연과 음악 페스티벌 유형을 추가했다. J-POP, 인디 음악, 꽃·정원, 걷기·러닝, 가족·어린이, 역사·전통 주제를 추가했다.

기존 관심 코드와 유형을 삭제하거나 의미를 바꾸지 않는다. 기존 `LIVE`와 `MUSIC` 선택은 새 공연 유형도 포함한다. 한 분야에서 선택한 유형/주제는 OR 조건이며, 분야만 고르면 그 분야 전체를 보여준다. 취향을 모두 충족해야 하는 AND 필터와 다르다.

## 자료 검토

- 생일 기념으로 확인된 카페만 BIRTHDAY_CAFE로 둔다. 일반 팬카페는 FAN_CAFE다.
- 게임 체험·공식 굿즈·무대가 중심인 게임 축제를 동인 판매전으로 포괄하지 않는다.
- 일러스트 전문 전시는 ILLUSTRATION이다. 굿즈 판매가 있다는 이유만으로 STATIONERY_GOODS로 분류하지 않는다.
- 일반 음악 공연은 축제의 CONCERT/MUSIC_FESTIVAL로 구분한다. 게임 OST·애니송·버추얼 중심임이 확인되면 SUBCULTURE_MUSIC다. 일본 아티스트 또는 애니 타이업 경력만으로 분야를 옮기지 않는다.
- 일반 브랜드 팝업과 팬덤 IP 팝업, 밀리터리·하비의 서비스 범위는 공식 전시 구성을 검토해 결정한다.
- 제목 키워드로 자동 분류하지 않는다. 취향 연결은 분야별 표준 코드와 검토된 태그의 정확한 별칭 일치로 처리한다. `VIRTUALS` 같은 이름을 VTUBER로 추정하지 않는다.
- `subjects`에는 표준 주제 코드와 작품·캐릭터 원문 태그를 함께 저장한다. 관리자 체크박스로 표준화할 때 작품명을 삭제하지 않는다. 작품으로 자동 연결된 항목은 원문 태그를 수정해 변경한다.

## 누락 확인

수집기 보완 큐는 MISSING_INTEREST_SUBJECTS, NO_INTEREST_TOPIC, TYPE_ONLY_SUBJECTS를 확인한다. 관리자 목록·편집 화면에도 같은 조건을 표시한다. 이는 검토 신호이며 행사 존재 여부의 부정이나 자동 비공개 사유가 아니다. 공식 자료가 부족하면 근거와 미확인 사유를 검토 메모에 남긴다.

박람회 등 기존 유형으로 기본 주제가 연결되더라도 빈 태그는 별도로 표시한다. 공란이 아니어도 더 세부적인 주제가 부족할 수 있으므로 담당자가 전시 품목을 확인해야 한다.

## 반영 순서

1. 코드·생성 사본·SQL·추천 조회 테스트를 통과시킨다.
2. 운영 백업 후 `023_event_taxonomy.sql`로 허용 유형을 확장한다. 행사 데이터를 변경하는 SQL이 아니다.
3. 새 유형을 해석할 수 있는 웹/SEO와 API·수집기를 배포한다.
4. 근거가 확인된 행사만 revision과 기존 공개본을 대조해 수정·재공개한다. 출처·원본 수집값·ID·저장·참가 부스는 보존하고 관련 없는 변경은 함께 공개하지 않는다.
5. 분야별 목록·관심 추천·달력 표시·canonical/사이트맵과 전후 건수를 확인한다.

타입 허용값을 이전으로 되돌리기 전에는 새 유형을 쓰는 기록이 없는지 확인해야 한다. 코드 배포와 개별 데이터 보정의 결과는 별도로 기록한다.
