3. 백엔드·프런트·수집기 함께 배포합니다. 환경변수/토큰/Codex 인증/호스트 허용 설정은 기존 것을 유지합니다. 비밀값을 Git에 넣지 않습니다.
4. 의존성이 설치되는 환경에서 `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm build`, `gradlew test`, `gradlew bootJar`를 실행하세요.
5. `docs/ux/USER_FLOW_V9_KO.md`의 실서비스 수락 기준을 스테이징에서 확인한 뒤 운영합니다. SQL/JDBC/RLS, 카카오/세션/CSRF, R2, 이미지 인식, 예약/POS 회귀도 별도로 확인하세요.
6. 기존 일요일03시KST 전체+배치도, 월~토04시KST 임박 배치도 보완 실행을 재개합니다. 스케줄 등록 파일은 이번에 변경하지 않았습니다.

## 개최 상태 JSON

```json
{
  "operationStatus": {
    "state": "UNKNOWN",
    "note": null,
    "sourceUrl": null,
    "checkedOn": null
  }
}
```

허용 상태: UNKNOWN / SCHEDULED / CANCELED / POSTPONED / RESCHEDULED.
UNKNOWN 이외에는 원문 URL·YYYY-MM-DD 확인일·안내 문구가 필수입니다. 단어 ‘취소’가 경고에 있다고 확정 취소로 바꾸지는 않습니다. 기존 행사 날짜·입장 조건은 별도 필드이며, 연기 후 새 날짜가 미정이면 날짜를 지어내지 않습니다. 기존 공개 스냅샷은 다음 관리자 승인까지 자동 덮어쓰지 않습니다.

구버전 1~8의 결과에는 필드가 없어도 기본 UNKNOWN으로 읽습니다. 저장용 검증 스키마는 호환성을 유지하고, Codex에 전달하는 live 출력 스키마에서만 해당 필드를 반드시 보고하게 합니다. 상태 변경만으로 행사 identity가 바뀌지 않습니다. 실제 CLI/모델의 출력 계약은 스테이징에서 다시 확인해야 합니다.

## 관리자

일반 입력폼 변경사항은 검토 상태만 저장한 경우와 구분됩니다. 의도한 수동값만 고정하고 ‘최신 수집값 사용’으로 해제할 수 있습니다. 기본 화면에서 해시/SQL/JSON을 입력하게 하지 않습니다. 미저장 경고는 데이터 복구용 영구 초안을 대신하지 않습니다. 브라우저 종료 확인창의 실제 문구는 브라우저가 결정합니다.

## 미리보기·검증

`preview/v9/`는 가상 행사·부스·상품으로 실제 JSX/CSS를 테스트 하네스에서 정적으로 렌더한 화면입니다. 미리보기 연결 JS는 데모용이고, React 상태/라우터/API의 통합 실행이 아닙니다. 행사 DB에 import하지 마세요. 모든 실검증·미검증 항목은 TEST_RESULTS_KO.md를 확인하세요.

## 되돌리기

동일 기준의 프런트·백엔드·수집기를 함께 이전 코드로 되돌립니다. 별도 DB 마이그레이션은 없지만 JSON에 새 필드가 있을 수 있으므로, 구버전 역직렬화 호환성을 스테이징에서 먼저 확인하세요. 운영 데이터의 상태 필드를 임의 일괄 삭제하지 않습니다.
