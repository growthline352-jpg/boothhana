# 부스하나 v19 적용 및 수락검사

2026-09-18 · 코드 오류 수정본 · **운영 배포 승인본이 아닙니다.**

## 서버 DB와 브라우저 저장소는 별개입니다

- 서버: v18과 동일한 SQL001~016을 사용합니다. **추가 SQL017은 없습니다.** v17 이하에서 올라오는 경우에만 먼저 기존 SQL016 적용 필요 여부를 확인합니다.
- 브라우저: 임시 오프라인 DB 이름은 `boothhana.offline.v18`을 유지하고 IndexedDB 버전을 2로 올렸습니다. v19 사본의 형식 번호는 19입니다. 이전 writer가 새 형식을 덮지 못하도록 업그레이드하며 `packs`/`meta`의 임시 사본은 비웁니다.
- 이 작업은 회원/비회원 보관함의 저장 기록·개인 메모, 서버 DB, 예약·재고 데이터를 삭제하는 작업이 아닙니다. 사용자가 내려받았던 v18 오프라인 행사 사본만 다시 저장해야 합니다.

## 적용 순서

1. 원본 소스·배포 설정·DB를 백업합니다. 신규 비밀키나 실제 config.local.json을 ZIP 또는 Git에 넣지 않습니다.
2. 스테이징에 v19를 반영하고 정식 의존성 설치, 프런트 lint/build 및 백엔드 test/bootJar, 격리 SQL 통합 검사를 수행합니다. 이번 로컬 대역 검사만으로 생략하지 않습니다.
3. 기존 `/offline/` 전체 정적 파일과 v19 Service Worker가 함께 배포되어야 합니다. Vercel 프로젝트 루트 `frontend`, 기존 `build:hosting` 설정과 서버 메타 라우팅은 유지합니다. 정적 파일이 HTML catchall로 변하지 않는지 MIME/내용을 확인합니다.
4. **행사 전, 인터넷이 연결된 때** 기존 오프라인 탭을 모두 닫고 일반 서비스/오프라인 화면을 새로 엽니다. 새 worker 설치·활성화와 저장소 전환을 확인합니다. 차단 안내가 나오면 다른 탭을 닫고 다시 시도합니다. 온라인 전환 전에 기기가 새 코드나 자료를 받았다고 가정하지 않습니다.
5. 행사 상세에서 동의 후 필요한 행사 자료를 다시 내려받습니다. 배치도·이미지는 기존처럼 별도의 `offlineAllowed` 권한과 CORS가 필요합니다. 기존 자료가 사라진 상태를 서비스 오류나 회원 보관함 삭제로 오인하지 않도록 안내합니다.
6. 저장 완료/누락 항목을 확인하고 `/offline/index.html`을 다시 열어봅니다. 인터넷을 끄고 브라우저 재실행·새 탭·배치도/선택 목록 열람을 실제 iPhone Safari 및 Android Chrome에서 확인합니다.
7. 같은 계정/다른 계정/로그아웃, 행사별 삭제/전체 삭제/동시 다운로드, 온라인 권한 철회가 열린 탭에 반영되는지 확인합니다. 실제 공개 API와 이미지 저장소까지 검증한 뒤 배포 여부를 결정합니다.

모든 사용자 기기를 서버에서 즉시 새 버전으로 바꿀 수는 없습니다. 특히 이미 완전히 오프라인인 기기는 이전 코드를 계속 사용할 수 있습니다. 업데이트·재다운로드 안내는 현장 진입 전에 해야 합니다.

## 이번 수정을 위한 필수 수락검사

| 흐름 | 기대 결과 |
|---|---|
| 내려받는 중 해당 행사 삭제 / 아직 없는 첫 사본 삭제 | 늦은 요청이 자료를 다시 생성하지 않음 |
| 같은 행사를 두 탭에서 내려받기 | 이미 커밋된 최신 사본을 늦은 이전 요청이 덮지 않음 |
| A 계정 다운로드/재확인 중 B 계정 확인 | A의 늦은 응답이 B의 자료를 생성·삭제하지 않음 |
| 공개 판매 요약 숨김, 상품 제외, 출처표시 변경 | 온라인 재확인 후 현재 공개 문구/허용 이미지 반영, 원래 만료일 유지 |
| 다른 탭에서 이미지 철회·자료 삭제 | 열린 리더에서도 오래된 자료·Object URL을 정리. 네트워크 재조회 순환 없음 |
| 이미지가 있는 목록에서 반복 검색 | 동일 이미지 URL 재사용, 화면 교체·종료 시 해제 |
| 상세를 열어둔 채 만료 / 백그라운드 후 복귀 | 유효하지 않은 사본을 더 이상 표시하지 않음 |
| 배치도 URL 허용, 실제 다운로드 실패 | 저장된 배치도 없음/부분 저장 안내. 완전 저장으로 표시하지 않음 |
| 선택 목록이 로딩/오류 상태 | 빈 개인 선택 목록을 조용히 저장하지 않음. 표시 포함을 해제하면 공개 정보만 저장 가능 |
| 오프라인 저장 중 다른 행사로 이동 | 이전 화면의 작업 결과를 새 행사의 완료 상태로 표시하지 않음 |
| 6번째 행사, 총량 초과, JSON 대신 HTML/잘못된 MIME | 원인에 맞게 거절하고 기존 유효 사본 유지 |
| 서울/경기 세 분야, 인천과 잘못된 지역코드 | 기존 범위/공개 조회 분리 유지 |

## 남은 한계

전용 오프라인 리더는 명시적으로 받은 공개자료의 읽기 전용 사본입니다. 기기 사용자가 개인 관심 선택표시를 볼 수 있으므로 공용 기기에서는 삭제해야 합니다. 오프라인에서는 서버의 계정 변경·권리 철회·실시간 재고를 즉시 알 수 없습니다. 저장공간 회수, 사용자 브라우저 데이터 삭제, 모바일 백그라운드 타이머 제한은 별도 실제 기기 검증 대상입니다.

기본 한도는 7일·최대5행사·총60MiB이며 최초 저장 기한을 재확인만으로 늘리지 않습니다. 신규 이미지 다운로드, 구매/수령 완료 상태 편집, 서버 동기화, 실제 판매자 결제/수령 기록은 이번 수정에 추가하지 않았습니다.

롤백 시 서버 SQL은 변경되지 않았지만 이전 v18 클라이언트가 브라우저 저장소 버전2를 그대로 열 수는 없습니다. 해당 기기의 임시 오프라인 저장소만 초기화 후 재다운로드해야 하며, 회원 보관함이나 서버 DB를 초기화해서는 안 됩니다. 따라서 먼저 스테이징에서 버전 전환을 검증합니다.
