# v18 적용·수락 절차

## 적용 순서

1. 운영 코드·DB·설정을 백업합니다. 실제 `.env`, config.local.json, 토큰, 인증 파일은 ZIP과 Git에 넣지 않습니다. 원본 v17은 유지합니다.
2. 진행 중 수집을 확인하고 중복 실행 없이 버전을 교체합니다. SQL001~015가 이미 있는 DB에 **016_catalog_scope_offline.sql**을 먼저 스테이징에서 검증·적용합니다. 신규 DB는 001~016 순서입니다. 운영 DB에 테스트 스크립트를 실행하지 않습니다.
3. 백엔드를 교체하여 readiness, 세 분야 분리, 서울·경기 필터, 인천 거절, 공개 상품/이미지 권한을 점검합니다. 내부 subculture URL·테이블명은 호환상 유지됩니다.
4. 프런트의 실제 환경변수 `VITE_API_BASE_URL`, `SEO_API_BASE_URL`, `VITE_PUBLIC_SITE_URL`, `PUBLIC_SITE_URL`을 설정합니다. 기존 v17 서버 메타 설정을 유지합니다. Vercel 프로젝트 루트는 frontend, 명령은 `pnpm run build:hosting`입니다.
5. **배포에 public/offline의 전체 파일이 포함**되어야 합니다. `/offline/index.html`, app.mjs/store.mjs/policy.mjs/style.css/manifest.webmanifest/icon.svg/sw.js가 HTML catchall로 바뀌지 않는지 원문 응답과 MIME을 확인합니다. 작업자는 소스를 file://로 더블클릭하지 않고 HTTPS(테스트는 localhost)로 실행합니다.
6. 이미지를 보여주는 공개 사용 승인과 별도로 임시 오프라인 저장 허용 근거를 확인하고 관리자 이미지 카드 체크를 저장합니다. 배치도 변환/공개 승인도 별도입니다. 이후 일반 승인 화면이 이를 false로 되돌린 경우 다시 검토합니다. 모든 이미지를 일괄 허용하지 않습니다.
7. R2/이미지 CDN이 프런트 출처의 익명 GET을 CORS로 허용하는지 확인합니다. 불투명 no-cors 응답을 강제로 저장하지 않습니다. CDN 리다이렉트도 내려받기 실패로 표시됩니다.
8. 수집기 지역/분야 scope를 확인합니다. 일정 템플릿은 기존 일요일03시 및 임박 배치도 월~토04시 유지입니다. 새 weekly-v18 체크포인트를 쓰며 이전 서울 전용 성공 결과를 새 범위의 성공으로 재사용하지 않습니다. 자동예약 등록/외부CLI실행은 배포자가 검증 후 수행합니다.

## 검증 명령

```sh
python verification/v18/run_checks.py
python -m unittest discover -s collector/tests -v
# 테스트용 독립 로컬 PostgreSQL만. 실제 변수/비밀번호는 파일·로그에 저장하지 않습니다.
python verification/v18/prepare_test_db.py --confirm-isolated-empty-test-cluster
python verification/v18/release_gate.py
# 독립 오프라인 리더의 실제 Chromium 검사. API·이미지는 로컬 가상 응답입니다.
python verification/v18/browser_offline.py
```

DB 준비 도구는 localhost/127.0.0.1의 비어 있는 boothhana_release_test만 허용합니다. 환경변수/테스트 역할/클러스터 조건은 도구가 검사하며 실패 시 강제로 운영 DB를 넣지 않습니다. 실제 빌드 완료가 아니면 React 편집 폼 E2E도 통과한 것으로 표시하지 않습니다.

## 사용자 흐름

인터넷 연결 상태에서 행사 상세 → 기기 저장 동의 → [이 행사 오프라인 저장] → 결과의 누락/배치도 상태 확인 → [저장 자료 열기]. 자주 사용할 때 **오프라인 자료 주소**를 홈 화면에 추가합니다. 일반 홈/관리자/회원 보관함 전체의 오프라인 실행을 약속하지 않습니다.

저장 후 비행기 모드 → 오프라인 주소 새 탭/다시 열기 → 행사명·부스번호 검색 → 선택 목록 → 배치도 확대/이미지 열람 → 삭제를 확인하세요. 배치도 파일이 없는 행사는 문자 부스번호만 표시됩니다. 오프라인은 열람 전용이며 구매·수령 완료 처리나 서버 동기화는 아닙니다.

## 출시 전 필수 수락검사

- 세 분야 각각 서울/경기 사례, 이름에 서울이 포함된 경기 행사, 인천 주소, 경기 주소/서울코드 불일치. 분류/지역 교차 누출 없음.
- 실제 프로그램·참가명단 없는 축제에 가짜 부스를 만들지 않음. 상시 상품을 이번 행사 판매로 오인시키지 않음.
- 느린 연결에서 즉시 로컬 내용 표시, 연결 끊김 후 새 탭/재방문/홈 화면 실행. 실제 Android Chrome 및 iPhone Safari 모두.
- 이미지 권한 기본 미허용, 명시적 허용, 철회, 배치도 READY→ROSTER_CHANGED, 공개 행사 삭제, 연결불가. 누락 안내 확인.
- 계정 A에서 저장 → 인증 확인중/오류 → 같은 계정 복귀 → B/로그아웃 확인. 늦은 A 다운로드/재확인이 B 자료를 덮거나 지우지 않음.
- 저장 취소, 부분 실패, 저장공간 부족, 6번째 행사, TTL 만료, 브라우저 데이터 삭제. 실패를 완전 저장으로 표시하지 않음.
- 공용 기기 경고, 관심 선택표시 포함/미포함, Cookie·계정 API 미캐시, 캐시에 관리자 HTML·주문정보가 없음.

정상 출시까지 실제 행사 최소 한 건의 수집→검토→공개→다운로드→현장 오프라인 열람을 완주해야 합니다. 측정하지 않은 성능, 상품 커버리지, iOS 호환성을 통과로 표기하지 않습니다.
