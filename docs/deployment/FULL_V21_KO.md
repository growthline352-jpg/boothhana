# 부스하나 v21 적용 및 수락검사

2026-09-18 · v20 코드 수정본 · **운영 배포 승인본 아님**

## 호환성과 영향

**추가 SQL 없음: SQL001~016 유지.** 이번에는 프런트뿐 아니라 백엔드 LibraryService도 변경됐으므로 두 영역을 같은 버전으로 적용하세요. 실제 의존성 버전과 잠금 파일, 수집기, 예약/POS 재고 정책은 변경하지 않았습니다.

임시 오프라인 저장소 `boothhana.offline.v18`, IndexedDB버전2, 사본형식19, shell캐시 `boothhana-offline-shell-v20-1`을 그대로 사용합니다. `/offline/` 제품 코드는 바뀌지 않았으므로 v19/v20의 유효한 행사 사본을 이번 버전 때문에 지우거나 재다운로드를 강제하지 않습니다. 만료·계정 변경·권리 철회·사용자 삭제의 기존 동작은 유지됩니다. v18 이하에서 직접 갱신할 때의 이전 형식 전환은 별도입니다.

회원/비회원 보관함 메모·방문계획·서버 원본 saved_json을 일괄 삭제하지 않습니다. 숨겨진 판매 요약은 해당 응답과 검색에서만 제거하며, 원본 저장 이력은 DB에 보존합니다. 요청 복구 sessionStorage 키와 UUID형식도 유지합니다. 작업 중인 ID를 지우거나 무조건 새 요청을 보내지 말고 기존 접수/거래 결과를 확인하세요.

## 적용 순서

1. 원본 소스·DB·배포 설정을 백업합니다. 키·`.env`·config.local.json은 ZIP/Git에 추가하지 않습니다.
2. 스테이징에서 정식 의존성을 설치하고 프런트 lint/build, 백엔드 test/bootJar를 실행합니다. 이번 독립 검사만으로 생략하지 않습니다.
3. 전용 로컬 테스트 DB에 SQL001~016을 준비하고 `verification/v21/release_gate.py`를 실행합니다. 새 `v21HiddenSalesRedactsSavedBoothHistoryAndSearch`가 누락·실패·skip되지 않았는지 확인합니다.
4. 프런트와 백엔드를 함께 갱신합니다. 기존 Vercel 프로젝트 루트 `frontend`, `build:hosting`, API·메타 환경변수·정적 오프라인 파일 라우팅은 유지합니다. 수집기 교체/실행이나 스케줄 재등록을 이번 수정만으로 할 필요는 없습니다.
5. 온라인 상태에서 새 프런트를 받은 뒤 아래 수락검사를 수행합니다. 기존 탭의 메모리 캐시는 배포만으로 즉시 교체되지 않으므로 화면 재진입/새로고침 후 검사합니다. 이전 오프라인 사본까지 서버 수정만으로 즉시 철회된다고 안내하지 않습니다.
6. 결과를 확인한 뒤 운영 적용 여부를 판단합니다. 이 ZIP 자체는 운영 승인 표시가 아닙니다.

## 필수 수락검사

| 흐름 | 기대 결과 |
|---|---|
| `[A]` 조회 중 `[A,B]` 조회 | A의 진행 중 결과 공유, 신규 B만 추가 조회; 반환 순서·중복 유지 |
| 겹친 공개 조회가 대기 중 화면/계정 캐시 clear | 이전 결과 거절, 이전 cleanup이 새 요청을 제거하지 않음 |
| 200개씩3묶음 동시 조회 | 캐시400개 제한을 유지하면서 이미 성공한 호출이 캐시 정리 때문에 실패하지 않음 |
| 캐시 적중 항목과 느린 신규 조회를 함께 호출 | 최종 반환 시 만료 항목을 최신처럼 내보내지 않고 재조회 안내 |
| 문의·예약/POS 기존 폼 실패 대기 중 새 폼에서 복구 완료→새 요청 | 오래된 failed/missing/completed가 새 UUID를 덮거나 지우지 않음 |
| 같은 빈 슬롯을 본 두 새 폼이 요청 준비 | 먼저 기록된 UUID 유지; 두 번째 폼 전송 payload/ID 제거 및 결과 확인 안내 |
| 저장소 접근 차단 | 기존 경고와 메모리 전용 동작 유지. 읽지 못한 키를 나중에 덮지 않음 |
| 부스 저장 후 판매정보만 EXCLUDED | 부스 공개 유지, 과거 판매 요약/태그 응답·검색 제외, 메모/방문일/원본 저장 이력 유지 |
| 판매정보 계속 공개 / 부스 전체 철회 | 기존 공개 기록 유지 / 기존 전체 비공개 처리 유지 |
| v19·v20에서 받은 오프라인 자료로 업데이트 | 유효한 사본 유지; 기존 만료·공개 재확인 동작 유지 |
| 서울·경기 세 분야 / 인천 제외 | 기존 지역·분류 동작 유지 |

실제 휴대폰, 네트워크 지연, 다중 탭, 서버 JOIN/검색, R2 이미지 CORS·권한 및 실제 계정을 이용한 종합 검증은 별도로 필요합니다. 클라이언트의 요청 보호는 서버에서 이미 처리된 거래/문의의 롤백이 아닙니다.
