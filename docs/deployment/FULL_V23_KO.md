# 부스하나 v23 적용·수락 절차

## 적용 범위

v22 대비 제품 변경은 프런트11개 파일입니다. **새 SQL 없음**; SQL001~016/백엔드/수집기/의존성과 잠금 파일 동일. v22에서 올라올 때 백엔드·수집기 교체나 SQL추가가 필요하지 않습니다. v20이하에서 올라오면 v21 서버 수정까지 함께 포함해야 합니다.

기기 보관함·회원 메모·방문계획을 초기화하지 않습니다. `/offline/` 실행 파일과 IDB2/사본형식19/`boothhana-offline-shell-v20-1`을 유지합니다. 유효한 v19이후 오프라인 자료를 이번 수정 때문에 다시 내려받게 하지 않습니다. 정상적인 만료·계정변경·권리철회·삭제는 유지됩니다.

1. 원본 소스·배포 설정을 백업하고 TEST_RESULTS_KO.md의 미완료 검사를 확인합니다.
2. 정식 의존성으로 frozen 설치, 프런트 lint/build, 백엔드 test/bootJar와 격리 DB 게이트를 수행합니다. 사용성을 확인하려고 운영DB를 테스트용으로 넣지 않습니다.
3. 새 프런트를 정상 빌드해 배포합니다. `usability.css`는 main.tsx에서 최종 스타일로 import되므로 별도 수동 스타일 경로가 필요하지 않습니다. Vercel 기존 frontend 루트/build:hosting/서버 메타/오프라인 정적 파일 라우팅은 유지합니다.
4. 기존 페이지를 온라인에서 다시 열어 새 CSS/JS를 받습니다. 이전에 이미 오프라인인 기기의 프로그램이 즉시 갱신됐다고 가정하지 않습니다.
5. 아래 흐름을 실제 API·브라우저·휴대폰에서 확인한 후 적용 여부를 판단합니다.

## 핵심 수락검사

| 흐름 | 기대 |
|---|---|
| 메모 편집 → QR → 부모 우선 닫힘 | 최종 창까지 배경 잠금 유지, 마지막 닫힘 후 스크롤 복원, 닫힌 부모로 초점 이동 없음 |
| 동일 조건에서 정상 QR→메모 닫기 | 원래 실행 버튼으로 초점 복원 |
| 저장한/방문 표시 부스 + 검색·전시관 → 조건 해제 | 개인 필터 포함 해제, 방문 날짜 유지 |
| 관심 목록 조회 지연/실패/계정 확인중 | ‘부스없음’으로 표시하지 않음, 공개 전체 부스는 접근 가능 |
| 역순·비어 있는 사용자 날짜 | 오류 설명, 0개 검색결과와 구분, 필드와 오류 연결 |
| 기간 하나만 선택 | 적용 기간 표시·해제, 다른 선택값 보존 |
| 조회 페이지가 실제 범위를 벗어남 | 같은 조건의 첫 페이지로, 잘못된 페이지 숫자 없음 |
| 모바일320/390/768 화면 | 카테고리·하단 메뉴 접근, 가로 페이지 넘침 없음, 마지막 콘텐츠가 고정 메뉴에 영구 가려지지 않음 |
| 보관함 검색/Enter/검색어 지우기 | 즉시 검색 반영, 지울 때 다른 필터 유지 |
| 내려받기 안내 펼침 | 동의·선택·실행을 같은 구역에서 확인, 동의 전 저장 불가, 기존 자료 열기는 별도 접근 |
| 지도·메모·새창/뒤로가기/키보드 | 화면 순서 변경 후에도 기존 동작과 입력 중 초안 유지 |
| v22→v23, 기존 오프라인자료 | 유효 사본 유지. 관심 저장과 현장 다운로드 차이가 안내됨 |

## 실행

```sh
python verification/run_checks.py
node --test verification/v23/test_dialogs.cjs verification/v23/test_public_usability.cjs verification/v23/test_library_download.cjs
node verification/v23/build_ui_preview.cjs
python verification/v23/check_static_layout.py
python verification/v23/check_native_dialog.py
# 아래는 실제 서버 주소로 브라우저가 이동하는 기존 리더/실DB 검사입니다.
python verification/v23/browser_offline.py
python verification/v23/release_gate.py
```

정적 검사에는 Playwright와 Chromium이 필요하며 기본 설치 브라우저 또는 BOOTH_CHROMIUM_EXECUTABLE을 사용합니다. 검사를 위해 관리 정책을 끄지 않습니다. 미리보기는 가상 자료·외부 API 대역이며 기능이 연결된 앱을 대신하지 않습니다. CI 파일의 경로만 갱신했으며 실제 GitHub 실행/배포는 수행하지 않았습니다.
