# v11 실사용 준비 체크리스트

모든 체크박스는 사용자의 실제 환경에서 확인한 뒤 체크합니다. 문서가 포함되었다는 이유로 완료된 작업으로 보지 마세요.

## 1. 소스·도메인·계정

- [ ] 원본 코드와 DB를 백업하고 별도 브랜치/스테이징을 준비한다.
- [ ] 이 ZIP은 전체본이며 이전 패치/생성기를 다시 적용하지 않는다. 로컬 변경은 비교·병합한다.
- [ ] `.git`, 실제 `.env`, `config.local.json`, Codex auth는 유지하되 저장소/ZIP/스크린샷에 유출하지 않는다.
- [ ] Vercel 프런트 root `frontend`, Render 백엔드 Docker root `backend`, 실제 HTTPS 주소를 확인한다.
- [ ] Kakao callback, FRONTEND_URL, ALLOWED_ORIGINS, 관리자 ADMIN_KAKAO_SUBJECTS가 실제 배포주소/계정과 일치한다.
- [ ] 세션/CSRF 쿠키의 Secure/SameSite 정책을 프런트·백엔드 사이트 구성과 맞춘다. 새 기능도 ADMIN 권한과 CSRF를 유지한다.
- [ ] R2 읽기·쓰기 키·버킷·R2_PUBLIC_URL은 백엔드만 보유하며 수집기/브라우저에 넘기지 않는다.

## 2. DB/준비상태

- [ ] [DB 체크리스트](V11_DATABASE_CHECKLIST_KO.md)의 공유앱 영향·JDBC 역할 확인을 마쳤다.
- [ ] SQL001~011의 미적용분만 번호순 적용했다. v10이009까지면010→011이다.
- [ ] `/api/public/health/live` 200 UP, `/api/public/health/ready` 200 READY이다.
- [ ] 관리자 로그인 후 `/api/admin/health/readiness`를 확인했다. 공개 readiness에는 내부 테이블/개별 오류를 반환하지 않는다.
- [ ] ready=503이면 관리자 진단/서버로그/읽기전용SQL로 확인한다. health check를 무조건항상200으로 바꾸지 않는다.
- [ ] Render healthCheckPath가 `/api/public/health/ready`이며 마이그레이션을 코드배포보다 먼저 적용했다.

## 3. 빌드·기존 회귀

```powershell
cd frontend
pnpm install --frozen-lockfile
pnpm lint
pnpm build
cd ../backend
.\gradlew.bat test
.\gradlew.bat bootJar
```

- [ ] 프로젝트가 선언한 실제 Node/React/Router/TypeScript/Vite/Java/Spring 의존성으로 실행했다. stub/파서 통과를 대체하지 않는다.
- [ ] 일반사용자/관리자 로그인, 소유권·타인접근 차단, CSRF, 예약·취소·수령·POS·이미지 업로드 기존 흐름을 확인했다.
- [ ] POS 취소 재고는 기존 수동조정 정책이며 이번 순위 제외와 혼동하지 않는다.

## 4. 굿즈 캐러셀

- [ ] 실제 POS 정상 판매가 있는 **공개 운영 상품**을 준비한다. 외부 카탈로그에 판매량을 추정 생성하지 않는다.
- [ ] `/admin/goods-showcase`에서 서브컬처 분류·메인 노출 허용을 저장한다. 변경 시 revision/409·권한을 검사한다.
- [ ] 기록없음/노출미선택은 빈상태, API오류는 재시도로 표시되는지 확인한다.
- [ ] 수량순이며 고가상품 매출순이 아님, 취소·30일밖·미래·개발MOCK 기록은 제외되는지 실제 SQL로 확인한다.
- [ ] 같은 기본상품의 여러 행사 판매를 합산하되 카드/상품 상세 ID는 올바른 공개 행사상품을 가리킨다.
- [ ] 1개/4개/12개, PC·모바일·방향키·스와이프·reduced-motion, 오른쪽끝/왼쪽끝 버튼과 링크초점을 검사한다.
- [ ] 품절·종료·가격·집계기준이 보이고, 이미지 미확보/실패여도 가짜 이미지를 대신 넣지 않는다.
- [ ] 노출 해제/상품비공개/부스철회/판매취소를 다음조회에 반영하며 구매자·판매수량·결제수단을 공개 응답에 노출하지 않는다.

## 5. 리뷰 수정 수락

- [ ] CANCELED/POSTPONED/RESCHEDULED/SCHEDULED의 안내·근거·확인일이 관리자검토→공개→DB재조회→카드·상세까지 유지된다.
- [ ] 기존 공개본 상태차이를 읽기전용으로 점검하고 필요한 행사는 근거 확인 후 재발행했다.
- [ ] 전체화면 지도→부스선택→상품보기→같은 지도 위치 복귀, Escape1회 상세닫기/2회 전체화면닫기, 초점복귀를 실제브라우저/모바일에서 확인했다.
- [ ] 통제된500 한 건의 화면 문의 코드와 서버로그가 일치한다. 실제 비밀번호/헤더/원시SQL/전체본문이 로그에 없는지 검토했다.

- [ ] Codex 인증·백엔드 수집토큰·이미지승인·허용호스트를 기존 설정대로 유지한다.
- [ ] 일요일03시 전체수집, 월~토04시 배치도보완 스케줄이 실제 실행계정에서 작동하는지 확인한다. 이번에는 스크립트를 바꾸지 않았으므로 단순 업데이트라면 재등록하지 않는다.
