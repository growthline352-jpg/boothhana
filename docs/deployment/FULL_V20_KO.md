# 부스하나 v20 적용 및 수락검사

2026-09-18 · 기존 v19 오류 수정본 · 운영 배포 승인 아님

## 호환성

**새 서버 SQL 없음: SQL001~016 유지.** 백엔드/수집기 소스와 프런트 의존성·잠금 파일도 v19 그대로입니다. 신규 서비스를 켜거나 새 권한을 자동 허용하지 않습니다.

오프라인 저장소 이름 `boothhana.offline.v18`, IndexedDB 버전2, package version19 유지. v19 사본은 업데이트 때문에 초기화하지 않습니다. **v18 이하에서 직접 넘어오는 경우는 이전 형식 전환 때문에 오프라인 행사 사본 재다운로드가 필요**합니다. 회원/비회원 보관함의 기존 메모·서버 데이터를 삭제하면 안 됩니다. 정상적인 만료·계정 변경·권리 철회·사용자 삭제에 따른 자료 정리는 기존대로 작동합니다.

## 적용 순서

1. 현재 소스·배포 설정을 백업하고 `TEST_RESULTS_KO.md`의 미완료 검사를 확인합니다. 실제 키나 `.env`/config.local.json은 배포 환경에서 별도 관리합니다.
2. 스테이징에서 정식 의존성으로 lint/build, backend test/bootJar, 실제 격리 DB·브라우저 검사를 진행합니다. 의존성 버전을 임의로 낮춰 검사만 통과시키지 않습니다.
3. 새 React 앱과 `/offline/` 정적 파일 전체를 함께 배포합니다. Vercel 루트 `frontend`, 기존 `build:hosting`, API/메타 환경변수·라우팅을 유지합니다. mjs/sw.js가 HTML fallback으로 반환되지 않는지 확인합니다.
4. 온라인 상태에서 기존 탭을 닫았다가 다시 열고 Service Worker의 `boothhana-offline-shell-v20-1` 갱신을 확인합니다. 기존 v19의 유효한 행사 사본은 그대로 보여야 합니다. 이미 오프라인인 기기가 새 코드를 즉시 받는다고 안내하지 않습니다.
5. 실제 모바일의 오프라인 재실행·로그인 전환·저장/취소와 아래 항목을 확인한 뒤 운영 적용 여부를 판단합니다. 이번 작업에서는 실제 배포/계정/DB를 변경하지 않았습니다.

## 필수 수락검사

| 흐름 | 기대 결과 |
|---|---|
| 보안 토큰 응답 헤더만 도착, JSON 본문 지연 | 15초 제한이 유지되고 실패 후 다음 저장에서 회복. 대기 중 변경 요청 전송 없음 |
| A 사용자의 토큰 준비/저장 응답 대기 중 B 확인 또는 로그아웃 | 이전 변경 요청의 추가 전송·자동 재시도·성공 결과 반영 차단. 이미 전송된 요청은 서버 실제 결과 재확인 |
| 로그아웃 실패 | 비회원으로 조용히 전환하지 않음. 이전 대기 쓰기 재개 없음 |
| 같은 계정으로 창 포커스 재확인 | 계정 변경처럼 처리하지 않음. 기존 초안 보존/정상 저장 유지 |
| 동일 계정의 CSRF_INVALID 동시 발생 | 제한된 1회 재시도와 토큰 갱신 통합 유지. 임의 403/네트워크 오류를 자동 재전송하지 않음 |
| 저장소 open 실패(blocked/timeout) 후 다른 탭 종료 | 이미 실패한 요청의 늦은 업그레이드가 사본을 삭제하지 않음. 사용자가 다시 시도할 수 있음 |
| 동일 행사에서 내려받는 중 방문 날짜 변경 | 이전 날짜 작업의 커밋/완료표시 차단, 새 날짜 동의/저장상태 초기화. 기존 사본 자동 삭제 없음 |
| v19에 저장한 사본이 있는 상태로 v20 업데이트 | 만료 전·동일 계정의 유효한 사본 유지; 새 shell로 오프라인 열람 |
| 서울/경기 세 분야·인천 제외·공개 철회·이미지 권한·재고/예약 | 기존 범위/정책 유지 |

## 명령

```sh
python verification/run_checks.py
# 신규 13개만
node --test verification/v20/test_api_lifecycle.cjs verification/v20/test_storage_open.mjs verification/v20/test_identity_scope.cjs
# 실제 브라우저(공개 API/이미지는 로컬 테스트 대역)
python verification/v20/browser_offline.py
# 운영 DB가 아닌 격리 테스트 DB만 허용
python verification/v18/prepare_test_db.py --confirm-isolated-empty-test-cluster
python verification/v20/release_gate.py
```

`release_gate`는 DB 준비가 없거나 실제 빌드·브라우저 검사가 실패하면 NOT_READY를 남깁니다. CI 경로만 갱신했으며 실제 GitHub push/실행/배포는 하지 않았습니다. 자동 검사가 통과해도 실기기·운영 이미지 CORS·계정/권리·운영 수락검사는 별도입니다.

## 남은 경계

클라이언트 취소는 이미 전송된 서버 작업의 롤백이 아닙니다. 다른 탭에서 계정을 바꿔도 현 탭이 그 변화를 아직 확인하지 않은 구간의 권한은 서버에서 검사해야 합니다. 보안 토큰 재시도는 서버가 CSRF_INVALID로 명시적으로 거절한 경우에만 제한적으로 유지했습니다.

오프라인은 명시적으로 내려받은 공개정보와 선택 표시의 읽기 전용 사본입니다. 네트워크 없는 상태의 즉시 권리 철회/계정변경 확인, 무기한 저장, 실시간 재고/수령 확인, 모든 모바일 환경을 보장하지 않습니다.
