# Google Cloud 신규 가입 크레딧 · 이미지 저장 운영 방침

작성일: 2026-09-21  
기준 애플리케이션: **BoothHana2 v24**  
패키지: **v24-gcp-credit-notes — 문서 보완본**  
상태: **운영 방향 확정 / GCS 코드 연결·실제 설정·이전 미실행 / 운영 배포 승인 아님**

## 1. 확정한 전제와 결정

사용자는 Google Cloud **신규 가입자이며 크레딧을 받을 수 있다**고 확인했습니다. 이 전제로 초기 이미지 저장·제공 비용에 신규 가입 무료 체험 크레딧을 활용합니다. 개인정보나 결제계정 화면을 직접 조회해 자격을 재검증한 것은 아닙니다.

- **이미지 저장의 목표 서비스: Google Cloud Storage(GCS).** 개인 Google Drive 또는 Google One 저장 공간을 사용하는 결정이 아닙니다.
- 행사·부스·상품·회원·보관함·예약·재고의 기존 PostgreSQL 구조는 유지합니다. Cloud SQL, Firestore, Notion 등으로 DB를 옮기는 결정은 아닙니다.
- 백엔드·프런트 호스팅 전체 이전, 신규 서버/외장하드 구매, 스타트업 지원금 신청, 유료 계정 전환은 이번 범위에 포함하지 않습니다.
- 이번 요청은 이 운영 방침을 ZIP에 명시하는 것입니다. GCS 연결 코드, 버킷 생성, 인증·과금 설정, 이미지 업로드·이전은 수행하지 않았습니다.

GCS는 버킷에 파일 객체를 보관하는 Google Cloud 서비스입니다. [S2] 이전의 Drive/외장하드 논의는 대안 검토 이력이며, 초기 이미지 저장의 우선 방향은 이 문서를 따릅니다.

## 2. 신규 가입 무료 체험 조건

2026-09-21 공식 안내 기준 **미화 $300 / 가입 후 90일**의 체험 크레딧을 전제로 합니다. 사용자 계정의 실제 활성화일·만료일·잔액은 콘솔 확인 전까지 미확인입니다. 문서 작성일을 체험 시작일로 간주하지 않습니다. [S1]

| 항목 | 운영 기준 |
|---|---|
| 크레딧 구분 | Google Cloud 신규 가입 Free Trial. 스타트업 $2,000 등 별도 지원금과 혼용하지 않음 |
| 금액·기간 | 공식 기본 조건 $300 / 90일. 실제 계정의 적용 내역은 별도 확인 |
| 체험 종료 | 유료 전환 없이 기간 종료 또는 소진 시 관련 리소스 중단·데이터 손실 위험이 있으므로 만료 전에 대응 |
| 유료 전환 | 사용자의 별도 승인 없이 진행하지 않음. 전환 뒤 크레딧/무료 구간 밖 비용은 청구될 수 있음 |
| 남은 크레딧 | 유료 전환해도 원래 만료일이 연장되는 것으로 해석하지 않음 |
| 상시 무료 | 90일 체험과 별개. GCS의 지정 미국 리전 무료 저장량을 서울 리전에도 적용된다고 계산하지 않음 |

위 프로그램 조건의 근거는 [S1]입니다. 크레딧이 있음을 월 운영비가 0원이라는 근거로 사용하지 않습니다.

## 3. 목표 구성과 현재 구현의 차이

### 목표 구성 — 아직 연결 전

```text
공개 사용이 허용된 이미지 수집·업로드
  → 크기·MIME·파일 바이트·SHA-256 검증
  → Cloud Storage 저장
  → 기존 DB에 이미지 식별·저장 위치·검증·권리 상태 관리
  → 승인된 이미지에 한해 사용자 화면 제공
  → 별도 오프라인 허용 자료만 사용자 기기에 내려받기
```

단일 리전·Standard 저장 등급을 초기 검토안으로 두고, 실제 리전은 이용자 위치·백엔드 위치·요금 비교 후 확정합니다. 서울·경기 행사 범위가 저장소 리전을 자동 결정하지는 않습니다. 버킷명·프로젝트 ID·예산 금액은 임의 확정하지 않습니다.

### 현재 v24 구현 — 이번 패키지에서도 그대로

| 위치 | 현재 동작 / 후속 변경 시 확인할 점 |
|---|---|
| `backend/src/main/java/com/boothhana/upload/VerifiedImageStorage.java` | 검증된 파일 저장·확인 인터페이스. GCS 구현을 연결할 후보 경계 |
| `backend/src/main/java/com/boothhana/upload/R2ImageStorage.java` | 현재 구현은 R2 endpoint와 AWS S3 client를 사용함. GCS 구현으로 변경한 상태가 아님 |
| `backend/src/main/java/com/boothhana/upload/R2UploadService.java` | 실제 업로드는 서버를 거친 검증 방식. 이름이나 오래된 설명만 보고 무검증 직접 업로드로 전환하지 않음 |
| `backend/src/main/resources/application.yml`, `backend/.env.example` | 현재 `app.r2.*` / `R2_*`를 사용함. 이 값에 GCS 버킷명·Google 자격증명을 넣으면 전환된다고 가정하지 않음 |
| `CatalogMediaService`, `FloorplanService`, `LibraryTargets`, `GoodsShowcaseService`, `PlatformService` | 공개 이미지 URL 생성도 `app.r2.public-url`에 연결됨. 저장 구현 하나만 바꿔서는 전환 완료가 아님 |
| `backend/src/main/java/com/boothhana/support/PrivateSupportStorage.java` | 문의 첨부는 별도 비공개 R2 저장 경계. 공개 이미지 버킷과 혼합하거나 임의 활성화하지 않음 |
| `frontend/public/offline/` | 기존 기기 사본·배치도 바이트 해시 검증 유지. URL만 저장했다고 오프라인 파일 저장 완료로 처리하지 않음 |

**현재 `.env.example`은 R2 구현용이며 GCS 실행 예제가 아닙니다.** 적용되지 않는 가상의 환경변수나 새 의존성을 이번 문서 보완에 끼워 넣지 않았습니다.

## 4. 후속 구현·적용 시 필수 확인사항

아래는 **미실행 체크리스트**입니다. 코드를 바꿀 때 실제 통과 근거를 붙여 완료 처리합니다.

- [ ] 결제 콘솔에서 크레딧 활성화·정확한 만료일·잔액·적용 프로젝트를 확인한다.
- [ ] 저장 비용뿐 아니라 읽기/쓰기 요청·인터넷 전송·추가 캐시/서버 비용을 포함해 리전·예산을 결정한다. [S3]
- [ ] GCS용 인증과 최소 접근 권한을 설계한다. 키·토큰·결제계정 비밀값을 프런트/ZIP/Git에 넣지 않는다.
- [ ] 공개 이미지와 미승인 원본·개인 문의 첨부를 분리한다. 비용 절감을 위해 버킷 전체를 공개하지 않는다.
- [ ] `put`/검증/조회 URL을 함께 연결하고 API DTO·상태·nullable·SQL 필요 여부를 대조한다. 새 SQL 필요 여부는 실제 구현 후 판단한다.
- [ ] 업로드 완료 전 크기·MIME·SHA-256을 확인한다. 원본 배치도를 변환하면 원본/변환본의 식별·해시를 분리한다. 저장소 ETag를 기존 SHA-256 대신 쓰지 않는다.
- [ ] 브라우저 CORS·권한·URL 만료·캐시 철회·429/5xx·시간초과·재시도를 확인한다. 서명 URL을 채택하면 영구 식별자/파일 버전과 임시 전송 URL을 분리해 기존 오프라인 URL 비교와의 호환성을 검증한다.
- [ ] 샘플 파일 업로드 → 서버 확인 → 공개 화면 → 실제 휴대폰 오프라인 다운로드 → 인터넷 차단 후 재열람을 통과한다.
- [ ] 기존 파일은 복사 후 개수·바이트·SHA-256·이미지 연결을 검증하고 전환한다. 검증·롤백 준비 전 원본 삭제 금지.
- [ ] 조회 실패 시 이미지만 대체 표시하고, 행사 일정·부스번호 조회가 함께 실패하지 않는지 확인한다.

서울·경기/인천 제외, 세 분야 분류, 예약·POS 정책, 이미지 공개 승인·오프라인 허용, 개인 메모·기기 사본의 보존 정책은 변경하지 않습니다.

## 5. 비용 관찰과 만료 전 대응

**저장량·API 작업량·데이터 전송량을 따로 측정**합니다. 원본·썸네일·과거 파일·삭제 보존본 등 실제 과금 대상과 로그/캐시도 확인합니다. 구체적인 요금은 사용 리전·등급·전송 목적지의 공식 요금표를 기준으로 산정합니다. [S3]

예산은 사용자가 정한 금액으로 만들고, 알림 기준은 50% / 80% / 90% / 100%를 초기 검토안으로 둡니다. **알림 전용 예산은 비용 자동 차단이 아닙니다.** 비용 인지 지연까지 고려해 한도에 여유를 두고, 자동 차단은 해당 서비스 지원·추가 설정 여부를 따로 검증합니다. [S4]

사용 비용과 프로모션 크레딧 차감을 분리해 기록합니다. 크레딧 차감 후 청구액만 보지 않도록 예산/보고서의 프로모션 크레딧 포함 여부를 점검합니다. [S4]

| 점검 시점 — 운영 제안 | 수행할 일 |
|---|---|
| 초기 연결 직후 | 실제 소량 업로드·다운로드의 용량·전송·요청·비용 확인 |
| 운영 중 매주 | 잔액·예상 소진일·월 비용·수집 증가량·누락 이미지 점검 |
| 실제 만료일 30일 전 또는 빠른 소진 예상 시 | 크레딧 차감 전 월 비용으로 GCS 유지/다른 저장소 이전 결정 |
| 실제 만료일 14일 전 | 승인된 경우에만 이전·백업·복구 및 접근권한 검증 수행 |
| 실제 만료일 7일 전 | 유료 유지 승인 또는 이전 완료 확인. 이미지 제공 중단 방지 |

이 일정은 문서상의 운영 계획이며, 실제 예약 알림을 생성하거나 결제/리소스를 자동 변경한 것이 아닙니다. 신규 수집을 멈추더라도 기존 이미지 조회·보관 비용이 모두 없어지는 것은 아니므로 제공 방식과 보관량도 함께 검토합니다.

## 7. 이번 ZIP의 변경·검증 범위

문서와 문서용 결정 메타데이터만 추가·수정했습니다. 프런트·백엔드 동작 코드, SQL001~016, 수집기, 의존성/잠금 파일, 실행 환경 예제 및 기존 테스트 코드는 원본 v24와 동일해야 합니다.

이번에는 문서 연결, 변경 파일 제한, 원본 보존, ZIP 경로/CRC/개별 SHA-256/정확한 파일 목록을 검사합니다. 과거 v24 테스트 로그를 이번에 새로 빌드·실연동한 결과로 표시하지 않습니다. `productionApproval=false`, 실환경 검증 미완료 상태는 유지합니다.

패키지 구분은 `PACKAGE_GCP_CREDIT_NOTES.json`, 이번 변경 목록은 `CHANGE_MANIFEST_GCP_CREDIT_NOTES.json`, 현재 전체 파일 해시는 `SHA256SUMS.txt`입니다. `RELEASE_V24.json`과 `CHANGE_MANIFEST_V24.json`은 변경하지 않은 v24 코드 릴리스의 이력이며, 문서 보완 후 현재 ZIP 전체 해시를 나타내지 않습니다. ZIP 자체의 SHA-256과 검증 보고서는 외부 동봉 파일을 사용합니다.
