# 부스하나 v22 적용 및 수락검사

2026-09-18 · 입력 v21의 프런트 오류 수정본 · 운영 승인 아님

## 호환성과 적용

**v21에서 갱신할 때 이번 동작 변경은 프런트만 적용하면 됩니다.** 전체 ZIP에는 일치하는 기존 백엔드/수집기도 들어 있지만 이 영역은 바이트 단위로 유지합니다. SQL001~016 유지, 추가 SQL 없음. 의존성/잠금 파일도 바꾸지 않습니다. v20 이하에서 건너뛰어 올라오면 v21의 서버 LibraryService 수정도 포함해야 합니다.

오프라인 DB `boothhana.offline.v18`, IDB버전2, 사본형식19, shell캐시 `boothhana-offline-shell-v20-1`은 그대로입니다. `/offline/` 파일을 변경하지 않았으며 v19 이후의 유효 자료를 강제 초기화/재다운로드하지 않습니다. 만료·사용자 삭제·계정 변경·권리 철회의 기존 정리는 유지됩니다. v18 이하의 예전 형식 전환은 이전 안내를 별도로 확인합니다.

1. 현재 소스·배포 설정을 백업합니다. 실제 `.env`·config.local.json·키는 ZIP/Git에 추가하지 않습니다.
2. 정식 의존성으로 `pnpm install --frozen-lockfile`, `pnpm run lint`, `pnpm run build`를 실행하고 기존 실제 DB 통합 게이트를 확인합니다. 이번 문법/대역 검사를 빌드 통과로 대신하지 않습니다.
3. 프런트를 갱신합니다. 기존 Vercel 루트 `frontend`, `build:hosting`, 서버 HTML 메타 환경변수/라우팅 및 `/offline/` 전체 파일 제공 설정은 그대로입니다. 실제 배포를 이번 작업에서 수행하지 않았습니다.
4. 온라인에서 새 프런트를 받은 뒤 아래 흐름을 확인합니다. 오래 열어둔 탭의 기존 JavaScript가 배포 즉시 바뀐다고 가정하지 않습니다. 비회원 조회키는 먼저 안전하게 보관하고 새로고침합니다.
5. 실제 모바일·브라우저·API 수락결과를 확인한 뒤 운영 적용 여부를 판단합니다. 서버 DB나 개인 보관함을 초기화할 필요가 없습니다.

## 필수 수락검사

| 흐름 | 기대 결과 |
|---|---|
| GET 조회가 느린 동안 저장/추가답변 성공 후 GET 성공 | 성공한 내용이 이전 조회로 되돌아가지 않음 |
| 같은 상황에서 오래된 GET 실패 | 저장 내용 유지, 거짓 오류 화면 없음 |
| 성공 뒤 사용자가 새로 조회 | 최신 서버 내용으로 정상 갱신 |
| 비회원 추가답변 대기 중 조회 종료 | 늦은 응답이 문의 내용을 다시 표시하지 않음 |
| 접수A 응답 대기 중 종료→접수B 조회 | A의 늦은 결과가 B를 덮지 않음. A의 초안을 B 키로 전송하지 않음 |
| 종료 후 같은 접수A 다시 조회 | 이전 조회 세션 응답은 새 조회를 덮지 않음 |
| 정상 비회원 신규접수/조회/추가답변 및 페이지 종료 | 기존 키 정책 유지, 결과 정상 표시, 종료된 화면에 결과 미반영 |
| 부스 판매 요약 철회 후 보관함 편집 화면 공개 재확인 | 현재·과거 판매 요약/태그가 숨겨짐, 개인 메모/방문일 및 입력 중 초안 유지 |
| 공개 확인 로딩/오류/전체 철회 | 이전 공개 문구·이미지 노출 없음. 개인 메모 보존 |
| 공개 판매정보가 계속 유지되는 부스 | 기존 과거 정보 표시 정상 |
| 서울·경기의 명시적 공개 주소 | 장소 지도·주소 복사 동작 확인 |
| 인천/다른 지역/비공개·미정·미확인 주소 | 지도/복사 비활성 및 기존 범위 유지 |
| v21에서 업데이트 후 기존 오프라인 자료 열기 | 유효한 사본 유지, 기존 만료·철회 동작 정상 |

사용자가 조회를 종료했다는 이유로 이미 서버에 전송된 답변/저장이 취소되지는 않습니다. 접수 결과가 불확실하면 기존 ID·조회키로 확인하고 중복 전송하지 않습니다. 서버의 새 공개 상태를 확인하기 전까지 즉시 철회를 보장하지 않습니다.
