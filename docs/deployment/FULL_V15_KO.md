# v15 배포·실제 검증
2026-09-18. 이 문서는 실행할 절차입니다. 실제 운영·DB·호스팅에 적용한 보고서가 아닙니다.

## 준비/적용
[DB 검토표](V15_DATABASE_REVIEW_KO.md)로 역할과 상태를 확인하고 미적용 SQL을 번호순 적용합니다. v14에서014까지라면015만 필요합니다. 이후 프런트·백엔드를 함께 업데이트합니다. 추가 환경변수·서비스 의존성은 없고 기존 qrcode를 사용합니다. collector 3단계·배치도 분석·프롬프트와 OS 스케줄은 그대로입니다.

```powershell
cd frontend
pnpm install --frozen-lockfile
pnpm lint
pnpm build
cd ../backend
.\gradlew.bat test
.\gradlew.bat bootJar
```

실제 의존성 버전을 확인하지 않고 임의로 낮추거나 verification용 stub을 서비스 코드로 넣지 마세요. 현재 환경에서는 Vite/client·node 미설치 및 Gradle DNS 오류로 전체 빌드를 완료하지 못했습니다.

## 실제 DB용 검증
`verification/v15/prepare_test_db.py`는 **빈 전용 localhost boothhana_release_test**와 독립 테스트 클러스터에서만 SQL001~015를 적용합니다. 기존 역할·데이터가 있으면 거절합니다. 이 프로그램은 운영 마이그레이션 도구가 아닙니다. v14의 `boothhana_support_test`도 별도 준비합니다. 워크플로 `.github/workflows/release-verification.yml`에 해당 구성을 연결했습니다. 현재 환경에서 CI를 실행하지 않았습니다.

```powershell
# 독립 규칙/명시적 가짜 경계 검사
python verification/v15/run_checks.py

# 전용 DB와 실제 의존성이 준비된 실행 계정에서만
python verification/v15/release_gate.py
```

Gate는 실제 release14개 + support8개 + library15개 이상, 실패·오류·skip0 및 최신 XML을 요구합니다. 환경변수 미설정·보고서누락은 NOT READY입니다. LibraryIntegrationTests는 전체 앱·실제 JDBC와 SQL001~015·MockMvc인증/CSRF를 사용하는15개 테스트를 작성했으나 **여기서는 실행하지 못했습니다**. 실제 브라우저/OAuth·R2는 이 서버 테스트와 별도입니다.

## 실제 사용자 과업 수락표
- [ ] 비로그인 행사/부스/상품 저장 → 기기 임시 표시, 중복저장 없음, 저장거부 시 성공으로 오표시하지 않음.
- [ ] 종료된 행사에서 저장했던 상품을 행사명·특징·내 메모로 다시 찾음. 운영 안내는 현재 공개값과 구분.
- [ ] 상품만 저장해도 해당 행사의 '저장한 부스'와 지도 강조에 나타남.
- [ ] 저장/조회/QR 스캔으로 방문 기록이 생기지 않음. 실제 날짜 직접표시→해제, 휴무/미래 날짜 거절.
- [ ] 로그인 후 기기기록 자동수입 없음. 명시적 가져오기→중복없음, 메모·방문 계획 충돌 시 원본 유지.
- [ ] 가져오기 도중 계정 전환·응답 유실·다중탭 변경에도 다른 계정으로 개인메모를 잘못 보관하지 않음.
- [ ] A→로그아웃→B에서 A의 메모/인덱스/늦은응답이 표시되지 않음. 기기 임시기록과 회원기록을 혼합하지 않음.
- [ ] 모바일 메모 입력/뒤로가기/이탈 경고/저장, 다른 화면에서 바뀐 revision의 수정 거절.
- [ ] 비공개·삭제·이미지승인철회 후 보관함에서도 옛 제목/이미지/공식링크 우회 노출 없음. 개인메모 수정/삭제 가능.
- [ ] QR PNG를 실제 휴대폰에서 스캔해 같은 행사/부스/상품·방문일을 엶. QR에 메모/개인 UUID 없음.
- [ ] 공식링크는 원문URL로 이동하고 현재 혜택·실시간재고를 보증하지 않음.
- [ ] 회원500/기기200 및30개 resolve·128KiB본문 한도를 검사.
- [ ] 기존 로그인/고객센터/예약/POS 재전송·수집·지도·UI 회귀 확인.
